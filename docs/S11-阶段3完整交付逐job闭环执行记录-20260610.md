# S11 阶段 3：完整交付逐 job 闭环执行记录

日期：2026-06-10

## 目标

将完整交付模式从“先跑完整个 run 的所有 Legil target，再统一标准化和 finalize”调整为“每张 OK 图作为一个 job 闭环执行”。

新的完整交付顺序：

```text
job 1:
  1. 只生成该 job 内需要 Legil 的 target
  2. 该 job Legil target 完成后立即标准化
  3. 该 job 标准化完成后立即 finalize
  4. final-package 中立即出现该 job 文件夹

job 2:
  重复同样闭环
```

## 本阶段改动

### 1. 完整交付入口切换为闭环 runner

文件：`src/routes/delivery.routes.js`

新增：

```text
runDeliveryJobsClosedLoop()
runDeliveryJobClosedLoop()
```

`/api/delivery/start` 中：

```text
completeDelivery = true  -> runDeliveryJobsClosedLoop()
completeDelivery = false -> runDeliveryCandidates()
```

普通 Legil 候选生成、单 target 重试等路径继续走旧的 `runDeliveryCandidates()`，避免扩大影响面。

### 2. job 内只调用 Legil target

`runDeliveryJobClosedLoop()` 内部用：

```text
collectRunnableTargets(run, { ...options, jobId })
```

只收集当前 job 的 runnable targets。

由于阶段 1 已经让 `targetNeedsGeneration()` 对 `source-reuse` 返回 false，所以源图复用 target 不会进入 Legil 调用。

### 3. job 级标准化

当前 job 的 Legil target 完成后立即调用：

```text
standardizeDeliveryRun(runId, { ...options, jobId })
```

源图复用 target 仍然会作为候选图进入同一套标准化流程，因此不会跳过压缩、尺寸输出等后处理。

### 4. job 级 finalize

当前 job 标准化完成后立即调用：

```text
finalizeDeliveryRunById(runId, { ...options, jobId, runStatus: 'running' })
```

同时调整 `finalizeDeliveryRun()`：

```text
支持 options.jobId
只 finalize 指定 job
completedJobs / failedJobs 按整个 run 重新统计
只有所有 job 都 finalized 时，run.status 才变为 finalized
```

这样第 1 张 OK 图完成后，`final-package/<job-folder>` 会立即落盘，不再等待后续 OK 图的 Legil target。

### 5. finalized job 状态保护

修正 `updateJobStatus()` / `updateRunStatusFromTargets()`：

```text
所有 target 都是 finalized -> job.status = finalized
所有 run target 都是 finalized -> run.status = finalized
```

避免已经 finalized 的 job 在后续 job 生成进度刷新时被降级回 `candidates_ready`。

## 中断语义

如果任务在 job 间被停止：

```text
已 finalized 的 job 不回滚
final-package 中已生成的 job 文件夹保留
后续未开始或未完成的 job 保持未 finalized
run.status = stopped
```

如果任务在某个 job 的 Legil target 过程中停止，则该 job 不进入标准化和 finalize，避免生成半闭环交付包。
