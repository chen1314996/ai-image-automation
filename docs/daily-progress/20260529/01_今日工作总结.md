## 已完成的关键工作

### 1. 重定义 S10 三尺寸交付业务方案

**目标**

把旧的“改尺寸”流程重构为更贴近业务交付的“两段流水线”：自动创意量产只负责出候选图，OK 图三尺寸交付只处理人工挑出的 OK 图。

**完成内容**

- 新增 `docs/S10-量产与三尺寸交付后处理新版分阶段开发方案-20260529.md`。
- 明确流水线 A：

```text
已有方向 / 素材分析方向 / 提示词池
  -> 自动拓展创意提示词
  -> Prompt Gate 质检
  -> Prompt 标准化
  -> Legil 批量生成候选图
  -> 保存到本地量产输出文件夹
  -> 人工浏览输出
  -> 人工复制 OK 图到待交付后处理输入文件夹
```

- 明确流水线 B：

```text
OK 图输入文件夹
  -> 系统扫描 OK 图
  -> 每张图建立 delivery job
  -> 每张图 x 3 个目标尺寸
  -> 每个尺寸用 Legil 生成 2-4 张候选
  -> 人工从每个尺寸候选中选 1 张
  -> 本地标准化到精确像素和 390KB 以内
  -> 加 LOGO
  -> 重命名
  -> 每张 OK 图打包成一个文件夹
```

- 明确三尺寸目标：

```text
800x800
1280x720
1080x1920
```

- 明确三尺寸适配只保留 Legil 图生图作为主流程，不再把即梦改尺寸作为交付入口。
- 明确最终命名规则和输出目录结构，文件名固定带 `_800x800`、`_1280x720`、`_1080x1920` 后缀。

### 3. 新增 delivery postprocess 本地数据层

**目标**

为每次 OK 图三尺寸交付建立可追踪的 run、job、target 和候选记录。

**完成内容**

- 新增 `src/services/delivery-postprocess/store.js`。
- 支持扫描输入文件夹中的图片：
  - `.jpg`
  - `.jpeg`
  - `.png`
  - `.webp`
  - `.bmp`
- 每张 OK 图生成一个 delivery job。
- 每个 job 固定生成三个 target：

```text
800x800    -> 1:1
1280x720  -> 16:9
1080x1920 -> 9:16
```

- run 数据写入：

```text

data/delivery-postprocess/runs/<runId>.json
```

- 支持同一个输入文件夹复用最近 run，保留已有 job/target/candidate 状态。
- 支持命名规则：
  - 固定前缀。
  - 起始编号。
  - 区域/代号。
  - 渠道。
  - 一级标签。
  - 二级标签。

### 4. 新增 S10 后端 API

**目标**

把三尺寸交付从页面操作接到后端任务模型，先完成扫描、候选生成、选择候选和标准化。

**完成内容**

- 新增 `src/routes/delivery.routes.js` 并在 `src/server/routes.js` 中注册。
- 接口包括：

```text
POST /api/delivery/scan
POST /api/delivery/start
POST /api/delivery/resume
POST /api/delivery/stop
POST /api/delivery/runs/:runId/retry-target
POST /api/delivery/runs/:runId/select-candidate
POST /api/delivery/runs/:runId/standardize
POST /api/delivery/runs/:runId/finalize
GET  /api/delivery/status
GET  /api/delivery/runs
GET  /api/delivery/runs/:runId
GET  /api/delivery/image
```

- 候选生成阶段接入 Legil 图生图：
  - `taskType` 使用 `delivery-candidates`。
  - 每个 target 独立更新 `generating`、`candidates_ready`、`failed` 等状态。
  - 候选保存到 `stage-ai/<job>/<targetSize>/`。
  - 支持停止、继续和重跑单 target。
- 选择候选后，target 状态变为 `candidate_selected`。
- 标准化接口把选中候选输出到 `stage-final/<job>/<baseName>_<targetSize>.jpg`。
- `finalize` 当前作为占位：确认已选状态，并提示 LOGO、重命名和打包将在后续接入。

### 5. 新增本地标准化能力

**目标**

确保最终交付图不是随意尺寸，而是精确目标像素，并且小于 390KB。

**完成内容**

- 新增 `src/services/delivery-postprocess/standardize.js`。
- 支持目标尺寸：

```text
800x800
1280x720
1080x1920
```

- 使用 `canvas` 读取候选图并进行 cover 方式标准化。
- 输出 JPG。
- 逐级尝试 JPEG quality，默认最低质量 60。
- 若压缩到最低质量仍超过 `390KB`，返回明确错误。
- 输出后再次读取尺寸，确认与目标尺寸完全匹配。
