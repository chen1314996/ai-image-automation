# 问题与解决方案 - 2026-06-07

## 问题 1：run 全部完成不等于资产质量达标

### 现象

6/7 的 89 条 run 全部 `legil_completed`，但日报补写时尚未逐条核对 savedCount、资产登记、图片质量和人工反馈。

### 原因

run phase 只表示流程完成，不代表每张图都质量好、命名正确、值得入库或已被人工审核。

### 解决方案

- 后续统计每条 run 的 savedCount 和 assetRegistration。
- 抽检输出图片和资产记录。
- 将质量反馈接入 creative-memory。

### 结果

6/7 先作为流程稳定性通过的证据，质量层面留到后续专项复盘。

---

## 问题 2：长跑产物增长很快

### 现象

一天新增 89 条 run，长期运行会快速堆积 JSON、图片、资产和队列状态。

### 原因

24 小时自动化本质上会持续产生运行数据，如果没有归档策略，后续检索和排障会变慢。

### 解决方案

- 按日期归档 run 统计。
- 给异常 run 做单独索引。
- 建立每日摘要，而不是每次都手动扫描所有 run。

### 结果

运行产物治理被列为后续重点。

---

## 问题 3：调度状态需要和真实 run 对齐

### 现象

`scheduler-state.json`、`creative-target-queues.json` 和 run 文件都会描述运行状态，长期运行时容易出现口径不一致。

### 原因

队列、调度器、当前 run 和资产入库是不同层级的数据源。

### 解决方案

- 后续统一“今日产量、当前队列、当前 run、失败次数”的可信来源。
- 运行中心使用诊断接口统一解释。
- 每日进度自动读取同一套口径。

### 结果

6/7 暂以 run 文件统计为准，后续需接入 P0 诊断口径。

---

## 问题 4：长跑成功后更需要反馈闭环

### 现象

系统已经能持续产图，但反馈数量和人工审核速度可能跟不上。

### 原因

自动化扩大产能后，如果审核和学习不跟上，系统会积累大量未评审资产。

### 解决方案

- 将资产审核、精选、负反馈作为 24 小时闭环的同等优先级。
- 在运行中心或知识库页提示未评审资产数量。
- 定期生成学习报告和方向权重调整建议。

### 结果

下一阶段重点从“持续生成”转为“持续进化”。
