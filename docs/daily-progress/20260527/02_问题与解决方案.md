# 问题与解决方案 - 2026-05-27

## 问题 1：历史“豆包/方舟”命名和新 Winky 规则冲突

### 现象

项目中仍有大量历史命名：

```text
doubao-automation.js
/api/doubao/full-automation
/api/config/doubao
豆包 API
火山方舟
Ark
Volcengine
```

但当前新规则要求所有新/改 LLM 能力统一使用 Lumos Winky。

### 原因

历史接口和前端调用已经围绕“豆包”命名建立。如果直接改 URL 和字段名，会影响已有工作流、前端配置和兼容调用。

### 解决方案

- 保留 `/api/doubao/*` 和 `/api/config/doubao` 这些历史入口作为兼容 wrapper。
- 将底层实现统一改为 Lumos Winky。
- 新增 `AGENTS.md` LLM Provider Rule，明确禁止新功能继续接火山/方舟/豆包模型调用。
- 在 `doubao-automation.js` 和 `prompt-generation-service.js` 中读取 `WINKY_*` 环境变量或本机 `automation-secrets.json` 的 winky 字段。
- 对 Ark/Volcengine URL 增加拦截，避免配置误保存或运行时误用。
- 前端和日志文案统一改为“Lumos Winky”或“提示词模型”，减少用户误解。

### 结果

旧 API 名称仍可用，但实际提示词生成、图文输入和模型列表都走 Lumos Winky。

## 问题 2：Agent 输出完整策划文章时，程序不容易稳定解析 prompt

### 现象

创意 Agent 原本偏向输出完整四部分 Markdown 表格：

```text
参考图分析表
100组素材迭代策略总表
逐方向详细迭代策略表
新方向拓展表
```

这适合人工阅读，但后台“运行一次自动创意”更需要稳定抽取 `新方向拓展表` 和 prompt。

### 原因

run-once 自动流程的第一目标是“可被程序解析并发送 Legil”。如果 Agent 输出太多策划文本，解析器和 Prompt Gate 容易受到标题、解释、代码块、非标准表头影响。

### 解决方案

- 新增 `PROJECT_SETTINGS.md`，明确 run-once MVP 优先只输出 `新方向拓展表`。
- 新增 `legil-run-once-prompt-contract` skill，固定表头：

```text
参考方向
新方向名称
方向描述
来源于哪条详细迭代策略
提示词1
提示词2
提示词3
提示词4
提示词5
```

- `creative-agent-service.js` 默认加载该 skill，并把 `PROJECT_SETTINGS.md` 拼进模型上下文。
- Agent 输出结果保存 `rawText` 和 `rawTableMarkdown`，方便后续回溯和调试 Prompt Gate。

### 结果

run-once 场景下优先保证“新方向拓展表”稳定、prompt 可解析、每条 prompt 可直接送 Legil。

## 问题 3：直接做 24 小时循环风险太大

### 现象

最终目标是 24 小时创意闭环系统，但如果一开始就做持续调度，会同时遇到：

- LLM 配置问题。
- Legil 登录和页面稳定性问题。
- Prompt 质量问题。
- 图片保存和资产回流问题。
- 每日生成额度和连续失败暂停问题。
- 反馈学习还没稳定的问题。

### 原因

24 小时循环是多个子系统叠加后的长期运行能力。没有先把单次闭环跑稳，直接循环容易扩大错误和成本。

### 解决方案

- 先锁定“运行一次自动创意”第一版 MVP。
- 默认一次处理 1 个方向，生成 5 个新方向，每个新方向 5 条 prompt，理论最多 25 条 prompt。
- 每条 prompt 默认 4 张图，单轮最多 100 张，日上限 1000 张。
- 增加 preflight 检查：
  - 创意知识库是否导入。
  - 输出目录是否可写。
  - 参考图目录是否存在。
  - 浏览器模式是否为 headed。
- 增加 agentOnly / smoke / full 模式，允许先只生成 prompt，再人工决定是否继续 Legil。

### 结果

当前架构先跑单轮，再从单轮记录和反馈中逐步扩展到更稳定的 24 小时自动循环。

## 问题 4：创意方向需要“成长”，但不能污染种子方向

### 现象

Agent 每轮会生成新方向。如果直接把所有新方向都加入可运行方向，会产生：

- 重复方向。
- 低质量方向。
- 跑偏方向。
- 方向体系膨胀失控。

### 原因

创意知识库需要长期进化，但种子方向和自动生成方向的可信度不同。必须先区分“草稿”“接受”“拒绝”“归档”“禁用”。

### 解决方案

- 新增 direction drafts：
  - 从 run 中提取 Agent 新方向为草稿。
  - 草稿可以 accept、reject、archive、merge。
- 新增本地成长方向 ID，如 `direction_grown_*`。
- 新增方向状态：

```text
seed
draft
accepted
rejected
archived
disabled
```

- 自动选题只允许 `seed` 和 `accepted` 状态进入候选。
- 支持从生成资产中收藏/沉淀方向证据。
- 支持反馈学习生成 memory rules，再人工 accept/reject/disable。

### 结果

系统可以吸收好方向，也能保留坏方向和拒绝理由作为负样本，但不会让未审核内容直接污染可运行方向池。

## 问题 5：素材数据表字段和图片链接来源不完全稳定

### 现象

素材分析页需要导入每周素材数据，但表格可能存在：

- 中文表头和英文表头混用。
- 百分比、金额、空值格式不一致。
- 图片链接藏在 `HYPERLINK("...")` 或普通文本中。
- 素材名中需要解析题材、包装形式、玩法、尺寸等信息。

### 原因

投放数据表不是为程序接口设计的标准 API，而是业务表格，需要做兼容解析。

### 解决方案

- `material-analysis/importer.js` 建立 `HEADER_ALIASES`，兼容：
  - 素材名称 / name
  - 花费 / 消耗 / spend
  - CTR / CVR / CPI / IPM
  - D0-D7 ROI
  - 素材内容 / 素材链接 / content
- 支持解析百分比、金额、空值、`HYPERLINK` 和普通 URL。
- 从素材名中解析 primary / secondary / idea / size。
- Top100 第一版按 `spend` 降序。
- 健康度优先使用 D0 IAP ROI，并保留方向表现和 action 建议。

### 结果

素材分析测试可以用真实样例 CSV 跑通 Top100、健康度、方向聚合和链接解析。

## 问题 6：AI 视觉识别可能失败，需要缓存、重试和可降级

### 现象

素材分析的 AI 视觉识别依赖图片链接和 Winky 图文模型，可能遇到：

- 图片链接失效。
- 图片不可下载。
- Winky 鉴权失败。
- 限流。
- 模型没有返回 JSON。
- 单张失败但整批仍需继续。

### 原因

视觉识别是外部模型与远程图片的组合调用，不应假设全部稳定。

### 解决方案

- 新增 `MaterialImageFetcher` 负责远程图片抓取和 data URL 构造。
- 新增 `MaterialVisionClient` 统一 Winky 图文调用、错误分类和 JSON 解析。
- 新增 `MaterialVisionCache` 缓存每个 run 的视觉结果。
- `MaterialVisionService` 支持并发、状态查询、失败记录和单素材 retry。
- API 层提供：

```text
POST /api/material-analysis/imports/:runId/vision/start
GET  /api/material-analysis/imports/:runId/vision/status
GET  /api/material-analysis/imports/:runId/vision/results
POST /api/material-analysis/materials/:materialId/vision/retry
```

### 结果

本地 mock 视觉流程已通过测试。真实 Winky 视觉识别仍需要用真实 Key 和真实图片再做验收。

## 问题 7：改尺寸中断后无法精确知道剩余任务

### 现象

原改尺寸逻辑更接近“按图片处理”。如果一张图需要多个比例，任务中断时很难明确：

- 当前处理到哪张图。
- 当前处理到哪个比例。
- 哪些比例已经完成。
- 剩余多少组任务。

### 原因

任务模型不够细，图片和比例没有被拆成独立 job。

### 解决方案

- 将改尺寸任务拆成：

```text
imagePath x aspectRatio = resize job
```

- `buildResizeJobs()` 生成完整 job 列表。
- `resizeResumeState` 保存：
  - provider
  - runId
  - jobs
  - nextIndex
  - totalImages
  - totalAspectRatios
  - completed / success / failed / saved
  - currentAction
- Legil 和即梦都支持 resumeMode 和 resumeRunId。
- 前端提供“继续任务”和“新任务”入口。

### 结果

改尺寸续跑的数据结构已经统一，后续真实页面测试时可以验证中断、继续和清除恢复状态。


### 原因

开发过程中生成了本地知识库、验收截图、素材样例和导入数据，这些文件有些是测试样例，有些是运行产物。

### 解决方案

- 已先将 `data/creative-knowledge/` 加入 `.gitignore`。
- 后续需要人工决定：
  - `sucai/` 是否作为项目样例数据提交。
  - `data/acceptance-*.png` 是否作为验收证据提交。
  - `data/tmp-direction-workbook-copy.xlsx` 是否应删除或忽略。
  - `data/material-analysis` 是否也应按运行产物忽略。

### 结果

当前日报只记录状态，不主动删除或忽略更多文件，避免误处理用户本地数据。
