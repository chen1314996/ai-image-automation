# 问题与解决方案 - 2026-06-04

## 问题 1：历史素材命名中 missing 比例仍高

### 现象

`first-round-candidate-summary.json` 中 446 个候选里有 172 个 `missing`，仅靠文件名规则无法稳定归类。

### 原因

历史文件名混入了 ref/prompt、日期、尺寸、临时标题、旧标签和截断字段，部分文件名缺少足够业务语义。

### 解决方案

- 先用规则和显式标签做候选归类。
- 对 missing/低置信样本引入 Winky 视觉识别。
- 设置 `minConfidence=0.8`，宁可跳过也不强行错误命名。

### 结果

Winky 首轮 apply 354 张，跳过 92 张，失败 0；未被高置信命中的素材保留后续复核空间。

## 问题 2：视觉命名批处理需要可审计报告

### 现象

视觉命名会真实改文件名，如果没有报告，很难追溯命名前后关系和置信度。

### 原因

AI 视觉判断存在不确定性，且批量重命名会影响后续资产检索、交付和 JSON 引用。

### 解决方案

- 每次运行输出 JSON 和 CSV 报告。
- 报告保留 rename/skipped/failed 统计。
- 保留 minConfidence、labelWorkbook、targetDir、outDir。
- 缓存视觉结果，避免重复调用 Winky。

### 结果

`data/rename-analysis/winky-first-round/` 中保留了 4 份报告和缓存，后续可回看或二次处理。

---

## 问题 3：自动创意长跑需要更多边界测试

### 现象

自动创意已经进入队列和恢复阶段，单个 happy path 测试不足以覆盖长跑风险。

### 原因

长跑会遇到 Legil 失败、prompt 失败、继续任务、队列尾部、暂停恢复和状态落盘等情况。

### 解决方案

- 新增 failed prompt 记录测试。
- 新增继续任务优先级测试。
- 新增最终队列轮询测试。
- 抽出 `creative-auto-test-utils.js` 复用测试场景。

### 结果

自动创意测试面扩展，为 6/6 继续纳入 `npm run test:creative-auto` 打基础。

---

## 问题 4：飞书通知需要适配更长时间运行

### 现象

24 小时自动化会产生更多状态变更，如果飞书通知不降噪，会影响实际使用。

### 原因

飞书链路既要能远程控制，又要能及时通知异常，但不能每个小状态都刷屏。

### 解决方案

- 加固健康监控和通知服务。
- 调整命令路由和卡片构建。
- 更新飞书命令测试。

### 结果

飞书控制链路继续向长跑场景收口，但仍需要后续真实通知压测。
