# 问题与解决方案 - 2026-06-02

## 问题 1：老流程和新流程能力分散

### 现象

项目中同时存在参考图老流程、素材分析、创意知识库、自动创意、任务表入口、S10 三尺寸交付和飞书控制等多条链路。

### 原因

前期为了快速验证能力，各模块先独立落地，状态、入口、队列和资产登记逐步变多。

### 解决方案

- 制定 `docs/项目Agent团队架构调整方案-20260602.md`。
- 明确两条主流程都保留，但共用：
  - 统一任务状态中心
  - 统一 Legil 队列
  - 统一 Prompt Gate
  - 统一资产登记
  - 统一反馈学习
  - 统一前端运行视图

### 结果

项目有了新的系统化架构方向，后续开发不再是“哪里缺补哪里”，而是围绕统一任务模型收束。

## 问题 2：创意 Agent 容易越界成执行层

### 现象

如果不明确边界，Agent 可能既生成创意、又承担质量判断、又尝试写知识库或驱动 Legil，职责过重。

### 原因

Agent 能力越来越强，但当前项目真正需要的是稳定的结构化输出和可控执行，而不是让模型直接接管所有动作。

### 解决方案

- 在 `docs/创意拓展Agent调整优化方案-20260602.md` 中重新定义边界。
- Agent 只负责生成结构化方向、prompt 和说明。
- Prompt Gate、Legil 队列、资产登记、反馈学习分别由系统模块承担。
- 更新 Agent instructions、项目设定和 Legil prompt 合约。

### 结果

创意 Agent 从“万能生成器”收敛为“结构化创意层”，后续更容易测试和接入队列。

## 问题 3：自动化任务表数据量大，必须支持缓存和暂停

### 现象

本日导入任务表后，生成 108 个任务方向和 198 张参考图，并对 108 个方向进行了视觉整理。

### 原因

任务表入口默认一行一个任务方向，且默认自动视觉整理全部行。真实业务表会带来大量 Winky 调用和运行产物。

### 解决方案

- 导入选项中保留：

```text
autoVisionAllRows = true
visionConcurrency = 1
maxVisionConcurrency = 2
maxVisionRetriesPerRow = 3
useTaskReferenceImagesForLegil = false
saveTaskDirectionToOfficialKnowledge = false
```

- 任务表视觉整理状态落盘到 `vision-status.json`。
- 视觉整理结果落盘到 `vision-results.json`。
- 后续继续补暂停、继续、缓存复用和额度限制。

### 结果

本轮 108 个任务方向全部整理成功，但也确认任务表链路必须有成本控制和恢复能力。
