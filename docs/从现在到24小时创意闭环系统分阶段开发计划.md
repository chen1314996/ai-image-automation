## 1. 先说最终目标

这个项目最终不是一个“自动点击 Legil 的脚本”，而是一个本地创意生产系统：

```text
创意知识库
  -> 自动选方向
  -> Agent 拓展新方向
  -> Prompt 转译和质检
  -> Legil 自动生图
  -> 图片资产入库
  -> 人工审核反馈
  -> 反馈学习成规则
  -> 下一轮更准
  -> 24 小时可控运行
```

最终你要得到的能力是：

| 能力 | 最终表现 |
| --- | --- |
| 自动运转 | 系统不用每轮手点，能按规则持续运行 |
| 准确生成 | 生成图越来越符合你想要的广告创意方向 |
| 可追溯 | 每张图都知道来自哪个方向、哪个 prompt、哪次 run |
| 可审核 | 好图、坏图、跑偏图能快速标记 |
| 会学习 | 系统能吸收你的反馈，下一轮自动避开坏模式 |
| 可暂停 | 登录失效、验证码、连续失败、额度用完时自动暂停 |
| 可扩展 | 后续可以接飞书同步、量产、改尺寸、重命名 |

## 4. 核心概念说明

为了后续你能深刻理解项目，需要先把几个概念分清楚。

### 4.1 方向定义

方向定义是给人和 Agent 理解的创意边界。

例子：

```text
题材 / 探索发现 / 围墙
画面核心为冰封末世中的围墙、防御结构、幸存者对外部威胁的阻挡和观察。
```

它回答：

```text
这类图想表达什么？
能包含哪些元素？
不能偏到哪里？
这个方向为什么有广告价值？
```

### 4.2 生图 Prompt

生图 prompt 是给 Legil 执行的单图指令。

它必须更具体：

```text
画面主体是谁
正在做什么
场景在哪里
镜头如何
光线如何
有哪些可见元素
文字如何处理
比例和分辨率要求是什么
```

方向定义和 prompt 不能混成一层。混在一起会导致：

```text
方向太具体，后续不好拓展；
prompt 太抽象，Legil 出图不稳定。
```

### 4.3 资产

资产不是只有图片文件，而是一条完整记录：

```text
图片文件
  + 来源方向
  + prompt
  + 模型参数
  + 生成时间
  + runId
  + 审核结果
  + 后续是否被复用
```

没有资产记录，系统就无法学习。

### 4.4 反馈

反馈是你对结果的判断：

```text
这张图好不好？
为什么好？
为什么坏？
这个方向能不能继续？
这个 prompt 哪部分不对？
哪些元素以后要避开？
```

反馈不是为了写日志，而是为了让下一轮 Agent 更懂你。

### 4.5 24 小时自动化

24 小时自动化不是“无限循环生成图片”。

真正的 24 小时自动化应该是：

```text
有额度
有选题策略
有 Prompt Gate
有失败暂停
有资产入库
有反馈学习
有通知
有人工接管
有重启恢复
```

## 5. 阶段验收总规则

每个阶段都分三种验收：

| 验收类型 | 谁负责 | 说明 |
| --- | --- | --- |
| 技术验收 | 系统 / 我 | 接口、文件、页面、流程能正常跑 |
| 业务验收 | 你 | 结果是否符合你的创意生产理解 |
| 方向验收 | 你 + 系统 | 是否继续按这条路线走，还是调整 |

每个阶段结束时，你只需要做三类判断：

```text
1. 这个阶段的页面和数据我看懂了吗？
2. 这个阶段产出的结果符合我的业务需求吗？
3. 是否允许进入下一阶段？
```

如果你觉得跑偏，应该在阶段验收时立刻调整，而不是等到 24 小时循环上线后再改。

## S2：资产审核和反馈入库

### 目标

让你能对生成的图片做审核，并把判断写入系统。

### 为什么要做

没有人工反馈，系统就不知道：

```text
哪些图是你想要的
哪些图跑偏了
哪些方向值得继续
哪些元素以后要避开
```

24 小时自动化如果没有反馈学习，只会更快地产生重复错误。

### 产出

| 产出 | 说明 |
| --- | --- |
| 资产审核状态 | `unreviewed / good / normal / bad / rejected` |
| 反馈标签 | 跑题、重复、构图弱、文字差、风格不符等 |
| 反馈备注 | 你可以写一句原因 |
| `feedback.json` 写入 | 每次审核形成一条反馈 |
| 资产统计更新 | 好图数、坏图数、已审核数 |

### 审核动作

| 操作 | 含义 |
| --- | --- |
| 标记好图 | 这张图符合方向，可以复用或继续拓展 |
| 标记一般 | 可参考，但不直接作为强正反馈 |
| 标记坏图 | 不符合需求，需要记录原因 |
| 标记废图 | 完全不可用，后续尽量避开 |
| 添加问题标签 | 说明为什么不好 |
| 添加人工备注 | 用自然语言补充判断 |

### 反馈标签第一版

| 标签 | 说明 |
| --- | --- |
| 跑题 | 没有体现原方向 |
| 重复 | 和已有图太像 |
| 构图弱 | 画面没有广告吸引力 |
| 主体不清 | 一眼看不出重点 |
| 文字差 | 文字乱码、过多、不可读 |
| 风格不符 | 不像无尽冬日或冰封末世 |
| 过度科幻 | 机甲、激光、赛博 UI 过多 |
| 参考图未跟随 | 与参考图线索差距大 |
| 可以量产 | 值得进入正式量产 |
| 可以拓展 | 方向有潜力，值得继续发散 |

### 相关 API

| API | 作用 |
| --- | --- |
| `POST /api/creative-knowledge/assets/:assetId/review` | 更新单张图审核 |
| `POST /api/creative-knowledge/feedback` | 写入反馈 |
| `GET /api/creative-knowledge/feedback` | 查询反馈 |

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 审核是否顺手 | 标好图、坏图是否够快 |
| 标签是否够用 | 是否能表达你常见判断 |
| 反馈是否准确写入 | 刷新后审核状态不丢 |
| 资产是否可筛选 | 能筛选未审核、好图、坏图 |
| 反馈是否可追溯 | 能知道你为什么标坏 |

### 通过标准

```text
你能完成一轮图片审核；
系统能保存你的判断；
下一步可以开始让系统学习这些判断。
```

### 需要你参与的部分

这个阶段需要你实际看图并标记几轮。系统能做界面和记录，但“好不好”必须由你定。

### 不做的事

```text
不自动替你判断好坏
不直接把反馈变成强规则
不删除坏图文件
```

## S3：创意拓展页重组

### 目标

把当前创意拓展页整理成清晰的工作台，让你不用看日志也能理解每次运行。

### 为什么要做

当前创意拓展页已经有很多能力：

```text
上传表格
Agent 生成表格
开始创意拓展
运行一次自动创意
进度状态
输出目录配置
```

但长期使用时，需要按闭环逻辑重排：

```text
数据源
选择目标
配置执行
生成进度
审核结果
历史记录
```

### 新页面结构

```text
创意拓展
  1. 数据源状态
  2. 选择目标
  3. 配置与执行
  4. 运行进度
  5. 结果审核
  6. 历史 run
  7. 手动表格模式
```

### 产出

| 产出 | 说明 |
| --- | --- |
| 自动创意主流程区 | 默认优先展示 run-once |
| 手动表格模式折叠 | 保留旧能力，但不干扰主流程 |
| 方向选择器 | 自动推荐 + 手动指定 directionId |
| Prompt 模式选择 | 只生成 prompt / 小批量 / 完整 25 条 |
| 结果审核入口 | run 完成后直接进入审核 |
| run 历史卡片 | 方便回看 |

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 页面逻辑是否清楚 | 你是否知道下一步该点哪里 |
| 自动推荐是否可信 | 推荐方向和理由是否能理解 |
| 小批量和完整模式是否明确 | 不会误触大批量 |
| 运行过程是否透明 | 能看到在哪个阶段 |
| 老功能是否保留 | 原上传表格和创意批量生图能力不丢 |

### 通过标准

```text
你能不看后端日志，仅通过页面理解：
这次跑了哪个方向、为什么跑、生成多少 prompt、丢弃多少、保存多少图、下一步审核什么。
```

### 跑偏信号

| 信号 | 为什么危险 |

| 只追求一键运行，不展示 Prompt Gate | 容易浪费额度 |
| 审核入口藏太深 | 反馈闭环会断掉 |

## S4：本地成长方向层

### 目标

让好方向不仅是一批图片，而是能进入知识库，成为下一轮可复用的方向。

### 为什么要做

最终系统要“进化”，不能只记录图片。

如果某次生成发现一个好方向，系统应该能：

```text
收录这个方向
记录它来源于哪个原方向
记录为什么好
下次继续沿它拓展
避免重复生成同样东西
```

### 产出

| 产出 | 说明 |
| --- | --- |
| `direction-drafts.json` | 保存 Agent 生成的新方向草案 |
| expanded direction | 人工采纳后进入本地成长层 |
| 方向采纳 / 拒绝 | 对新方向做人工决策 |
| 方向合并 | 避免重复方向越来越多 |
| 方向禁跑 | 某些方向禁止自动运行 |

### 方向状态

| 状态 | 含义 |
| --- | --- |
| seed | 从飞书或 sucai 导入的原始方向 |
| draft | Agent 生成，未审核 |
| accepted | 你确认可用 |
| rejected | 你拒绝，不再推荐 |
| archived | 暂时归档 |
| disabled | 禁止自动运行 |

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 草案是否清楚 | 能看懂 Agent 生成的新方向 |
| 采纳流程是否安全 | 不会自动污染知识库 |
| 拒绝原因是否能记录 | 坏方向能成为反例 |
| 采纳方向是否可复用 | 下轮能看到这个方向 |
| 方向是否不会失控膨胀 | 有合并、归档、禁跑能力 |

### 通过标准

```text
你能从一次 run 的结果里挑出一个好方向，
收录到本地知识库，
并在下一轮选择或自动推荐中看到它。
```

## S5：Prompt 转译层升级

### 目标

把“方向定义”和“Legil 生图 prompt”正式拆开。

### 为什么要做

当前 run-once 中 Agent 同时生成方向和 prompt。短期可以跑，但长期会有问题：

```text
方向不够干净
prompt 风格不稳定
不好判断是方向错了还是 prompt 错了
反馈学习难以定位问题
```

拆层后流程变成：

```text
创意拓展 Agent
  -> 新方向定义
Prompt 转译 Agent
  -> 多条 Legil prompt
Prompt Gate
  -> 通过后生图
```

### 产出

| 产出 | 说明 |
| --- | --- |
| Prompt 转译服务 | 输入方向，输出 Legil prompt |
| Prompt schema | 固定 prompt 字段和格式 |
| Prompt 自检 | 主体、动作、场景、文字、分辨率等检查 |
| Prompt 重写 | 不合格时自动重写一次 |
| Prompt 版本记录 | 每条 prompt 可追溯转译版本 |

### Prompt 标准字段

```text
promptTitle
sourceDirectionId
newDirectionName
subject
action
scene
camera
lighting
visualStyle
textRule
mustKeep
mustAvoid
finalPrompt
```

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 方向和 prompt 是否分清 | 方向不再像一次性提示词 |
| prompt 是否更像你会给 Legil 的指令 | 具体、可执行、不抽象 |
| prompt 是否减少跑偏 | 出图和方向更一致 |
| prompt 语言是否符合你的习惯 | 中文长 prompt 是否可接受 |
| 禁用规则是否生效 | 不该出现的元素没有进 prompt |

### 通过标准

```text
同一个好方向能稳定转译出多条不同但同源的 prompt；
每条 prompt 都能清楚说明画什么；
Prompt Gate 能解释为什么保留或丢弃。
```

### 跑偏信号

| 信号 | 说明 |
| --- | --- |
| prompt 只是换词 | 缺少真正的创意变量 |
| prompt 过短 | Legil 容易自由发挥 |
| prompt 太抽象 | 出图不可控 |
| prompt 太死 | 后续拓展空间不足 |

## S6：反馈学习 Agent

### 目标

让系统从你的审核反馈中总结经验，下一轮自动用上。

### 为什么要做

这是“持续进化”的核心。

没有反馈学习，系统只是自动生成；有反馈学习，系统才会变成：

```text
这类元素你经常喜欢 -> 下次多用
这类元素你经常拒绝 -> 下次避开
这个方向好图率高 -> 提高优先级
这个 prompt 模板容易跑偏 -> 降权或禁用
```

### 产出

| 产出 | 说明 |
| --- | --- |
| `creative-memory.json` | 保存偏好、规避模式、规则 |
| 反馈消化接口 | 把 feedback 转成规则草案 |
| 规则确认页面 | 你确认后规则才启用 |
| Agent 上下文注入 | 下一轮拓展读取规则 |
| 学习报告 | 告诉你系统学到了什么 |

### creative-memory 结构

```json
{
  "preferred_patterns": [],
  "avoid_patterns": [],
  "rules": {
    "global": [],
    "dimension": {},
    "node": {}
  },
  "style_calibration": {},
  "stats": {}
}
```

### 学习流程

```text
人工审核 assets
  -> feedback.json
  -> 反馈学习 Agent 分析
  -> 生成规则草案
  -> 你确认
  -> creative-memory.json
  -> 下一轮 Agent prompt 注入
```

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 学习报告是否说人话 | 能不能看懂系统总结了什么 |
| 正向偏好是否准确 | 系统是否正确理解你喜欢什么 |
| 负向规避是否准确 | 系统是否正确理解你不想要什么 |
| 规则是否可编辑 | 你能改、删、禁用规则 |
| 下轮是否生效 | 新一轮生成是否明显避开旧问题 |

### 通过标准

```text
你审核一批图后，
系统能总结出 3 到 10 条有用规则草案；
你确认后，
下一轮 Agent 输入中能看到这些规则，
生成结果能体现变化。
```

### 不通过时怎么办

如果系统总结得不准，不直接启用规则。先改反馈标签、学习 prompt 和样本数量。

```text
必要时把确认后的好方向写回
```

### 你需要提供

| 项目 | 说明 |
| --- | --- |

| 飞书 App Secret | 用于 token |
| 表格 token / sheet id | 指定读取哪张表 |
| 权限授权 | 应用要能读表、读图片 |
| 写回目标 | 如果后续要写回，需要指定表和字段 |

### 通过标准

```text
点击同步飞书后，
知识库页的数据能更新，
并且和飞书表格核心字段一致。
```

## S9：调度器和 24 小时试运行

### 目标

从“手动运行一次”升级为“按规则自动运行多轮”。

### 为什么现在才做

24 小时循环必须在以下能力稳定后做：

```text
知识库可看
资产可审
反馈可写
Prompt Gate 可控
失败会暂停
结果可追溯
```

否则自动化只会放大错误。

### 调度策略

| 策略 | 说明 |
| --- | --- |
| 时间窗口 | 可配置每天什么时候运行 |
| 每日额度 | 默认 1000 张硬上限 |
| 单轮规模 | 默认 25 prompt x 4 张 = 100 张以内 |
| 冷却时间 | 每轮之间间隔，避免平台风控 |
| 自动暂停 | 连续失败 5 次、额度用完、Legil 异常 |
| 人工接管 | headed 浏览器保持可见 |
| 夜间安全 | 夜间失败只暂停，不反复重试 |

### 产出

| 产出 | 说明 |
| --- | --- |
| scheduler-state 升级 | 记录调度状态 |
| 自动循环服务 | 按规则触发 run-once |
| 调度控制按钮 | 开启、暂停、恢复、停止 |
| 调度日志 | 每轮开始、结束、失败原因 |
| 调度配置 | 每日额度、运行窗口、单轮规模 |

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 是否能开启自动运行 | 不需要每轮手点 |
| 是否能暂停 | 点暂停后不再提交新 prompt |
| 是否守额度 | 不超过每日上限 |
| 是否能避开重复方向 | 不连续跑同一个方向 |
| 是否异常停得住 | 模拟失败后能暂停 |

### 试运行步骤

```text
第 1 天：只开 2 小时，每轮 1 到 2 条 prompt
第 2 天：开 4 小时，每轮 5 条 prompt
第 3 天：开 8 小时，每轮 10 到 25 条 prompt
第 4 天以后：根据稳定性决定是否进入 24 小时
```

### 通过标准

```text
系统能连续运行多轮；
每轮都有 run 记录；
没有超过额度；
失败能暂停；
你能随时知道它在干什么。
```

## S11：准确率优化和持续进化

### 目标

用数据和反馈持续提高“生成你想要的图”的比例。

### 为什么要做

最终目标不是“每天生成 1000 张”，而是：

```text
每天生成越来越多可用图
越来越少跑偏图
越来越少重复图
越来越懂你的方向偏好
```

### 核心指标

| 指标 | 说明 |
| --- | --- |
| Prompt 通过率 | accepted / raw |
| 生图成功率 | saved / expected |
| 审核覆盖率 | reviewed / saved |
| 好图率 | good / reviewed |
| 坏图率 | bad + rejected / reviewed |
| 方向采纳率 | accepted directions / draft directions |
| 重复拦截率 | duplicate rejected / raw |
| 禁用命中率 | forbidden rejected / raw |
| 失败暂停次数 | 越少越好 |

### 优化方式

| 问题 | 优化方式 |
| --- | --- |
| 好图率低 | 调整 Agent 上下文、Prompt 转译规则、参考图策略 |
| 重复多 | 加强历史相似度、方向去重 |
| 跑题多 | 强化 mustKeep、方向定义、参考图上传 |
| 文字差 | 增强画面文字规则和 OCR 后续检查 |
| 风格漂移 | 建立视觉偏好规则和反例规则 |
| 失败多 | 修 Legil 选择器、等待策略、恢复策略 |

### 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 指标是否可信 | 好图率是否符合你的体感 |
| 优化是否有效 | 改规则后下一轮是否变好 |
| 学习是否不乱 | 不会因为少量反馈过度收窄 |
| 是否越来越懂你 | 方向、prompt、图是否更贴近你的要求 |

### 通过标准

```text
连续多天运行后，
好图率、方向采纳率、重复率等指标能被看见；
根据反馈调整后，生成结果有明显改善。
```

## 最终 24 小时正式运行标准

当以下条件都满足，才建议进入真正的 24 小时自动运行：

| 条件 | 标准 |
| --- | --- |
| run-once 稳定 | 连续多轮无严重错误 |
| 小批量稳定 | 2 到 5 prompt 多轮成功 |
| 完整单轮稳定 | 25 prompt 能稳定完成或可控失败 |
| 资产入库稳定 | 每张图都能写入 assets |
| 审核闭环稳定 | 你能方便标好坏 |
| 反馈学习有效 | creative-memory 能影响下一轮 |
| 额度控制稳定 | 不超过 1000 张 / 天 |
| 失败暂停稳定 | 连续失败能停 |
| 通知稳定 | 异常、暂停、完成、日报可靠 |
| 重启恢复稳定 | 服务重启不丢状态 |

正式运行后的日常节奏：

```text
系统白天 / 夜间自动运行
  -> 你每天看日报
  -> 挑时间审核好图坏图
  -> 系统消化反馈
  -> 下一个运行窗口自动应用
```

建议每个阶段结束后，你按下面模板验收：

```text

   通过 / 不通过

2. 这个阶段是否解决了它应该解决的问题？
   通过 / 不通过

3. 这个阶段有没有让项目更接近 24 小时准确生图？
   通过 / 不通过

4. 有没有明显跑偏？
   没有 / 有，问题是：

5. 是否允许进入下一阶段？
   允许 / 暂停 / 需要调整
```

## 防跑偏规则

以下情况出现时，应该暂停继续开发，先纠偏：

| 跑偏信号 | 为什么要停 |
| --- | --- |
| 只增加自动运行，不增加审核反馈 | 系统会更快地产生错误 |
| 只看生成数量，不看好图率 | 会浪费额度和时间 |
| 图片没有资产记录 | 无法学习和追溯 |
| 反馈只写备注，不进入规则 | 下一轮不会变好 |
| Agent 直接写知识库 | 容易污染方向体系 |
| 飞书自动写回无人工确认 | 容易污染团队底表 |
| 24 小时循环没有暂停机制 | 可能无限失败 |
| 页面看不懂系统状态 | 你无法接管和判断 |

## 你需要提供的东西

大部分开发系统可以自己推进。真正需要你提供或确认的是：

| 阶段 | 需要你提供 |
| --- | --- |
| S1 | 确认知识库展示的方向层级是否符合你理解 |
| S2 | 实际审核几轮图，告诉系统什么是好图、坏图 |
| S4 | 决定哪些新方向可以收录 |
| S5 | 判断 prompt 风格是否符合你想给 Legil 的方式 |
| S6 | 确认系统总结的规则是否准确 |
| S7 | 提供飞书 App、表格、权限配置 |
| S8 | 确认好图进入量产、改尺寸、重命名的工作方式 |
| S9 | 确认自动运行时间窗口和放量节奏 |
| S10 | 确认飞书通知目标和日报格式 |
| S11 | 持续给反馈，校准什么是你要的图 |

默认不需要你提供的：

```text
输出目录
参考图目录
Legil 默认参数
每日额度规则
每 prompt 出图张数
基础禁用规则
Prompt Gate 逻辑
run 记录结构
assets 入库逻辑
```

## 项目最终成熟后的工作方式

最终成熟后，你的角色会从“手工操作生图平台”变成“创意系统的导演和审核者”。

你的日常工作：

```text
看日报
看好图
标记坏图原因
收录好方向
确认系统总结的规则
偶尔调整禁用词和方向策略
在 Legil 登录失效时接管
```

系统的日常工作：

```text
同步知识库
选择方向
拓展新方向
生成 prompt
质检去重
控制额度
操作 Legil
保存图片
写入资产
等待审核
学习反馈
更新下一轮策略
```

成熟状态的判断：

```text
你不需要盯着它每一步；
你能随时看懂它为什么这么做；
你能纠正它；
它能记住纠正；
它能在下一轮变好。
```
