# Web页面成熟产品化分阶段开发文档-20260612

## 1. 文档目的

本文档用于指导当前 AI 生图自动化平台的 Web 页面成熟产品化改造。目标是在尽量不影响现有后端接口、自动化能力和业务函数的前提下，系统性提升页面的信息架构、视觉一致性、移动端可用性、任务启动效率和对外展示成熟度。

本次改造重点不是重做业务能力，而是把现有功能从“内部开发控制台”升级为“成熟的自动化生产工作台”。

## 2. 当前结论

当前平台功能已经较完整，覆盖运行中心、自动化策略、创意拓展、素材分析、方案迭代、批量产图、知识库、改尺寸交付、全局配置等核心模块。但页面仍有明显的连续迭代痕迹：

- 全局导航没有按业务心智分组，移动端导航占用首屏过多。
- 页面首屏被品牌标题、导航和状态条压得较低，桌面端业务首卡通常在约 383px 以后出现。
- 批量产图页承载了多种模式，但最高频的“参考图自动产图”没有成为唯一清晰主入口。
- 改尺寸页已经覆盖标准化、LOGO、命名、打包，隐藏的 renamePage 不应再作为独立产品入口。
- 页面存在内部文案，例如 OK 图、S10.3、P0、P1、老流程、新流程、Run、Phase 等，成熟产品感不足。
- 移动端需要完整支持配置和启动任务，因此不能只做查看型适配。
- 实时日志常驻底部适合开发调试，但对日常使用和移动端完整操作不友好。

## 3. 已确认产品决策

### 3.1 生产导航顺序

生产组顺序固定为：

1. 创意拓展
2. 素材分析
3. 方案迭代
4. 批量产图

说明：

- 创意拓展作为生产策源地。
- 素材分析作为数据反馈与创意机会发现。
- 方案迭代作为人工计划表到自动化方向池的连接器。
- 批量产图作为最终执行器，虽然高频，但在业务链路中放在生产组最后。

### 3.2 页面命名

- “月度方案迭代”统一改为“方案迭代”。
- “OK 图三尺寸交付”统一改为“改尺寸交付”。
- 页面内出现“OK 图”的文案全部调整为“源图”“待交付图片”“交付图片”等更成熟的产品表达。
- “自治策略”建议升级为“自动化策略”。如希望保留原名，也应在页面说明中去掉内部 Policy Guard 口吻。

### 3.3 renamePage 处理

当前 renamePage 是隐藏的本地交付工具页，包含：

- 重命名设置
- 本地标准化
- 批量加 LOGO
- 批量打包文件夹

由于“改尺寸”页已经覆盖标准化、LOGO、命名、打包，后续处理原则为：

- renamePage 不作为正式导航入口。
- renamePage 的能力合并到“改尺寸交付”流程。
- 保留底层函数，避免影响现有工具能力。
- 如仍需手动独立执行，放入“改尺寸交付”的高级本地工具折叠区，而不是独立页面。

### 3.4 移动端要求

移动端必须完整支持：

- 页面切换
- 路径配置
- 参数配置
- 任务启动
- 任务暂停、继续、停止
- 进度查看
- 日志查看
- 关键结果查看

移动端不是只读状态页。

### 3.5 批量产图最高频模式

批量产图页最高频使用场景为：

```text
参考图 -> Winky 自动生成提示词 -> Legil 生图 -> 保存结果
```

因此批量产图页默认模式应为“参考图自动产图”，表格提示词产图和手动提示词池作为次级模式。

## 5. 改造原则

### 5.1 不影响现有功能

第一阶段尽量不改后端接口、不改自动化流程、不改已有函数入参。优先通过：

- HTML 轻量重排
- CSS 统一
- 少量前端交互增强
- 文案替换
- 页面入口调整

完成成熟产品化。

### 5.2 每页只保留一个当前主动作

每个页面在当前状态下最多突出一个主按钮：

- 创意拓展：开始创意拓展
- 素材分析：导入素材数据
- 方案迭代：导入方案表
- 批量产图：开始自动产图
- 改尺寸：开始改尺寸交付
- 配置：保存配置

其他动作降级为次级按钮、更多菜单或折叠区域。

### 5.3 执行优先，配置折叠

高频页面首屏应优先展示：

- 输入来源
- 输出位置
- 必要配置
- 当前主操作
- 当前任务状态

高级配置默认折叠，只保留用户启动任务前必须判断的内容。不要为了“看起来完整”额外增加重复摘要卡片。

### 5.4 状态可信

状态文案要避免大面积 `--`、`读取中`、`暂无`。

建议统一为：

- 未开始
- 暂无数据
- 未配置
- 正在读取状态
- 运行中
- 已完成
- 失败
- 需要处理

### 5.5 去内部化

成熟产品页面中尽量不展示：

- OK 图
- S10.3
- P0 / P1
- 基线收口
- 老流程 / 新流程
- Run
- Phase
- Agent
- final-package
- 过多 emoji 按钮

替换为：

- 源图 / 待交付图片
- 改尺寸交付
- 系统状态
- 批量产图 / 创意拓展 / 交付任务
- 任务
- 阶段
- 执行模块
- 交付包
- 统一图标或纯文本按钮

### 5.6 视觉设计与版式硬性要求

本项目后续前端调整需要按网页设计专家和平面设计专家标准处理，不能只满足“功能可用”。每次改页面时都要同时检查内容细节、视觉传达和排版质量。

设计要求：

- 页面第一眼必须能判断“这是做什么的、下一步点哪里、当前是否可执行”。
- 首屏不堆解释说明，不用流程条替代真实操作路径。
- 主卡、次级卡、任务列表要按同一栅格对齐，不出现左窄右空、局部挤压、下方空洞。
- 卡片数量从严控制，能合并到主流程的配置不单独拆成卡片。
- 普通信息卡不堆装饰图标；图标只用于导航、状态、关键操作和危险操作。
- 表单字段要按真实工作顺序排列，不能为了视觉平衡打乱任务逻辑。
- 路径、文件名、示例命名必须处理长文本溢出，不能撑破输入框、按钮或卡片。
- 按钮文案短、明确、同一语义同一叫法，不能混用内部口径。
- 移动端不是桌面端缩小版，需要重新排列为可配置、可启动、可停止的单列任务流。

每次交付前必须做两类检查：

```text
内容检查：是否有不该给外部用户看的内部文案、重复摘要、解释型提示。
版式检查：是否对齐、是否拥挤、是否溢出、是否有不合理空白、是否主次清楚。
```

## 6. 分阶段开发计划

## 阶段 P0：成熟产品化基础框架

### 6.1 阶段目标

建立成熟产品的全局信息架构和基础交互框架，解决所有页面共有的首屏过低、导航过重、内部文案明显、移动端导航不可扩展等问题。

### 6.2 改造范围

主要文件：

- `public/index.html`
- `public/js/ui-core.js`
- `public/css/visual-polish.css`
- `public/css/feature-pages.css`
- `public/css/logs-modal-toast.css`

### 6.3 开发任务

1. 调整全局导航分组。
2. 生产组顺序改为：创意拓展、素材分析、方案迭代、批量产图。
3. “月度方案迭代”全局改为“方案迭代”。
4. “OK 图”全局替换为成熟产品文案。
5. “OK 图三尺寸交付”改为“改尺寸交付”。
6. “自治策略”评估是否改为“自动化策略”，优先改页面展示文案。
7. 压缩 Header。
8. 移动端导航改为页面切换抽屉。
9. 顶部状态条文案和颜色可信化。
10. 实时日志改为可收起或抽屉。
11. 移除按钮 emoji。
12. 隐藏 renamePage 正式入口。

### 6.4 验收标准

桌面端：

- 全局业务首卡从约 383px 降到不超过 220px。
- 导航按 4 组展示。
- 页面标题和副标题无明显内部阶段文案。
- 正式导航中不出现 renamePage。
- 生产顺序正确。

移动端：

- 导航不再 3 行铺满首屏。
- 页面切换通过抽屉或菜单完成。
- 首张业务卡片不超过 180px 出现。
- 无横向滚动。
- 日志默认不占用主页面高度。

文案：

- 页面中不再出现“OK 图”作为用户可见主文案。
- “月度方案迭代”不再作为页面名出现。
- “Run / Phase / Agent”不作为主要中文页面文案出现。

### 6.5 风险与控制

风险：

- 导航结构变更可能影响 `switchPage()` 的 class 切换逻辑。
- 移动端抽屉需要确保不影响桌面端原有点击。

控制：

- 保留原页面 id。
- 保留原函数名。
- 仅调整展示入口和 class。
- 每个页面切换后做截图验收。

## 阶段 P1：批量产图高频路径重排

### 7.1 阶段目标

把“参考图自动产图”升级为批量产图页默认主流程。降低表格提示词、手动提示词等次级模式对首屏的干扰。

### 7.2 页面定位

页面名：

```text
批量产图
```

副标题：

```text
根据参考图自动生成提示词，并批量提交生图任务。
```

默认模式：

```text
参考图自动产图
```

### 7.3 首屏结构

首屏建议包含：

```text
参考图自动产图

参考图文件夹
生图参考图文件夹
输出文件夹

参数摘要
Winky: gpt-5.5
生图平台: Legil
模型: Nano Banana 2
比例: 1:1
输出: 4 张
模式: 有头/无头

[扫描参考图] [开始自动产图] [继续任务] [打开生图平台]
```

### 7.4 开发任务

1. 增加批量产图模式切换：
   - 参考图自动产图
   - 表格提示词产图
   - 手动提示词池
2. 默认选中参考图自动产图。
3. 文件夹配置、参数摘要、主按钮提前到首屏。
4. Legil URL、Legil 参数、Winky 提示词模板折叠为高级配置。
5. 表格提示词批量产图移入次级 tab。
6. 提示词管理移动到结果区。
7. 旧完整工作流内容保留，但不要作为首屏主流程。
8. 运行中显示迷你状态条。
9. 移动端底部 sticky 主操作。

### 7.5 按钮层级

未扫描：

- 主按钮：扫描参考图
- 次按钮：打开生图平台

已扫描：

- 主按钮：开始自动产图
- 次按钮：继续任务、打开生图平台

运行中：

- 主按钮：查看进度
- 次按钮：暂停、继续
- 危险按钮：停止任务

### 7.6 验收标准

- 进入批量产图页默认看到参考图自动产图。
- 首屏能完成参考图文件夹、输出文件夹配置和任务启动。
- 表格提示词产图不再占据默认首屏。
- 移动端能完整配置路径并启动任务。
- 运行中能看到当前参考图、当前阶段、进度和停止入口。

## 阶段 P2：改尺寸交付整合

### 8.1 阶段目标

把“改尺寸”页成熟化为“改尺寸交付”工作台，并整合 renamePage 的重命名、标准化、LOGO、打包能力。

本阶段只调整前端页面内容、信息层级、排版和展示入口，不改变既有后端接口、任务函数、默认路径、续跑逻辑和交付链路。目标是让页面看起来像成熟产品，而不是把所有内部处理步骤都展示给用户。

### 8.2 页面定位

导航名：

```text
改尺寸
```

页面标题：

```text
改尺寸交付
```

副标题：

```text
将待交付图片自动适配为多种投放尺寸，并完成标准化、LOGO、命名与打包。
```

页面表达原则：

```text
输入清楚 -> 输出清楚 -> 一键启动 -> 状态可追踪
```

不要在首屏展示 `源图导入 -> AI 尺寸适配 -> 标准化 -> LOGO -> 命名 -> 交付包` 这类流程条。流程存在于后台任务链路，不作为普通用户主视觉内容。

### 8.3 文案替换

必须调整：

```text
OK 图 -> 源图 / 待交付图片
OK 图输入文件夹 -> 源图文件夹
扫描 OK 图 -> 扫描源图
OK 图改尺寸 -> 改尺寸交付
OK 图三尺寸交付 -> 改尺寸交付
完整改尺寸交付 -> 完整交付流程
final-package -> 交付包
```

### 8.4 页面结构

首屏：

```text
源图文件夹
交付输出文件夹
LOGO 模板目录
目标尺寸
处理模式

[扫描源图] [开始改尺寸交付] [继续未完成]
```

首屏不展示：

```text
配置摘要
1-6 步骤说明
标准化配置
备用业务命名
交付包设置
示例文件夹命名
```

版式要求：

```text
改尺寸交付主卡：通栏
命名规则卡：通栏，位于主卡下方
任务列表：通栏，位于命名规则之后
LOGO 模板目录：放在交付输出文件夹下方
```

任务列表：

桌面端为表格，移动端为卡片。任务列表头部只保留标题，不展示“桌面端按表格查看，移动端自动切换为任务卡片”这类说明文案。

### 8.5 命名规则排版

命名规则是用户需要理解的唯一显性后处理规则，放在主交付卡下方，不放在右侧窄栏。

桌面端四项核心配置一行展示：

```text
固定前缀 | 起始编号 | 区域/代号 | 渠道
```

示例只保留图片命名：

```text
示例图片：GOFCNIM28930_BJ_广点通_题材_探索发现_三级标签_细分命名_800x800.jpg
最终命名按前缀、编号、区域、渠道和尺寸后缀生成。
```

要求：

- 不展示示例文件夹命名。
- 不展示备用业务命名。
- 长文件名必须单行省略，不能撑破卡片。
- 移动端字段纵向排列，主操作仍可触达。

### 8.6 renamePage 合并策略

映射关系：

```text
renamePage 重命名设置 -> 改尺寸交付：命名规则
renamePage 本地标准化 -> 改尺寸交付：后台标准化能力
renamePage 批量加 LOGO -> 改尺寸交付：LOGO 模板目录
renamePage 批量打包文件夹 -> 改尺寸交付：后台打包能力
```

保留底层 JS：

- `rename-images.js`
- 与标准化、LOGO、打包相关函数

但不再提供独立正式页面入口。

前端展示控制：

- `标准化配置` 不作为默认前端卡片展示。
- `交付包设置` 不作为默认前端卡片展示。
- `备用业务命名` 不作为默认前端卡片展示。
- 需要兼容既有函数时，可以保留隐藏按钮或隐藏容器，但不能占页面视觉空间。

### 8.7 视觉验收标准

- 改尺寸页没有“OK 图”用户可见主文案。
- 页面标题为“改尺寸交付”。
- 用户能在首屏完成源图扫描和开始交付。
- `LOGO 模板目录` 位于 `交付输出文件夹` 下方。
- `配置摘要` 不在前端页面展示。
- 1-6 步骤说明不在前端页面展示。
- `改尺寸交付` 主卡和 `命名规则` 卡通栏对齐。
- `任务列表` 头部不展示解释响应式规则的说明文案。
- 标准化、LOGO、命名、打包能力保留在执行链路中，但前端只展示用户真正需要配置和判断的内容。
- renamePage 不出现在正式导航中。
- 移动端任务列表以卡片展示，不横向溢出。

### 8.8 风险与控制

风险：

- 删除可见卡片时误删底层函数依赖的 id。
- 通栏布局覆盖旧 CSS 时影响移动端 sticky 主操作。
- 为了“说明清楚”再次增加大量提示文案，导致页面重新变复杂。

控制：

- 保留既有关键 id 和函数名，仅移动 DOM 或隐藏展示入口。
- 前端隐藏不等于删除能力，后端链路仍按原流程执行。
- 新增文案优先短句，避免解释响应式规则、内部步骤和技术实现。
- 桌面端和移动端都做截图验收，检查无横向滚动、文本不溢出、主操作可触达。

## 阶段 P3：创意拓展成熟化

### 9.1 阶段目标

把生产组第一入口“创意拓展”优化为成熟的生产策源地页面。

### 9.2 页面定位

标题：

```text
创意拓展
```

副标题：

```text
基于知识库方向自动拓展创意，生成提示词并提交生图。
```

流程：

```text
方向选择 -> 提示词质检 -> 生图生成 -> 结果审核
```

### 9.3 开发任务

1. 去掉“跑起来”等口语化文案。
2. `Prompt Gate` 展示为“提示词质检”，二级说明保留 Prompt Gate。
3. 首屏突出：
   - 方向库状态
   - 图片额度
   - 推荐方向
   - 当前任务
   - 开始创意拓展
4. Legil 生图参数默认折叠。
5. 运行进度区域在桌面端保持可见，移动端以 sticky 状态条展示。
6. 历史 run 改为“历史任务”。
7. Run ID 改为“任务 ID”。

### 9.4 验收标准

- 创意拓展首屏可直接理解“从方向到生图”的链路。
- 页面不出现明显内部口吻。
- 只有一个主按钮。
- 移动端能选择方向、配置参数并启动任务。

## 阶段 P4：素材分析阶段化

### 10.1 阶段目标

降低素材分析页未导入数据前的空态噪音，将导入、分析、报告、视觉识别、创意拓展按阶段展示。

### 10.2 页面定位

标题：

```text
素材分析
```

副标题：

```text
导入投放素材数据，识别高消耗素材、表现趋势和后续创意机会。
```

### 10.3 阶段结构

```text

历史导入
```

导入后：

```text

```

分析后：

周报与经验文档

4. `D0 ROI 健康度优先目标` 改为 `ROI 健康度`。
5. 按钮主次重新排序。
6. 移动端表格改卡片。
7. 增加“送入方案迭代 / 送入创意拓展”的清晰入口。

### 10.5 验收标准

- 未导入数据时页面不显示大面积无效 `--`。
- 用户清楚第一步是导入素材数据。
- 导入后才展示后续分析能力。
- 移动端能上传或配置素材表并触发分析。

- 所有现有后端能力和自动化能力保持可用。
