# 创意拓展页面方向标签优化方案

日期：2026-06-26  
范围：`创意拓展产图` 页面、候选方向审核、Agent 拓展策略、方向标签与知识库联动  
定位：本方案替代旧方案里用户可见的“视觉 DNA”表达。后续页面统一使用“方向标签”，分类只作为内部逻辑和颜色映射存在，不在页面上显示“氛围 / 视角 / 事件 / 钩子”等字段名。

## 1. 最新结论

当前方向需要从“显性展示 visualHook / creativeAxes”调整为“用短中文方向标签表达画面重点”。页面目标不是让用户读结构化字段，而是让用户一眼看懂：

- 这个方向画面核心是什么。
- 它和已有方向有什么不同。
- 它有没有参考图支撑。
- 它适合稳定复用，还是适合探索新组合。
- 它能不能直接进入 prompt 和生图。

因此创意拓展页不再把 `visualHook`、`riskNote`、`productionAdvice` 原样露出，也不再用“视觉 DNA：氛围 -- / 视角 -- / 事件 -- / 钩子 --”这种行文。它们应被转译为短标签、候选理由、风险提示和投产建议。

推荐用户可见语言：

```text
方向标签
标签覆盖
标签组合
高表现标签
缺口标签
避坑标签
候选方向审核
生成投产任务
```

不再显示：

```text
视觉 DNA
氛围
视角
事件
钩子
visualHook
dedupeReason
riskNote
productionAdvice
```

这些字段可以继续作为兼容数据源存在，但页面和 Agent 指令应统一抽象成“方向标签”。

## 2. 参考截图带来的页面判断

### 2.1 创意拓展页的参考重点

参考项目的创意拓展页有几个值得吸收的产品结构：

```text
数据源
  当前使用哪个标签宇宙 / 知识库

入口
  标签树
  灵感定位
  自动拓展

自动拓展配置
  拓展层级
  拓展方式
  公共设置

运行阶段
  加载 / 上下文 / LLM / 解析 / 完成

候选方向审核
  候选卡片
  预览图
  历史

底部操作
  去知识库整理
  生成投产任务
  回填飞书
```

这个流程的核心不是“先配置生图参数”，而是“先把方向想清楚”。它把 prompt 和生图放在候选审核之后，符合当前用户希望“在方向层纠偏，而不是等图片生成后才发现方向不对”的目标。

### 2.2 知识库截图对创意拓展页的启发

知识库截图里真正有价值的不是某一种暗色样式，而是信息密度和标签表达方式：

- 树形目标在左侧，选中目标详情在右侧。
- 参考图以小缩略图显示，缺图位置用虚线占位。
- 方向状态用小 badge 表达：本地成长、待补齐、1 图、3 图。
- 方向描述是一小段自然语言。
- 标签是短中文 pill，不展示分类名。
- 页面有“可用性 / Agent”这样的生产判断，不只是资料展示。

这意味着创意拓展页的候选方向卡片也应该像“可投产方向单元”，而不是像日志详情。每张候选卡片应该能在 3 秒内回答：它是什么、重点在哪、为什么保留、风险在哪、下一步做什么。

### 2.3 当前项目页面的问题

当前 `creativePage` 已经有很强的执行能力：

- 输出目录和参考图目录。
- 生图参数。
- 待拓展方向队列。
- 候选倍率、拓展随机度、历史避重范围。
- 候选方向审核模式。
- 运行进度、Prompt Gate、最近产出、结果审核。
- 历史任务。

问题主要在产品表达：

- 第一屏更像“产图控制台”，不是“创意拓展工作台”。
- 候选方向审核区被放在运行进度内部，存在感不够强。
- 生图参数过早出现，抢占了方向策划的注意力。
- 方向标签没有成为核心语言，仍然混杂描述、字段名和英文内部字段。
- 候选卡片信息长短不一，用户需要阅读很多文字才能判断方向质量。
- “自动通过 / 人工审核 / 只生成 prompt / 持续生图”等模式分散，缺少清晰的决策顺序。

## 3. 页面目标

新版创意拓展页应分成四段心智：

```text
选目标
  从方向库、标签地图、素材分析、方案迭代选择本轮要拓展的父方向或方向包。

选策略
  稳定拓展：复用高表现标签组合。
  探索拓展：跨组合、补缺口、寻找新方向。

审候选
  先看候选方向标签、描述、参考图状态、保留理由和风险，再决定采纳、编辑、删除。

再投产
  通过审核的候选方向进入 prompt 生成和 Legil 生图。
```

页面不应该默认给用户一种“点开始就直接产图”的压力，而应该让用户觉得这是一个可控的创意决策流程。

## 4. 建议的信息架构

### 4.1 顶部导航

保留当前平台顶部导航，但页面标题建议从：

```text
创意拓展产图
```

调整为：

```text
创意拓展
```

副标题调整为：

```text
先生成和审核新方向，再进入 prompt 与生图投产。
```

顶部右侧状态只保留当前任务状态：

```text
待启动 / 生成候选中 / 等待审核 / 生成 prompt 中 / 生图中 / 已完成 / 已暂停
```

### 4.2 第一屏结构

建议第一屏采用上下结构，而不是把目录和生图参数放在最前：

```text
创意拓展

1. 数据源
   当前方向包 / 标签宇宙 / 知识库同步状态

2. 入口
   [标签树] [灵感定位] [自动拓展]

3. 本轮策略
   目标方向
   方向标签概览
   稳定拓展 / 探索拓展
   候选方向审核：自动通过 / 人工审核

4. 候选方向审核
   候选卡片列表

底部固定操作
   已选 N 个
   去知识库整理
   生成投产任务
   回填飞书
```

生图参数和输出目录放进“投产设置”折叠面板，默认收起。只有用户准备生成投产任务时才需要看它。

## 5. 三个入口模式

### 5.1 标签树

用途：用户明确知道要拓展哪个方向时使用。

界面：

```text
左侧：方向树 / 搜索 / 筛选
右侧：选中方向详情
  方向路径
  方向描述
  方向标签
  参考图状态
  Agent 可用性
  加入本轮拓展
```

标签显示规则：

```text
末世标语  冰封墙面  幸存者  停下必亡  蓝冷光
```

不要显示：

```text
氛围：紧张危机 / 视角：第一人称 / 事件：逃离 / 钩子：中文标语
```

### 5.2 灵感定位

用途：用户不是从某个已知方向出发，而是输入一个创意意图，让 Agent 找方向。

输入：

```text
我想做一批冰封末世里更有转化感的生存提示画面
```

输出：

```text
建议目标方向：
末世标语
地下避难所
冰裂断桥

建议标签：
中文标语  冰封废墟  求救信号  近景人物  危机选择
```

页面动作：

- 一键加入候选目标。
- 转到自动拓展。
- 保存为本地成长方向草案。

### 5.3 自动拓展

用途：批量生成新方向。

配置项建议收敛为：

```text
拓展策略
  稳定拓展
  探索拓展

候选规模
  每个目标生成 4 个新方向
  候选倍率 2

投产规模
  每个新方向生成 2 条 prompt

审核方式
  人工审核
  自动通过
```

“拓展随机度 / 历史避重范围”等技术配置可以放进高级设置，不要出现在核心决策区。

## 6. 拓展策略设计

### 6.1 稳定拓展

目标：复用高表现标签组合，降低产图失败率。

Agent 行为：

- 优先读取当前父方向下高采纳标签。
- 优先使用已有好图验证过的组合。
- 允许替换其中 1 到 2 个标签形成轻微变化。
- 避免过度跳题。
- 适合稳定跑量、复用成熟题材。

示例：

```text
父方向：城市废墟
高表现标签：巨型地标  暴风雪  俯瞰  初次发现  求救信号

稳定拓展：
雪夜信号塔求救
暴风雪  信号塔  求救信号  远景压迫  生存选择
```

### 6.2 探索拓展

目标：跨标签组合，补齐方向库缺口，发现新优质方向。

Agent 行为：

- 读取当前方向的高表现标签和缺口标签。
- 用“高表现标签 + 缺口标签”生成新组合。
- 保留核心题材一致性，但允许画面机制变化。
- 对历史重复组合加惩罚。
- 对风险标签加惩罚。

示例：

```text
父方向：城市废墟
高表现标签：暴风雪  巨型地标  第一人称
缺口标签：近景物件  暖光路标  低机位

探索拓展：
暖光路标下的避难入口
暖光路标  低机位  近景手电  避难入口  雪夜废墟
```

### 6.3 策略在页面上的表达

页面只显示两个主要选项：

```text
稳定拓展
复用高表现标签组合，适合批量投产。

探索拓展
跨组合补缺口，适合寻找新方向。
```

内部可以继续保留 `balanced` 作为兼容值，但用户可见层不建议再放第三个“平衡”，否则决策会变模糊。

## 7. 候选方向卡片设计

### 7.1 卡片主结构

每个候选方向卡片建议固定为：

```text
雪夜信号塔求救                       86
雪夜废墟  信号塔  求救信号  暴风雪  远景压迫

幸存者在暴风雪废墟中发现仍在闪烁的信号塔，尝试发出求救信号。

值得保留
已有高表现标签“暴风雪 / 巨型地标”，新增“求救信号”让目标动作更明确。

注意
与“黎明废墟俯瞰”同属巨型地标，但核心动作不同；参考图不足，建议后续补图。

[采纳] [编辑] [删除] [入成长层] [直接生成 prompt]
```

注意：卡片上不显示“visualHook / dedupeReason / riskNote / productionAdvice”。这些内容要转译成人话：

| 内部字段 | 页面文案 |
| --- | --- |
| `visualHook` | 融入标签和描述 |
| `dedupeReason` | `注意` 或 `重复风险` |
| `riskNote` | `注意` 或风险标签 |
| `productionAdvice` | `投产建议`，默认折叠或放 tooltip |
| `creativeAxes` | 转为短中文方向标签 |

### 7.2 标签规则

候选卡片最多显示 5 个主标签：

```text
雪夜废墟  信号塔  求救信号  暴风雪  远景压迫
```

编辑详情里显示：

```text
主标签：5 个
扩展标签：最多 5 个
风险标签：单独一行
```

风险标签可以显示，但要和主标签视觉区分：

```text
风险：英文文字  主体遮挡  文字过多
```

风险标签不计入主标签组合，不参与“画面重点”的主要展示。

### 7.3 标签质量标准

好标签：

```text
中文标语
冰封墙面
求救信号
近景手电
巨型地标
低机位
暴风雪
断桥逃生
红色警示
暖光路标
```

坏标签：

```text
macro prop with human stakes
方向正确
主体明确
一眼能吸引人
氛围紧张危机
视觉钩子强
productionAdvice
```

规则：

- 必须是中文。
- 优先 2 到 6 个字，最多 8 个字。
- 不显示分类前缀。
- 不出现英文内部字段。
- 不使用长句。
- 不把抽象评价当标签。
- 标签应描述画面可见元素、构图关系、动作机制、场景特征或关键符号。

## 8. 候选审核工作流

### 8.1 自动通过

保持当前流程：

```text
目标方向
  -> Agent 生成候选方向
  -> Direction Plan Gate 自动筛选
  -> Prompt Gate
  -> Legil 生图
```

页面上仍然要在运行详情中展示候选回看，但不阻塞任务。

### 8.2 人工审核

推荐作为重要任务默认模式：

```text
目标方向
  -> Agent 生成候选方向
  -> 停在候选审核区
  -> 用户采纳 / 编辑 / 删除
  -> 采纳项生成 prompt
  -> Prompt Gate
  -> Legil 生图
```

用户编辑项：

```text
方向名
方向描述
主标签
扩展标签
风险标签
避坑说明
```

用户不需要编辑内部分类。分类由系统根据标签词典和 AI 分析自动归类，只用于颜色、统计和 Agent 组合逻辑。

### 8.3 底部操作条

参考截图的底部固定操作很适合当前场景。建议在候选审核区出现时固定显示：

```text
已选 3
[全选] [去知识库整理] [生成投产任务] [回填飞书]
```

动作定义：

- `全选`：采纳当前可用候选。
- `去知识库整理`：把候选送入成长整理页面。
- `生成投产任务`：基于已采纳候选生成 prompt，并按投产设置调用生图。
- `回填飞书`：把审核后的方向和标签写回飞书方向表。

## 9. 投产设置位置

当前页面把输出目录、参考图目录、生图模型、比例、分辨率等放在前面。新版建议改为：

```text
投产设置
  输出目录
  参考图目录
  图生图模型
  宽高比
  分辨率
  输出数量
  有头 / 无头
```

默认收起，只在以下场景自动展开：

- 用户点击“生成投产任务”。
- 配置缺失或输出目录不可用。
- 当前任务失败原因与投产配置有关。

这样页面主注意力会回到“方向与候选”，而不是“机器参数”。

## 10. 方向标签数据层

### 10.1 新增方向标签文件

建议新增：

```text
data/creative-knowledge/direction-tags.json
```

建议结构：

```json
{
  "version": 1,
  "updatedAt": "2026-06-26T00:00:00.000Z",
  "directions": {
    "direction-id": {
      "directionId": "direction-id",
      "path": "题材/探索发现/末世标语",
      "summary": "画面核心为冰封墙面上的末世生存标语，体现封冻末世里的生存危机感。",
      "mainTags": ["末世标语", "冰封墙面", "幸存者", "红色警示", "生存危机"],
      "extraTags": ["暴风雪", "手电照明", "近景人物", "蓝冷光"],

      },

    }

    "俯瞰": {
      "aliases": ["鸟瞰", "高空视角"],
      "internalType": "composition"
    }
  }

```

### 10.2 数据来源优先级

方向标签应从多源聚合，不只靠文本猜：

```text
1. 参考图 AI 视觉识别
2. 方向描述
3. 好图 feedback
4. direction-evidence 成功案例
5. direction-expansion-history 入选候选
6. direction-drafts 已采纳草案
7. runs/*.json 的 selectedExtensions
8. 旧 visualDna / visualHook / creativeAxes 兼容字段
```

第一版可以先用已有文本和历史数据聚合，但最终必须接入参考图 AI 视觉识别。视觉识别必须走 Lumos Winky OpenAI-compatible chat completions，并用 `image_url` 传图，遵守项目 AGENTS.md 的 LLM Provider Rule。

### 10.3 参考图充足度

按用户确认的规则：

```text
0 张：缺参考图
1-2 张：参考图不足
3+ 张：可用
```

如果该方向已有好图反馈，可以降低补图紧急度，但不要把参考图数量伪装成充足。页面可以显示：

```text
1 图 · 有好图证据
```

而不是显示：

```text
参考图充足
```

## 11. Agent 使用方向标签

### 11.1 Agent 指令上下文

`buildAgentInstruction` 应从旧的“视觉 DNA 上下文”调整为“方向标签上下文”：

```text
当前方向标签：
- 高表现标签：暴风雪、巨型地标、中文标语、第一人称
- 缺口标签：近景物件、暖光路标、低机位
- 避坑标签：英文文字、文字过多、主体遮挡、过度科幻
- 重复组合：暴风雪 + 巨型地标 + 俯瞰
- 本轮策略：探索拓展
```

Agent 生成候选方向时必须输出：

```json
{
  "name": "雪夜信号塔求救",
  "description": "幸存者在暴风雪废墟中发现仍在闪烁的信号塔，尝试发出求救信号。",
  "mainTags": ["雪夜废墟", "信号塔", "求救信号", "暴风雪", "远景压迫"],
  "extraTags": ["巨型地标", "蓝冷光"],
  "riskTags": ["主体过小"],
  "keepReason": "复用高表现标签“暴风雪 / 巨型地标”，新增“求救信号”形成更明确的动作目标。",
  "reviewSuggestion": "可采纳，后续建议补充信号塔和求救灯光类参考图。"
}
```

### 11.2 Direction Plan Gate 打分

旧打分项可以保留，但要改成标签语义：

```text
标签完整度
  至少 3 个主标签，推荐 5 个。

标签可视化程度
  标签是否能直接在画面里被看见。

高表现匹配
  是否复用当前父方向下已验证的高表现标签。

缺口探索
  是否补齐当前方向库缺少的标签。

组合新颖度
  是否避免重复历史组合。

风险惩罚
  是否触发英文文字、主体遮挡、过度科幻、文字过多等风险。

描述一致性
  描述是否覆盖主标签，而不是标签和描述各说各话。
```

打分摘要不要显示技术字段，页面显示为：

```text
知识评分 86
值得保留：高表现标签复用明确，同时补了“求救信号”缺口。
注意：参考图不足，投产前建议补图。
```

### 11.3 Prompt Gate 检查

Prompt Gate 不只检查禁忌词和重复，还要检查：

```text
prompt 是否体现主标签。
prompt 是否体现候选方向描述。
prompt 是否避开风险标签。
prompt 是否没有把中文标签错误翻译成英文画面文字。
prompt 是否没有丢掉核心视觉符号。
```

如果候选方向主标签是：

```text
中文标语  冰封墙面  幸存者  红色警示  生存危机
```

Prompt Gate 应检查 prompt 是否真的写出了：

```text
冰封墙面
醒目的中文警示标语
幸存者或人类尺度
红色警示元素
危机感
```

## 15. 分阶段开发建议

### 阶段 A：先改页面表达

目标：让页面先像参考截图，而不是继续露出旧 DNA 字段。

任务：

- 用户可见“视觉 DNA”统一改为“方向标签”。
- 创意拓展候选卡片只显示短中文标签。
- 候选卡片隐藏 `visualHook / dedupeReason / riskNote / productionAdvice` 字段名。
- 候选审核区从运行详情中提升为独立区块。
- 生图参数移动到默认收起的“投产设置”。
- 底部增加“去知识库整理 / 生成投产任务 / 回填飞书”操作条。

验收：

- 页面不出现“氛围 / 视角 / 事件 / 钩子 / visualHook / visualDna”。
- 候选卡片主标签最多 5 个。
- 标签全部为中文短标签。
- 候选卡片能一眼看出方向重点。

### 阶段 B：方向标签数据层

目标：建立 `direction-tags.json` 和聚合 API。

任务：

- 新增方向标签读写文件。
- 从方向描述、历史入选候选、好图反馈、方向草案聚合标签。
- 对英文和长句做清洗。
- 风险标签单独拆出。
- 知识库和创意拓展共用同一套标签转换函数。

验收：

- 方向卡片和候选卡片都能读取同一套标签。
- 没有标签时能从旧字段回退生成。
- 标签质量规则可测试。

### 阶段 C：候选审核体验

目标：让人工审核真正可用。

任务：

- 候选卡片支持采纳 / 编辑 / 删除 / 入成长层 / 直接生成 prompt。
- 编辑面板支持方向名、描述、主标签、扩展标签、风险标签。
- 采纳后的候选进入 prompt 生成。
- 删除候选不会进入 prompt。
- 入成长层写入草案。

验收：

- 人工审核模式下任务停在候选区。
- 用户编辑标签后，生成 prompt 使用编辑后的标签。
- 直接生成 prompt 能跳过生图，只产出提示词。

### 阶段 D：Agent 标签组合

目标：方向标签真正影响拓展质量。

任务：

- Agent 指令注入高表现标签、缺口标签、避坑标签、重复组合。
- 增加稳定拓展 / 探索拓展策略。
- Direction Plan Gate 加入标签完整度、组合新颖度、高表现匹配、风险惩罚。
- Prompt Gate 检查 prompt 是否体现主标签。

验收：

- 稳定拓展更像高表现方向的安全变体。
- 探索拓展能补缺口，不只是随机换词。
- Prompt Gate 能拦截“候选方向很好但 prompt 没写出来”的情况。

### 阶段 E：参考图 AI 视觉识别

目标：方向标签不只靠文本，而是能读参考图。

任务：

- 新增“分析方向标签 / 重新分析参考图 / 批量补齐标签”。
- 使用 Lumos Winky vision 读取参考图。
- 输出主标签、扩展标签、风险标签、摘要、置信度。
- 分析结果进入 `direction-tags.json`。
- 参考图不足时标记，允许用户后续手动补图。

验收：

- 有参考图的方向能生成更准确的画面标签。
- 0 图、1-2 图、3+ 图状态清晰。
- 用户可以手动覆盖 AI 标签。

## 18. 复查当前项目后的优化补充

本节是对当前真实代码和数据文件复查后的补充。结论是：项目已经实现了不少“视觉 DNA”相关能力，但还没有形成“方向标签”这一层统一产品语言。后续开发不应该推翻已有能力，而应该做一层清晰的兼容迁移。

### 18.1 当前真实数据基线

复查 `data/creative-knowledge` 后的当前基线：

```text
正式方向：139 个
方向内已有 visualDna：0 个
方向内已有 mainTags / riskTags：0 个
方向草案：5 个
草案内已有 visualDna：0 个
参考图：425 张
0 张参考图的方向：0 个
1-2 张参考图的方向：0 个
3+ 张参考图的方向：139 个
反馈记录：9 条
good / normal / accepted / adopted 反馈：7 条
方向拓展历史：398 条
运行记录：683 条
带 directionPlanReport 的运行：444 条
历史入选候选方向：2083 个
历史候选里带 visualHook / dimensions / visualDna 线索：2081 个
历史候选里已有 directionTags / mainTags：0 个

```

这说明当前项目有一个很大的优势：参考图其实已经非常充足，所有 139 个正式方向都有 3 张以上参考图；真正缺的不是素材，而是“参考图视觉识别 -> 短中文标签 -> Agent 可组合标签”的数据层。

所以原方案里的“参考图 AI 视觉识别”不应放得太后。建议改成两步：

```text
阶段 B1：先用历史 visualHook / dimensions / 描述做临时标签聚合。
阶段 B2：立刻接入参考图视觉识别，对 139 个方向批量生成方向标签。
```

也就是说，方向标签数据层和参考图识别应该连在一起做，而不是等页面全部改完后才做。

### 18.3 需要修正的方案重点

#### 优化 1：新增“兼容迁移层”，不要直接删旧字段

当前 Agent 合约和 Gate 仍强依赖：

```text
visualHook
dimensions.mood
dimensions.perspective
dimensions.narrative
dimensions.hook
dedupeReason
riskNote
productionAdvice
visualDna
```

如果直接让 Agent 只输出 `mainTags / extraTags / riskTags`，会影响现有解析器、Direction Plan Gate、Prompt Gate 和历史测试。

建议迁移期使用双结构：

```json
{
  "name": "雪夜信号塔求救",
  "description": "幸存者在暴风雪废墟中发现仍在闪烁的信号塔，尝试发出求救信号。",
  "mainTags": ["雪夜废墟", "信号塔", "求救信号", "暴风雪", "远景压迫"],
  "extraTags": ["巨型地标", "蓝冷光"],
  "riskTags": ["主体过小"],

  "visualHook": "暴风雪废墟中的信号塔仍在闪烁求救光",
  "dimensions": {
    "mood": "紧张危机",
    "perspective": "远景压迫",
    "narrative": "求救",
    "hook": "信号塔求救光"
  },
  "dedupeReason": "与已有废墟地标方向相似，但核心动作从发现改为求救。",
  "riskNote": "避免主体过小和信号塔被风雪遮挡。",
  "productionAdvice": "突出信号塔光源、幸存者尺度和暴风雪环境。"
}
```

页面只显示 `mainTags / extraTags / riskTags` 和转译后的“值得保留 / 注意 / 投产建议”，内部继续保留旧字段给 Gate 用。等标签 Gate 稳定后，再逐步减少旧字段依赖。

#### 优化 2：先做 display adapter，马上解决页面难看问题

当前创意拓展页仍有这些可见问题：

```text
方向候选回看卡片直接显示 visualHook / dedupeReason / riskNote / productionAdvice。
人工审核卡片仍显示 氛围 / 视角 / 事件 / 视觉钩子。
空标签显示 DNA 待补。
审核区文案写“编辑 DNA 后再进入 prompt 阶段”。
知识库仍显示 DNA 覆盖、维护记录 / 视觉 DNA、生成 DNA 规则草案。
```

第一步建议不要等后端 schema 全部完成，先加前端适配函数：

```text
candidateToDirectionTags(candidate)
visualDnaToDirectionTags(visualDna, dimensions, visualHook)
normalizeDirectionTagText(value)
splitRiskTags(value)
renderDirectionTagPills(tags)
```

这样可以先把页面从“旧字段展示”改成“短中文标签展示”，马上贴近参考截图。

#### 优化 3：方向标签不是分类字段的换名

旧方案容易让开发误解成：

```text
氛围 -> 一个标签
视角 -> 一个标签
事件 -> 一个标签
钩子 -> 一个标签
```

但用户现在明确不要看到这种分类。更准确的模型应该是：

```text
mainTags：用户看到的 3-5 个画面重点
extraTags：详情里辅助判断的补充标签
riskTags：风险标签，单独展示
internalFacets：内部分类，只做颜色、打分、组合逻辑，不直接展示
```

推荐结构：

```json
{
  "mainTags": ["冰封墙面", "中文标语", "幸存者", "红色警示", "生存危机"],
  "extraTags": ["手电照明", "蓝冷光", "近景人物"],
  "riskTags": ["文字过多", "英文文字"],
  "internalFacets": {
    "subject": ["幸存者"],
    "scene": ["冰封墙面"],
    "action": ["生存选择"],
    "composition": ["近景人物"],
    "symbol": ["中文标语", "红色警示"]
  }
}
```

页面显示 `mainTags`，颜色从 `internalFacets` 映射，但不显示 `subject / scene / action / composition / symbol`。

#### 优化 4：参考图识别要成为数据层主路径

当前 `POST /api/creative-knowledge/references/:referenceId/analyze-dna` 存在，但它只是把 `visualNotes` 等手动 payload 写到参考图上，没有真正读取本地图片并调用 Winky vision。

建议升级为：

```text
POST /api/creative-knowledge/references/:referenceId/analyze-tags
POST /api/creative-knowledge/directions/:directionId/tags/analyze
POST /api/creative-knowledge/direction-tags/analyze-batch
```

其中：

```text
references/:referenceId/analyze-tags
  分析单张参考图，输出 imageTags / riskTags / visualSummary。

directions/:directionId/tags/analyze
  汇总该方向 3 张参考图 + 方向描述，输出方向级 mainTags / extraTags / riskTags。

direction-tags/analyze-batch
  批量补齐没有方向标签或标签置信度低的方向。
```

调用方式必须使用 Lumos Winky 的 OpenAI-compatible chat completions，图片使用 `image_url`。可以复用 `scripts/rename-images-with-winky-vision.js` 中已有的 Winky vision 调用模式。

#### 优化 5：方向标签质量需要硬校验器

当前页面问题之一是标签长短不一、英文混入、抽象词混入。只靠 prompt 约束不够，必须有服务端校验器。

建议新增：

```text
normalizeDirectionTags(raw)
validateDirectionTags(tags)
mergeDirectionTagAliases(tags)
scoreDirectionTagQuality(tags)
```

校验规则：

```text
主标签 3-5 个。
扩展标签最多 5 个。
风险标签最多 5 个。
主标签必须中文为主。
主标签推荐 2-6 字，最多 8 字。
禁止英文内部字段。
禁止“氛围 / 视角 / 事件 / 钩子 / DNA”等分类词作为标签。
禁止“方向正确 / 主体明确 / 一眼吸引人”这类评价句作为标签。
风险类词进入 riskTags，不进入 mainTags。
重复近义词合并，比如 鸟瞰 / 俯瞰 / 高空视角。
```

验收可以加脚本：

```text
scripts/test-direction-tags-normalizer.js
```

#### 优化 6：Prompt Gate 需要从 warning 升级为分级拦截

当前 Prompt Gate 对 DNA 落地主要是 warning：

```text
dnaLandingWarningCount
warnings[]
```

这适合早期，但如果要真正减少“方向很好，prompt 没写出来”，应该分级：

```text
低风险：只 warning，例如缺一个扩展标签。
中风险：降分，例如 5 个主标签只体现 2 个。
高风险：拒绝，例如完全没体现核心标签，或命中风险标签。
```

建议 Prompt Gate 新增：

```text
tagLandingScore
missingMainTags
riskTagHits
tagLandingStatus: pass / warn / reject
```

最小规则：

```text
主标签 >= 5 个时，prompt 至少体现 3 个。
主标签 3-4 个时，prompt 至少体现 2 个。
命中 riskTags 中的硬风险，直接 reject。
```

#### 优化 7：稳定 / 探索不只是 UI 选项，要改变打分权重

当前代码已有 `diversityMode = stable / balanced / explore`，但用户可见层应该简化为稳定拓展和探索拓展。内部可以继续保留 `balanced`，但打分权重要更明确：

```text
稳定拓展
  高表现标签匹配权重更高。
  历史组合重复惩罚较低，但方向名重复仍严惩。
  缺口标签加分较少。
  适合跑量。

探索拓展
  缺口标签加分更高。
  历史组合重复惩罚更高。
  高表现标签至少保留 1-2 个，防止跑飞。
  适合找新方向。
```

对应 Direction Plan Gate 可以从 `diversityPenaltyMultiplier()` 扩展为：

```text
tagStrategyWeights(strategy)
```

#### 优化 8：知识库 API 可以先做别名，不必立刻删旧 visual-dna 路由

当前已有：

```text
GET  /api/creative-knowledge/visual-dna/overview
GET  /api/creative-knowledge/visual-dna/workbench
POST /api/creative-knowledge/visual-dna/rule-drafts
GET  /api/creative-knowledge/directions/:directionId/visual-dna
```

建议新增方向标签 API，但先复用旧聚合逻辑：

```text
GET  /api/creative-knowledge/direction-tags/overview
GET  /api/creative-knowledge/direction-tags/workbench
POST /api/creative-knowledge/direction-tags/rule-drafts
GET  /api/creative-knowledge/directions/:directionId/tags
POST /api/creative-knowledge/directions/:directionId/tags
```

旧路由保留，避免历史页面和测试断掉；新页面只调用新路由。

#### 优化 9：历史数据迁移要有一次性回填脚本

因为历史运行里已有 2083 个入选候选，其中 2081 个有可用 visualHook / dimensions 线索，建议新增一次性脚本：

```text
scripts/backfill-direction-tags.js
```

脚本目标：

```text
读取 directions.json
读取 reference-images.json
读取 direction-expansion-history.json
读取 runs/*.json selectedExtensions
读取 feedback.json
生成 direction-tags.json
输出覆盖率报告
```

输出示例：

```text

```

第一版可以先不调用 Winky，只做离线回填；第二版加 `--vision` 参数调用 Winky。

#### 优化 10：测试计划需要加入“禁止旧词露出”的自动检查

真实验收除了截图，还应该加 DOM 文案检查：


可以新增：



### 18.4 调整后的推荐开发顺序

结合当前代码和数据，推荐把开发顺序改成：

```text
A0 旧词止血
  把页面上可见 DNA / 氛围 / 视角 / 事件 / 钩子 / visualHook 等先隐藏或转译。

A1 候选卡片方向标签化
  前端用 adapter 把现有 visualHook / dimensions 转成短中文标签，先解决观感和可读性。

B1 离线方向标签回填
  新增 direction-tags.json，用历史运行和方向描述生成第一版标签。

B2 参考图 Winky 视觉识别
  因为 139 个方向都有 3+ 参考图，尽早批量分析，生成更准确标签。

C 知识库方向标签 API 和页面
  新 API 先复用旧聚合逻辑，再逐步切到 direction-tags.json。

D Agent 双合约输出
  同时输出 mainTags / riskTags 和旧 visualHook / dimensions，保证 Gate 不断。

E Direction Plan Gate 标签权重
  在已有 DNA 打分上叠加标签质量、标签组合、策略权重。

F Prompt Gate 标签落地拦截
  从 warning 升级到 pass / warn / reject。

G 真实页面和回归测试
  DOM 禁词检查、Playwright 截图、creative-auto 和 knowledge 测试。
```

这个顺序比原方案更贴近当前项目，因为它先解决用户肉眼看到的问题，同时又不破坏现有 Agent / Gate / 历史运行链路。

## 19. Web 页面排版与 UI 高标准补充

本节用于约束后续真实开发时的页面观感。参考项目只用于学习“候选方向审核流程、短中文标签、维护记录组织方式”，不能照搬它的主题、边距、卡片密度和颜色。新页面必须继续像当前平台的一部分，而不是突然变成另一个产品。

### 19.1 总体 UI 定位

页面气质应保持为：

```text
深色生产工具
信息密度高
决策路径清楚
操作按钮克制
标签短而可扫
状态明确
```

不建议变成：

```text
营销落地页
大标题 hero
大面积装饰渐变
漂浮卡片堆叠
说明文字过多
每张卡高度失控
```

这套功能的用户不是来“欣赏页面”的，而是来判断方向、筛候选、生成投产任务。因此 UI 的首要目标是让用户少读长文、多看标签、快速做决定。

### 19.2 必须复用当前平台风格锚点

开发时应优先复用现有 CSS token 和组件语义，不要为方向标签工作台单独开一套视觉系统。

当前可作为风格锚点的类名包括：

```text
product-workbench
product-page-heading
product-task-surface
mass-primary-surface
mass-legil-panel
creative-s3-section
creative-target-queue-panel
creative-direction-review-workbench
knowledge-map-card
knowledge-visual-dna-card
```

当前可复用的变量包括：

```text
--product-bg
--product-panel
--product-panel-raised
--product-border
--product-text
--product-muted
--product-accent

--mass-panel
--mass-border
--mass-text
--mass-muted
--mass-accent
--mass-blue
```

建议处理方式：

- 新增方向标签样式时，优先基于 `product-*` 和 `mass-*` 变量扩展。
- 候选审核区继续跟随 `creative-*` 现有结构，不单独做浅色卡片。
- 知识库方向标签区继续跟随 `knowledge-*` 现有结构，不做独立主题。
- 如果需要新增类名，建议使用 `direction-tags-*` 或 `creative-direction-tags-*` 前缀，避免语义再次绑定到 DNA。

### 19.3 页面层级与首屏重点

创意拓展页第一屏应该围绕“本轮要拓展什么方向、用什么策略、候选是否需要审核”组织，而不是先展示一堆生图参数。

推荐首屏信息层级：

```text
页面标题与任务状态
  创意拓展
  当前状态：待启动 / 生成候选中 / 等待审核 / 生成 prompt 中 / 生图中

目标与策略
  本轮目标方向
  当前方向标签
  稳定拓展 / 探索拓展
  自动通过 / 人工审核

候选方向审核
  候选数量
  已采纳数量
  风险数量
  候选卡片列表

投产设置
  默认折叠
  只在生成 prompt 或配置异常时展开
```

投产设置、输出目录、分辨率、比例、生成数量等参数应该放在“投产设置”折叠面板里。它们很重要，但不是方向决策的第一关注点。

### 19.4 布局规格

桌面端建议：

```text
1440px 宽度
  顶部：页面标题 + 状态 + 主要操作
  中部：目标与策略横向排列
  下部：候选审核卡片两列或三列

1920px 宽度
  页面主体最大宽度受控
  候选卡片最多三列
  不要无限拉长单行文本
```

平板端建议：

```text
两列布局
目标与策略在上
候选审核在下
操作栏保持可见但不遮挡内容
```

移动端建议：

```text
单列布局
候选卡片满宽
主要操作按钮满宽或双按钮一行
底部操作栏只在审核阶段出现
底部操作栏必须给内容区预留 padding-bottom
```

明确禁止：

- 卡片里面再套大卡片。
- 页面 section 做成多层浮动卡片。
- 文本横向溢出。
- 标签把卡片撑爆。
- 底部固定操作栏遮住最后一张候选卡。
- 宽屏下候选卡被拉成过长的横条。

### 19.5 候选方向卡片排版

候选卡片是本次改版最重要的 UI 单元，必须从“日志详情”改成“可审核方向单元”。

推荐结构：

```text
标题行
  方向名                         分数 / 状态

标签行
  短中文主标签，最多 5 个

描述
  方向描述，最多 2 行

判断区
  值得保留：最多 2 行
  注意：最多 2 行

操作区
  采纳  编辑  删除  入成长层  直接生成 prompt
```

视觉规则：

- 卡片圆角控制在 8px 左右，跟现有平台一致。
- 卡片内边距建议 14px 到 16px。
- 卡片之间间距建议 12px 到 16px。
- 标题最多两行，超出截断或进入 tooltip。
- 描述最多两行，避免大段正文占满卡片。
- “值得保留”和“注意”只显示摘要，详细内容放到展开详情或编辑面板。
- 操作按钮不使用大面积高亮，只有主操作“采纳”或“生成 prompt”使用强调色。
- 删除、风险、入成长层这类动作要视觉弱化，但可识别。

候选卡片不再直接显示这些字段名：

```text
visualHook
dedupeReason
riskNote
productionAdvice
氛围
视角
事件
钩子
视觉 DNA
```

它们只能作为内部数据来源，被转译成短标签、保留理由、风险提示和投产建议。

### 19.6 方向标签 pill 规范

方向标签必须像参考截图里的“小标签”，而不是长短不一的解释句。

标签显示规则：

```text
主标签：最多 5 个
扩展标签：详情里最多 5 个
风险标签：单独一行，最多 5 个
单个标签推荐 2-6 字
单个标签最多 8 字
全部使用中文
不显示分类名
```

好的标签示例：

```text
中文标语
冰封墙面
幸存者
红色警示
暴风雪
求救信号
巨型地标
近景手电
低机位
断桥逃生
```

不应出现在页面上的标签：

```text
macro prop with human stakes
visualHook
productionAdvice
氛围紧张危机
视角第一人称
事件撤离
一眼能吸引人
主体明确
方向正确
```

颜色规则：

- 页面不显示分类名，但标签可以根据内部分类映射颜色。
- 颜色只能做轻量区分，不要做成彩虹糖。
- 主标签使用低饱和底色加浅色描边。
- 风险标签使用更克制的警示色，不和主标签混在一起。
- 低置信标签可用虚线边框或弱透明度表达。

溢出规则：

- 一张候选卡最多展示 5 个主标签。
- 超出部分显示 `+N`，hover 或点击后展示全部。
- 长标签要截断，tooltip 显示完整内容。
- 标签容器高度要稳定，不因为标签数量变化导致整张卡片跳动过大。

### 19.7 知识库方向标签页面排版

知识库页面应保持“管理型工具”的布局，不要做成展示型画廊。

推荐页签：

```text
总览
标签地图
成长整理
维护记录 / 方向标签
```

如果继续保留原“维护记录”概念，用户可见命名建议是：

```text
维护记录 / 方向标签
```

不再使用：

```text
维护记录 / 视觉 DNA
```

方向库列表里的方向卡片建议结构：

```text
方向路径
方向描述，最多 2 行
方向标签：短中文 pill，最多 5 个
参考图：3 / 3
状态：可用 / 待补图 / 低置信 / 待复核
```

知识库总览里的覆盖指标也要改名：

```text
方向标签覆盖：已分析方向数 / 总方向数
高频标签：中文标语、冰封墙面、幸存者、巨型地标
待补标签方向：N 个
待复核方向：N 个
缺参考图方向：N 个
```

不再展示：

```text
DNA 覆盖
高频氛围
高频视角
缺事件方向
缺视觉钩子方向
```

### 19.8 工作台两列区的 UX

“维护记录 / 方向标签”工作台可以继续保留两列，但文案和信息组织要换成用户容易理解的表达。

推荐结构：

```text
左侧：采纳模式
  父方向
  已采纳方向数量
  好图方向样本
  每个样本显示 3-5 个方向标签

右侧：标签偏好
  父方向
  高频标签
  高风险标签
  缺口标签
  可生成规则草案
```

示例：

```text
城市废墟 4
  黎明废墟俯瞰
    史诗废墟  黎明逆光  俯瞰城市  巨型地标  初次发现

  暴雪废墟探路
    暴风雪  第一人称  手电照明  巨型地标  探路
```

右侧统计不要写成：

```text
氛围：史诗壮阔(2)
视角：俯瞰(2)
事件：撤离(2)
```

而应该写成：

```text
高频标签：巨型地标(5)、暴风雪(3)、俯瞰城市(3)
高采纳组合：巨型地标 + 初次发现、暴风雪 + 第一人称
风险标签：英文文字、主体过小、文字过多
缺口标签：近景物件、低机位、暖光路标
```

内部仍然可以按 subject / scene / action / composition / symbol 等 facet 统计，只是页面不要露出这些分类名。

### 19.9 状态设计

为了照顾真实使用体验，以下状态必须有清晰 UI，不要只留空白或报错文本。

候选审核区状态：

```text
未生成候选
生成候选中
等待人工审核
已采纳
已删除
已入成长层
已直接生成 prompt
低置信
高风险
```

方向标签状态：

```text
标签已分析
待分析
分析中
分析失败
低置信待复核
参考图不足
使用历史数据回填
使用 Winky 视觉分析
```

空状态文案要短，重点告诉用户下一步动作。例如：

```text
还没有候选方向。选择目标方向后生成候选。
这个方向还没有标签。可先用历史数据回填，再用参考图复核。
参考图不足，方向仍可拓展，后续需要手动补图。
```

### 19.10 编辑面板 UX

候选方向编辑不是表单堆字段，而是“改方向重点”。

推荐编辑项：

```text
方向名
方向描述
主标签
扩展标签
风险标签
避坑说明
```

交互规则：

- 标签输入使用 chip editor，不用纯 textarea。
- 回车新增标签。
- 标签超长时即时提示。
- 输入英文时提示“建议改成短中文标签”。
- 删除标签需要一键可撤销，避免误删。
- 编辑保存后候选卡片立即刷新。
- Prompt 生成必须读取编辑后的标签，而不是旧字段。

不建议让用户编辑：

```text
internalFacets
visualDna
dimensions
visualHook
```

这些属于内部兼容层，用户不应该被迫理解。

### 19.11 操作优先级

候选卡上的按钮不能全部同等重量。建议分成三级：

```text
一级操作：采纳
二级操作：编辑、直接生成 prompt
三级操作：删除、入成长层、复制
```

人工审核阶段的底部操作栏：

```text
已采纳 3 / 候选 8
[全选可用] [生成投产任务]
[去知识库整理] [回填飞书]
```

按钮规则：

- “生成投产任务”在没有采纳项时禁用。
- “回填飞书”在没有已采纳且完整的方向时禁用。
- “全选可用”只选择低风险候选。
- 高风险候选要允许采纳，但需要二次确认或明显提示。

### 19.12 文案规范

页面文案要短、生产化、可判断。

推荐：

```text
方向标签
标签覆盖
高频标签
缺口标签
风险标签
采纳模式
标签偏好
待复核
低置信
可投产
待补图
```

避免：

```text
视觉 DNA
氛围
视角
事件
钩子
神经网络式分析
高级智能语义拆解
自动化灵感宇宙
```

按钮文案建议：

```text
生成候选
采纳
编辑
删除
入成长层
生成 prompt
生成投产任务
分析标签
批量复核
```

不要在页面内写大段“使用说明”。如果确实需要解释，放在 tooltip 或空状态里。

### 19.13 响应式与可访问性

必须检查以下问题：

- 390px 移动端无横向滚动。
- 1440px 桌面端候选卡片不会过宽。
- 1920px 宽屏内容有最大宽度，不飘散。
- 所有按钮文字不会溢出。
- 长方向名不会撑破标题行。
- 标签不会挤压操作按钮。
- 底部固定栏不会遮挡内容。
- 键盘 tab 顺序符合审核流程。
- 禁用按钮有明确 disabled 样式。
- 风险状态不只依赖颜色，也要有文字或图标提示。

### 19.14 视觉回归测试要求

真实开发完成后，必须用 Playwright 做页面截图验证，而不只是跑接口。

建议截图场景：

```text
创意拓展页 - 未启动
创意拓展页 - 生成候选中
创意拓展页 - 等待人工审核
创意拓展页 - 候选卡片两列桌面
创意拓展页 - 候选卡片移动端
创意拓展页 - 编辑候选弹窗
知识库 - 方向标签总览
知识库 - 标签地图
知识库 - 维护记录 / 方向标签
```


### 19.16 开发落地优先级修正

结合 UI 高要求，开发顺序建议进一步调整为：

```text
U0 风格对齐
  先复用现有 product / mass / creative / knowledge 样式变量，确定页面骨架。

U1 旧词止血
  把用户可见 DNA、氛围、视角、事件、钩子、visualHook 等转译或隐藏。

U2 标签 pill 组件
  做统一的 direction tag pill 渲染、截断、+N、tooltip、风险态。

U3 候选卡片重排
  固定标题、标签、描述、判断、操作五段结构。

U4 知识库卡片重排
  方向库、标签地图、维护记录统一使用方向标签表达。

U5 真实截图验收
  桌面、平板、移动端循环测试，修到排版稳定。

U6 再接 Winky 视觉识别和 Agent 标签组合
  在 UI 已经干净可用后，补齐更准确的数据来源。
```

也就是说，视觉和排版问题不能等数据层完全做完才处理。先把页面语言、卡片结构和标签组件修好，用户马上能感受到质量提升；再让 Winky 视觉识别和 Agent 标签组合逐步提高准确性。
