# 创意拓展图片命名标准化分阶段开发方案

日期：2026-06-02

## 1. 背景与目标

当前创意拓展、素材分析转创意拓展、普通批量产图等链路生成图片后，文件名主要依赖运行序号、参考图名、prompt 标题等信息。随着素材量增加，后期维护时很难仅通过文件名判断图片属于哪个标准方向、是基于哪个标签体系产出的、当前新图的具体内容是什么。

本次需求目标是建立统一的图片命名规则：

- 文件名前半部分使用方向库中的标准一级、二级、三级标签。
- 文件名最后一段使用本轮新生成或本次输入的新内容标题。
- 原素材名、原图名中的历史细分内容只作为识别线索，不直接继承到新文件名中。
- 三级以下方向只保留到标准三级标签，再追加新内容标题。
- 默认短命名，不把 prompt 标题写入文件名，但资产记录中需要保留 prompt 标题。
- 素材分析转创意拓展、普通批量产图如果能识别到标签，也要走同一套命名规则。

最终希望文件名天然具备维护价值：

```text
run编号_全局序号_标准一级标签_标准二级标签_标准三级标签_新内容标题_v图片序号_时间戳.png
```

示例：

```text
creative_20260602_153012_0001_题材_探索发现_避难所_雪原信号塔救援_v01_20260602_153245.png
```

## 2. 最终命名规则

### 2.1 核心规则

新图命名中的一级、二级、三级标签必须优先来自方向库标准标签，而不是直接继承素材名或原图名中的旧内容。

素材名、原图名、文件夹名只作为标签识别线索：

- 能匹配到方向库的层级才保留。
- 不能匹配的最后一段视为旧内容标题，不进入新文件名。
- 新文件名最后一段统一替换为本次的新内容标题。

最终业务核心名：

```text
标准标签路径_新内容标题
```

### 2.2 各层级规则

| 输入方向或原始素材可确认层级 | 文件名业务核心名 |
| --- | --- |
| 只确认一级 | `一级标签_新内容标题` |
| 确认到二级 | `一级标签_二级标签_新内容标题` |
| 确认到三级 | `一级标签_二级标签_三级标签_新内容标题` |
| 三级以下方向 | `一级标签_二级标签_三级标签_新内容标题` |
| 完全无法确认标签 | `新内容标题` 或保持旧命名逻辑 |

### 2.3 文件名格式

推荐完整文件名格式：

```text
{runId}_{sequence}_{outputNameBase}_v{variant}_{timestamp}.png
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `runId` | 本次运行批次编号 |
| `sequence` | 全局输出序号，保证排序和防重名 |
| `outputNameBase` | 标准标签路径 + 新内容标题 |
| `variant` | 同一 prompt 多图输出序号，如 `v01`、`v02` |
| `timestamp` | 保存时间戳，进一步防重名 |

示例：

```text
creative_20260602_153012_0001_题材_探索发现_避难所_雪原信号塔救援_v01_20260602_153245.png
creative_20260602_153012_0002_题材_探索发现_避难所_雪原信号塔救援_v02_20260602_153245.png
```

## 4. 标准标签识别策略

### 4.1 识别优先级

系统生成 `standardLabelPath` 时，按以下顺序查找：

1. prompt 或任务中已有的结构化标准标签：
   - `primaryTag`
   - `secondaryTag`
   - `tertiaryTag`
   - `standardLabelPath`
2. `sourceDirectionId` 对应的方向库标准路径。
3. `sourceDirectionPath` 对应的方向库标准路径。
4. 从素材名、原图名、文件夹路径中提取候选词，与方向库做最长路径匹配。
5. 在同一个一级、二级范围内做保守的包含匹配或别名匹配。
6. 如果仍无法确认，则降级到已确认层级或旧命名逻辑，不强行猜三级标签。

### 4.2 文件名解析原则

素材名或原图名中可能包含投放编号、渠道、尺寸、旧内容标题。解析时需要清理：

- 投放编号：如 `GOFCNIM6724`
- 渠道或地区短码：如 `DR`、`CN`、`BJ`
- 尺寸：如 `800x800`、`1280x720`、`1080x1920`
- 文件扩展名：如 `.png`、`.jpg`
- 明显的旧尾缀：如 `拓展`、`形象拓展`、`变体`，只作为辅助匹配，不直接进入新文件名

### 4.3 匹配原则

方向库匹配应优先精确，谨慎模糊：

- 已有标准路径完全匹配时，置信度为 `high`。
- 在同一一级、二级下，旧内容包含标准三级标签时，置信度为 `medium`。
- 只能确认一级或二级时，置信度为 `medium` 或 `low`。
- 无法确认标签时，置信度为 `missing`。

禁止跨一级、二级随意模糊匹配，避免误判。

## 5. 新内容标题规则

文件名最后一段统一称为：

```text
contentTitle
```

不同链路来源不同：

| 链路 | `contentTitle` 来源 |
| --- | --- |
| 自动创意拓展 | `newDirectionName` |
| 素材分析转创意拓展 | AI 生成的新方向名 `newDirectionName` |
| 普通批量产图 | prompt item 标题、用户输入标题、表格标题或从 prompt 提取的短标题 |
| 无标题批量产图 | 可用原图旧内容标题兜底，但优先使用本次标题 |

默认不把 `promptTitle` 放进文件名。

但 `contentTitle` 必须能大致识别图片内容，禁止过于泛化：

不推荐：

```text
新方向1
探索发现拓展
避难所变体
高点击方向
优化版
```

推荐：

```text
冰封地铁站避难
雪原信号塔救援
地下补给仓发现
废弃观测站求生
破冰进入避难所
```

## 6. 数据结构设计

每条 prompt、每张生成图、每条资产记录都尽量保留以下字段。

```js
{
  primaryTag: '题材',
  secondaryTag: '探索发现',
  tertiaryTag: '避难所',
  standardLabelPath: ['题材', '探索发现', '避难所'],

  sourceDirectionId: '',
  sourceDirectionPath: '题材 / 探索发现 / 避难所形象拓展',
  sourceRawName: 'GOFCNIM6724_DR_题材_探索发现_避难所形象拓展_800x800',
  sourceParsedParts: ['题材', '探索发现', '避难所形象拓展'],
  sourceContentTitle: '避难所形象拓展',

  newDirectionName: '雪原信号塔救援',
  promptTitle: '主角点亮信号塔',
  contentTitle: '雪原信号塔救援',

  outputNameBase: '题材_探索发现_避难所_雪原信号塔救援',

  namingSource: 'direction-library-fuzzy',
  tagConfidence: 'medium'
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `standardLabelPath` | 方向库标准标签路径，最多保留三级 |
| `sourceRawName` | 原素材名、原图名或原始来源名称 |
| `sourceParsedParts` | 从原始名称里解析出的候选片段 |
| `sourceContentTitle` | 原图或旧素材中的旧内容标题 |
| `contentTitle` | 本次新内容标题，最终进入文件名 |
| `outputNameBase` | 最终文件名中的业务核心名 |
| `namingSource` | 标签来源 |
| `tagConfidence` | 标签识别置信度 |

`namingSource` 推荐枚举：

```text
prompt-meta
direction-library-id
direction-library-path
direction-library-exact
direction-library-fuzzy
material-analysis-levels
material-name
reference-file-name
reference-folder
asset-store
legacy
none
```

`tagConfidence` 推荐枚举：

```text
high
medium
low
missing
```

## 7. 分阶段开发方案

## 阶段 0：基线确认与测试样例锁定

### 目标

明确当前保存文件名的生成链路，锁定新规则验收样例，避免开发后无法判断效果。

### 主要工作

- 确认创意拓展保存图片文件名来自 `/api/legil/creative-batch` 传入 Legil 的命名字段。
- 确认 Legil 最终文件名由 `buildOutputFileName()` 生成。
- 梳理自动创意、素材分析转创意拓展、普通批量产图三条入口当前传递的数据字段。
- 准备命名验收样例和方向库模拟数据。

### 验收标准

- 明确旧文件名格式。
- 明确每个入口当前能拿到哪些字段。
- 明确以下样例的预期输出：
  - 创意拓展一级标签
  - 创意拓展二级标签
  - 创意拓展三级标签
  - 创意拓展三级以下方向
  - 素材分析转创意拓展
  - 普通批量产图有标签原图
  - 普通批量产图无标签原图

## 阶段 1：统一命名服务与方向库标签解析

### 目标

新增统一命名服务，集中处理方向库标准标签解析、旧内容标题识别、新内容标题拼接、文件名清洗。

### 建议新增文件

```text
src/services/output-naming/creative-output-naming.js
```

### 核心函数

```js
resolveStandardLabelPath({
  sourceDirectionId,
  sourceDirectionPath,
  sourceLabelPath,
  sourceRawName,
  referenceFolderPath,
  directionLibrary,
  maxLevel
})

buildOutputNameBase({
  standardLabelPath,
  contentTitle,
  fallbackName
})

sanitizeFileNamePart(value, maxLength)

parseLabelCandidatesFromName(name)

buildCreativeOutputNamingContext(input)
```

### 主要工作

- 从结构化字段解析标准标签。
- 从方向库 `direction id` 或 `direction path` 查标准标签。
- 从素材名、原图名、文件夹路径中提取候选标签。
- 与方向库做最长路径匹配。
- 在同一一级、二级下支持保守的模糊匹配。
- 未匹配的最后一段标记为 `sourceContentTitle`，不进入新文件名。
- 生成 `outputNameBase`。
- 清理 Windows 非法字符并控制长度。

### 验收标准

输入：

```text
sourceRawName = GOFCNIM6724_DR_题材_探索发现_避难所形象拓展_800x800
directionLibrary = 题材 / 探索发现 / 避难所
contentTitle = 雪原信号塔救援
```

输出：

```text
outputNameBase = 题材_探索发现_避难所_雪原信号塔救援
namingSource = direction-library-fuzzy
tagConfidence = medium
```

输入：

```text
sourceRawName = 题材_探索发现_废弃观测站.png
directionLibrary = 题材 / 探索发现
contentTitle = 夜间求生信号
```

输出：

```text
outputNameBase = 题材_探索发现_夜间求生信号
sourceContentTitle = 废弃观测站
```

## 阶段 2：自动创意拓展主链路接入

### 目标

自动创意工作台生成的 prompt 进入 Legil 后，保存图片按新命名规则输出。

### 修改范围

- `src/services/creative-auto/prompt-translator.js`
- `src/services/creative-auto/prompt-gate.js`
- `src/server/context.js`
- `src/routes/legil.routes.js`

### 主要工作

- 在 prompt 翻译和 Prompt Gate 阶段保留命名相关元数据。
- 在 `normalizeCreativeBatchPromptItems()` 中保留：
  - `primaryTag`
  - `secondaryTag`
  - `tertiaryTag`
  - `standardLabelPath`
  - `sourceDirectionId`
  - `sourceDirectionPath`
  - `newDirectionName`
  - `promptTitle`
  - `contentTitle`
  - `outputNameBase`
- 在 `/api/legil/creative-batch` 逐条 prompt 执行前调用统一命名服务。
- 将生成的 `outputNameBase` 传给 Legil 保存逻辑。
- 保持 `promptTitle` 只进入资产记录，不默认进入文件名。

### 关键规则

```text
选中一级方向：一级标签_新内容标题
选中二级方向：一级标签_二级标签_新内容标题
选中三级方向：一级标签_二级标签_三级标签_新内容标题
选中三级以下方向：一级标签_二级标签_三级标签_新内容标题
```

### 验收标准

输入：

```text
选中方向 = 题材 / 探索发现 / 避难所 / 地下入口
newDirectionName = 地下补给仓发现
```

输出文件名包含：

```text
题材_探索发现_避难所_地下补给仓发现
```

并且不包含 prompt 标题。

## 阶段 3：素材分析转创意拓展接入

### 目标

素材分析 Top100、素材逐张拓展等入口转到创意拓展后，能使用方向库标准标签命名，而不是直接继承素材名里的旧内容。

### 修改范围

- `src/services/material-analysis/creative-expansion.js`
- 可能涉及素材分析前端发送创意拓展 payload 的模块

### 主要工作

- 将素材分析里的 `levels.primary / levels.secondary / levels.tertiary` 作为候选标签。
- 将素材名、素材方向、视觉分析建议方向作为辅助识别线索。
- 接入统一命名服务，通过方向库解析标准标签。
- 将 `sourceContentTitle` 与 `contentTitle` 区分保存。
- 每条生成 prompt 都带上：
  - `standardLabelPath`
  - `sourceRawName`
  - `sourceContentTitle`
  - `newDirectionName`
  - `contentTitle`
  - `outputNameBase`
  - `namingSource`
  - `tagConfidence`

### 验收标准

输入：

```text
素材名 = GOFCNIM6724_DR_题材_探索发现_避难所形象拓展_800x800
方向库 = 题材 / 探索发现 / 避难所
newDirectionName = 雪原信号塔救援
```

输出文件名包含：

```text
题材_探索发现_避难所_雪原信号塔救援
```

并且不输出：

```text
题材_探索发现_避难所形象拓展_雪原信号塔救援
```

## 阶段 4：普通批量产图接入

### 目标

普通批量产图如果原图或 prompt item 能识别到方向库标签，也使用标准标签路径 + 本次标题命名。识别不到时保持旧逻辑，不影响现有流程。

### 修改范围

- `src/routes/legil.routes.js`
- `src/services/legil/config-methods.js`
- 可能涉及普通批量产图前端调用模块

### 主要工作

- 支持普通批量产图 prompt item 传递结构化命名元数据。
- 支持从原图文件名解析候选标签。
- 支持从原图所在文件夹解析候选标签。
- 支持从资产库查找原图已有标签。
- 接入统一命名服务，生成 `outputNameBase`。
- 无法识别方向库标签时，走旧命名或只使用本次标题。

### 验收标准

输入：

```text
原图 = 题材_探索发现_废弃观测站.png
方向库 = 题材 / 探索发现
title = 夜间求生信号
```

输出文件名包含：

```text
题材_探索发现_夜间求生信号
```

如果方向库存在：

```text
题材 / 探索发现 / 废弃观测站
```

则输出文件名包含：

```text
题材_探索发现_废弃观测站_夜间求生信号
```

- 三级以下方向截断到三级。
- 素材分析旧内容归一到方向库标准三级。
- 普通批量产图旧内容不误当三级。
- 原图最后一段确实是标准三级时保留。
- Windows 非法字符清洗。
- 文件名长度控制。
- 无标签 fallback。

## 9. 风险与处理策略

### 9.1 标签误判

风险：从素材名中把旧内容标题误判为标准三级标签。

处理：

- 必须通过方向库确认后才作为标准标签。
- 无法确认时只保留到已确认层级。
- 不跨一级、二级做模糊匹配。

### 9.2 文件名过长

风险：历史素材名和新标题过长导致 Windows 路径问题。

处理：

- 单个标签字段限制长度。
- `outputNameBase` 限制总长度。
- 完整文件名控制在合理范围内。

### 9.3 旧流程兼容

风险：普通 Legil 生成、旧批量产图、改尺寸流程被影响。

处理：

- 命名增强只在有命名上下文时启用。
- 无法识别标签时 fallback 到旧逻辑。
- 单测覆盖无标签场景。

### 9.4 停止后继续任务字段丢失

风险：创意拓展暂停后继续，新增命名字段未进入 resume state。

处理：

- `normalizeCreativeBatchPromptItems()` 必须保留所有命名字段。
- resume state 中保存完整 prompt item，而不是只保存 prompt 文本。

### 9.5 中文编码

风险：当前部分文件中文显示存在编码错位，大范围重写可能扩大问题。

处理：

- 开发时只做局部补丁。
- 避免无关格式化。
- 新增模块使用 UTF-8。

## 10. 总体验收清单

开发完成后，至少需要通过以下验收：

1. 创意拓展一级：

```text
题材_新内容标题
```

2. 创意拓展二级：

```text
题材_探索发现_新内容标题
```

3. 创意拓展三级：

```text
题材_探索发现_避难所_新内容标题
```

4. 创意拓展三级以下：

```text
题材_探索发现_避难所_新内容标题
```

5. 素材分析转创意拓展：

```text
素材名：GOFCNIM6724_DR_题材_探索发现_避难所形象拓展_800x800
方向库：题材 / 探索发现 / 避难所
新标题：雪原信号塔救援
输出：题材_探索发现_避难所_雪原信号塔救援
```

6. 普通批量产图旧内容不继承：

```text
原图：题材_探索发现_废弃观测站.png
方向库：题材 / 探索发现
新标题：夜间求生信号
输出：题材_探索发现_夜间求生信号
```

7. 普通批量产图标准三级保留：

```text
原图：题材_探索发现_避难所.png
方向库：题材 / 探索发现 / 避难所
新标题：夜间求生信号
输出：题材_探索发现_避难所_夜间求生信号
```

8. 多图输出不重名：

```text
v01
v02
v03
v04
```

9. 无法匹配方向库时不强行猜三级标签。

10. 资产记录中保存完整标签、旧内容标题、新内容标题、prompt 标题、命名来源和置信度。

## 11. 最终定稿描述

新图命名中的一级、二级、三级标签必须优先来自方向库标准标签，而不是直接继承素材名或原图名中的旧内容。素材名、原图名只作为标签识别线索；能匹配到方向库的层级才保留，不能匹配的最后一段视为旧内容标题并被本次新内容标题替换。最终文件名默认短命名：

```text
run编号_序号_标准标签路径_新内容标题_v序号_时间戳.png
```

这套规则的核心价值是：前面是稳定分类，最后是当前内容。后期维护时，文件名可以同时表达“归属方向”和“本次新图主题”，避免被历史素材名里的旧标题带偏。
