# 创意拓展与知识库页面分析及视觉 DNA 迭代方案

日期：2026-06-26  
范围：`创意拓展产图` 页面、`知识库资产中心` 页面  
目标：分析当前项目现状、优缺点，并吸收参考项目中“方向拆成视觉 DNA、采纳模式、风格偏好、维护记录”的优点，形成可落地的迭代方案。

## 1. 需求复述

本次不是要立即改代码，而是先对当前项目的两个核心页面做产品和系统层面的分析：

- `创意拓展产图` 页面：看它现在如何接收方向、生成候选方向、做 Prompt Gate、调用生图平台、展示运行结果。
- `知识库资产中心` 页面：看它现在如何管理方向、参考图、成长方向草案、资产审核、反馈规则和运行记录。
- 对照参考项目截图，尤其关注它把方向拆成视觉 DNA、从采纳样本里学习风格偏好、在知识库里做维护记录和成长整理的设计。
- 最终输出一份迭代方案，说明当前项目哪些地方已经具备基础，哪些地方还缺一层产品表达和数据模型，以及后续怎么分阶段升级。

一句话总结：当前项目已经有“创意闭环系统”的骨架和很多后端能力，下一步应把散落在运行记录、方向规划、反馈规则里的视觉信息提升为一个可查看、可编辑、可统计、可驱动 Agent 的“视觉 DNA 层”。

## 2. 当前项目的总体判断

当前项目已经不只是简单的 AI 生图自动化工具，而是一个接近“创意资产闭环系统”的本地平台。它已经有几条比较完整的链路：

```text
方向库 / 素材分析 / 方案迭代
    ↓
创意拓展方向队列
    ↓
Direction Plan Gate 生成并筛选候选方向
    ↓
Prompt Gate 生成并质检提示词
    ↓
Legil 生图与保存资产
    ↓
知识库资产审核
    ↓
反馈学习与规则沉淀
    ↓
下一轮 Agent 读取经验继续生成
```

从数据文件看，当前项目已经有这些知识库资产：

- `data/creative-knowledge/directions.json`：方向库，包含标签路径、描述、状态、运行统计、参考图统计。
- `data/creative-knowledge/direction-drafts.json`：从 Agent 或运行记录中提取的新方向草案。
- `data/creative-knowledge/assets.json`：生成图片资产，关联 run、方向、prompt、输出文件。
- `data/creative-knowledge/feedback.json`：人工审核反馈。
- `data/creative-knowledge/creative-memory.json`：反馈学习后的规则草案和已启用规则。
- `data/creative-knowledge/direction-expansion-history.json`：方向拓展历史，已经包含 `visualHook`、`dedupeReason`、`productionAdvice`、`creativeAxes` 等接近视觉 DNA 的字段。
- `data/creative-knowledge/runs/*.json`：每轮自动创意运行记录，包含 `directionPlanReport`、入选方向、被淘汰方向、Prompt Gate 结果和 Legil 进度。

所以当前项目的优势不是“没有基础”，而是基础已经很厚。主要问题是：很多高级信息还藏在运行记录和后台字段里，页面上还没有形成一个像参考项目那样清晰的“视觉 DNA / 采纳模式 / 风格偏好 / 维护记录”工作台。

## 3. 创意拓展页面现状分析

当前 `创意拓展产图` 页面位于 `public/index.html` 的 `creativePage` 区块，主要逻辑在 `public/js/creative-auto.js`，核心后端服务在 `src/services/creative-auto/index.js`。

### 3.1 当前页面的信息架构

当前页面大致分为：

```text
页面标题与任务状态
    ↓
输出目录 / 参考图目录
    ↓
开始、继续、新任务、停止、打开平台
    ↓
生图参数
    ↓
待拓展方向队列
    ↓
运行进度
    ↓
结果审核入口
    ↓
来源详情
    ↓
方向库选择
    ↓
历史任务
```

这说明它当前更偏“产图控制台”而不是“创意策划工作台”。页面重点是把方向送进任务队列，然后跟踪 Agent、Prompt Gate 和 Legil 的运行结果。

### 3.2 当前创意拓展页的优点

#### 优点 1：执行链路完整

当前页面已经能从多个上游来源接收方向：

- 知识库方向库。
- 素材分析 brief。
- 方案迭代任务。
- 手动方向选择。
- 自动推荐方向。

然后统一进入 `待拓展方向队列`，并能设置：

- 每个原始方向拓展多少个新方向。
- 每个新方向生成多少条 prompt。
- 候选倍率。
- 拓展随机度。
- 历史避重范围。

这已经具备参考项目“自动拓展”的基础，而且比截图项目更偏工程化。

#### 优点 2：Direction Plan Gate 已经很强

后端已经不是直接让 LLM 写 prompt，而是先生成候选方向，再经过 Direction Plan Gate 筛选。每个候选方向要求包含：

- `name`：候选方向名。
- `description`：方向描述。
- `visualHook`：视觉钩子。
- `dedupeReason`：排重理由。
- `riskNote`：风险说明。
- `productionAdvice`：制作建议。
- `dimensions`：方向维度。

这已经非常接近“视觉 DNA”模型，只是目前页面没有把它作为主资产展示。

#### 优点 3：有自动修复和质检机制

当前服务里有：

- 方向候选评分。
- 方向候选修复。
- Prompt Gate。
- 失败 prompt 重试。
- agent-only 只生成提示词模式。
- agent 完成后再手动继续 Legil 模式。
- 运行中暂停、恢复。

这说明系统不是简单调用模型，而是有“候选池 - 质检 - 修复 - 继续执行”的生产级链路。

#### 优点 4：方向队列适合批量生产

`待拓展方向队列` 会估算：

```text
原始方向数
候选方向数
入选新方向数
预计提示词数
```

这和参考项目的量产页“预计 116 张、启动前预检”是同类思路。当前项目在批量任务规模感知上已经做得不错。

#### 优点 5：和知识库有明确闭环

页面里有“运行完成后进入知识库资产审核”的入口。生成结果不是停留在当前页，而是进入知识库沉淀。这是创意闭环系统最重要的结构之一。

### 3.3 当前创意拓展页的不足

#### 不足 1：页面重执行，轻方向策划

当前页面标题是“创意拓展产图”，实际第一感知也是“开始产图”。但参考项目的拓展页更强调：

```text
先选目标
再看 Agent 建议
再审核候选方向
再决定是否投产
```

当前页面虽然后端有候选方向，但页面上缺少一个清晰的“候选方向审核区”。用户看到的是运行队列、prompt 和进度，而不是一组可编辑、可比较、可采纳/拒绝的新方向卡片。

#### 不足 2：视觉 DNA 没有显性化

当前后端已生成 `visualHook`、`dedupeReason`、`productionAdvice`、`creativeAxes`，但页面没有把它们拆成类似：

```text
氛围：紧张危机
视角：第一人称
事件：撤离
尺度：巨型地标
视觉钩子：红色信号弹
风险：避免科技屏
```

用户只能看到 prompt、方向名或运行摘要，无法快速判断这个方向的视觉结构。

#### 不足 3：手动方向选择的视觉辅助不够

方向库选择区目前主要是树、搜索、层级选择和方向统计。它能选方向，但没有像参考项目一样提供：

- 当前方向缺什么 DNA。
- 历史上这个方向常用什么视角/氛围。
- 这个方向适合从哪些视觉维度继续扩。
- 当前选中方向与已有历史的相似度。

这会导致用户选方向时主要靠路径和描述，而不是靠视觉策略。

#### 不足 4：候选方向的“为什么入选/为什么淘汰”没有产品化

运行记录中 `directionPlanReport` 已经有：

- 入选候选方向。
- 淘汰候选方向。
- 分数。
- 分数说明。
- 相似度。
- visualHook。
- dedupeReason。
- riskNote。
- productionAdvice。

但页面没有把这些做成一个像参考项目“审核候选方向”的卡片区。这样用户很难参与方向层审核，只能在 prompt 或图片阶段介入。

#### 不足 5：创意拓展页和知识库的角色边界略混

当前创意页既有：

- 方向队列。
- 方向库选择。
- 运行进度。
- prompt 展示。
- 历史任务。
- 结果审核入口。

功能很多，但“策划、生成、审核、沉淀”的层级不够明显。参考项目的优点是入口明确：标签树、灵感定位、自动拓展，然后候选方向审核，再生成投产任务。

## 4. 知识库页面现状分析

当前 `知识库资产中心` 页面位于 `public/index.html` 的 `knowledgePage` 区块，主要逻辑在 `public/js/creative-knowledge.js`，后端服务在 `src/services/creative-knowledge/index.js`。

### 4.1 当前页面的信息架构

当前知识库页大致分为：

```text
知识库资产中心总览
    ↓
同步记录 / 飞书方向表 / 写回 / 远程控制
    ↓
方向标签地图
    ↓
方向库
    ↓
本地成长方向草案
    ↓
自动评审
    ↓
资产审核
    ↓
经验规则
    ↓
运行记录
```

这已经是一个比较完整的“资产中心”，不仅有方向库，也有资产审核、经验规则和飞书同步。

### 4.2 当前知识库页的优点

#### 优点 1：资产闭环非常完整

知识库页面已经覆盖：

- 方向统计。
- 参考图统计。
- 资产统计。
- 运行统计。
- 入库图数量。
- 成长层统计。
- 审核统计。
- 方向可送入创意拓展。
- 资产可审核。
- 反馈可学习成规则。
- 方向草案可采纳、拒绝、归档。

这比普通“图片历史记录”强很多，已经具备知识库雏形。

#### 优点 2：方向库可用于生产

方向库不是只读陈列，支持：

- 搜索。
- 来源筛选。
- 状态筛选。
- 表现筛选。
- 批量选择。
- 送入创意拓展。
- 禁跑。
- 归档。
- 合并。

这说明方向库是活的，可以直接驱动生产。

#### 优点 3：成长层已经存在

`本地成长方向草案` 是当前项目非常重要的能力。它能从运行记录里提取新方向草案，并支持后续采纳/拒绝/归档。

这与参考项目的“成长整理”很像。区别是参考项目把成长整理做成了更明确的工作流：

```text
导入候选
筛出待补齐
编辑和地图
保存落盘
```

当前项目具备底层能力，但页面表达还比较像“草案列表”，不够像“成长整理工作台”。

#### 优点 4：资产审核和自动评审已经成型

知识库页支持：

- 未审、好图、一般、坏图、废图筛选。
- 自动评审。
- 低置信抽样队列。
- 人工样本导入。
- 自动评审一致率。
- 资产审核后写入 feedback。

这已经比参考项目截图中的“采纳模式”更偏工程闭环。当前系统能把图片结果回流为规则，是非常重要的基础。

#### 优点 5：反馈学习规则已有闭环

`经验规则` 区支持：

- 运行 Feedback Learning Agent。
- 生成规则草案。
- 人工编辑规则。
- 启用规则。
- 拒绝规则。
- 禁用规则。
- 区分全局、标签层、方向层规则。

这已经是很好的“AI 记忆治理”设计。

### 4.3 当前知识库页的不足

#### 不足 1：知识库像“资产列表”，还不像“创意知识地图”

当前知识库页很完整，但信息结构偏列表式：

```text
方向库列表
草案列表
资产列表
规则列表
运行列表
```

参考项目截图里的知识库更强调：

```text
总览
标签地图
成长整理
维护记录
```

也就是说，它把知识库按用户心智分成“看健康、看结构、整理成长、维护经验”。当前项目虽然功能更丰富，但用户进入后更容易感觉是很多折叠面板，而不是一套清楚的知识运营路径。

#### 不足 2：标签地图仍偏统计树，缺少节点详情

当前 `方向标签地图` 会展示方向数、资产、参考图、运行数。这个很好，但参考项目的标签地图会在选中节点后展示：

- 当前节点说明。
- 可用性。
- 方向数量。
- 参考图样本。
- 当前方向。
- 是否需要人工整理。
- 参考图缺口。

当前项目的标签地图更像分布概览，还不是“节点维护工作台”。

#### 不足 3：缺少“采纳模式”看板

参考项目的维护记录页左侧有“采纳模式 Agent”，它把人工审核通过的方向按父方向分组，并展示每个方向的视觉标签：

```text
城市废墟
  黎明废墟俯瞰：史诗壮阔 / 俯瞰 / 黎明 / 初次发现 / 巨型地标
  暴雪废墟探路：神秘未知 / 第一人称 / 暴风雪 / 初次发现 / 巨型地标
```

当前项目虽然有 `feedback.json`、`creative-memory.json`、`direction-expansion-history.json`，但没有一个页面把“被采纳的方向/好图背后的视觉 DNA”拉出来看。

#### 不足 4：缺少“风格偏好统计”

参考项目右侧的“风格偏好”很值得学习，它按方向统计：

```text
城市废墟
  氛围：史诗壮阔(2)、神秘未知(1)、荒凉孤独(1)
  视角：俯瞰(2)、第一人称(1)、平视(1)
```

当前项目的 `creative-memory.json` 里有规则，但缺少这种维度化统计：

- 每个父方向常用氛围。
- 每个父方向常用视角。
- 哪些视觉钩子采纳率高。
- 哪些动作机制更容易通过。
- 哪些 DNA 组合重复过多。

#### 不足 5：视觉 DNA 数据模型没有统一

当前相关字段分散在不同地方：

- `direction.description`：方向文本。
- `direction.referenceHints`：参考图提示，但有历史数据 `[object Object]` 的质量问题。
- `directionDraft.dimensions`：草案维度。
- `directionDraft.prompts`：提示词。
- `run.directionPlanReport.selectedExtensions[].visualHook`：入选方向视觉钩子。
- `run.directionPlanReport.selectedExtensions[].dedupeReason`：排重理由。
- `run.directionPlanReport.selectedExtensions[].productionAdvice`：制作建议。
- `direction-expansion-history.items[].creativeAxes`：方向拓展轴。
- `referenceImages[].visualDna`：参考图 DNA。
- `creative-memory.rules`：反馈规则。

这些都很有价值，但缺少一个统一的 `visualDna` schema。没有 schema，就很难统计、筛选、展示和复用。

## 5. 参考项目值得吸收的核心优点

### 5.1 把“方向”拆成视觉 DNA

参考项目最值得学的不是 UI 样式，而是它把方向继续拆成：

```text
题材
氛围
视角
天气
动作事件
冲突机制
尺度关系
视觉钩子
风格约束
风险规避
```

这让方向从一句描述变成可计算的结构。

当前项目已经有 `visualHook` 和 `creativeAxes`，所以不是从零开始，而是应该把这些字段升级为统一结构。

### 5.2 把“维护记录”做成知识运营页

参考项目的维护记录不是纯日志，而是把规则、采纳模式和风格偏好放在一起，用户可以直接看到：

- 哪些方向被采纳。
- 被采纳方向有什么共性。
- 各方向常用氛围和视角是什么。
- 哪些经验被 Agent 学到了。

当前项目的 `经验规则` 很强，但偏文本规则。可以补一个“维护记录 / 视觉偏好”视图，让规则更可视化。

### 5.3 成长层要从“草案列表”升级为“整理工作台”

参考项目的成长整理更有流程感：

```text
导入候选
筛出待补齐
编辑和地图
保存落盘
```

当前项目有方向草案，但还可以增强：

- 展示草案 DNA 完整度。
- 展示相似方向和重复风险。
- 支持编辑 DNA。
- 一键补参考图/补描述。
- 采纳后自动进入正式方向库。

### 5.4 候选方向审核应该前置

参考项目在正式投产前有“审核候选方向”。当前项目的 Direction Plan Gate 是后台自动完成的，用户更多是在 prompt 或图片阶段介入。

建议引入“可选人工审核模式”：

```text
Agent 生成候选方向
    ↓
页面展示候选方向卡片
    ↓
用户采纳 / 删除 / 编辑 DNA
    ↓
入选方向再生成 prompt
```

默认可以继续自动跑，但在人审模式下可以让用户更好地控制方向质量。

## 6. 推荐引入的视觉 DNA 数据模型

建议新增统一的视觉 DNA schema。第一阶段不必建复杂数据库，可以先在 JSON 字段里兼容落地。

### 6.1 方向级 visualDna

建议给方向、草案、入选 extension 都逐步补齐：

```json
{
  "visualDna": {
    "topic": ["城市废墟"],
    "atmosphere": ["紧张危机", "史诗壮阔"],
    "camera": ["第一人称"],
    "weather": ["暴风雪"],
    "time": ["黎明"],
    "sceneState": ["冰封", "废墟"],
    "event": ["撤离", "初次发现"],
    "conflict": ["安全与危险对比", "资源争夺"],
    "scale": ["巨型地标", "人物渺小"],
    "visualHook": ["红色信号弹", "远处暖光入口"],
    "style": ["3D卡通商业广告", "电影感"],
    "avoid": ["英文文字", "过度科幻", "主体不清"]
  }
}
```

### 6.2 最小可用维度

第一版建议只做 6 个维度，避免过度设计：

- `atmosphere`：氛围，例如紧张危机、史诗壮阔、荒凉孤独、温暖希望。
- `camera`：视角，例如第一人称、俯瞰、平视、远景、低机位。
- `event`：动作事件，例如发现、撤离、护送、争夺、修复、求救。
- `scale`：尺度关系，例如巨型地标、人物渺小、中等建筑、单体小件。
- `visualHook`：视觉钩子，例如红色信号弹、远处灯光、破损标语、物资箱。
- `avoid`：风险规避，例如英文包装、过度科幻、主体不清、文字乱码。

这 6 个维度已经足够支撑页面展示和偏好统计。

### 6.3 字段映射建议

现有字段可以这样迁移或映射：

| 现有字段 | 建议映射 |
| --- | --- |
| `visualHook` | `visualDna.visualHook` |
| `creativeAxes` 中 `camera:*` | `visualDna.camera` |
| `creativeAxes` 中 `emotion:*` | `visualDna.atmosphere` |
| `creativeAxes` 中 `subject-action:*` | `visualDna.event` |
| `creativeAxes` 中 `scene-mechanism:*` | `visualDna.conflict` 或 `visualDna.event` |
| `riskNote` | `visualDna.avoid` |
| `productionAdvice` | `productionAdvice` 保留，同时可辅助抽取 camera/event |
| prompt 中的 `情绪氛围` | `visualDna.atmosphere` |
| prompt 中的 `画面内容` | 辅助抽取 event / visualHook |
| feedback labels | 用于补充 avoid / preference stats |

收益：

### 任务 2：知识库方向卡片显示 DNA 摘要

```text
视觉 DNA：氛围 -- / 视角 -- / 事件 -- / 钩子 --
```

如果暂时没有 `visualDna`，就用已有数据回退：

- 从 `description` 抽取。
- 从成功案例 `direction-evidence` 抽取。
- 从 `direction-expansion-history` 抽取。
- 从最近 run 的 `selectedExtensions` 抽取。

收益：

- 方向库不再只是标签路径，而开始有视觉结构。
- 用户能快速判断方向是否适合继续拓展。

### 任务 3：知识库总览新增“视觉 DNA 覆盖率”

在知识库总览区新增：

```text
DNA 覆盖：已拆解方向数 / 总方向数
高频氛围：紧张危机、史诗壮阔、温暖希望
高频视角：第一人称、俯瞰、平视

缺视觉钩子方向：N 个
```

收益：

- 把知识库质量从“有多少方向/参考图”升级为“方向是否有可生产的视觉结构”。

### 任务 4：新增一个轻量 API 汇总 DNA

建议新增：


第一版不要求写入，只做只读聚合。

数据来源：

- `directions.json`
- `direction-drafts.json`
- `direction-expansion-history.json`
- `runs/*.json`
- `feedback.json`
- `creative-memory.json`

## 7.2 第二阶段：建立视觉 DNA 工作台

目标：对标参考项目的“维护记录”，做一个真正可用的视觉偏好与采纳模式页面。

### 任务 1：知识库新增页签或面板“视觉 DNA”


其中“维护记录 / 视觉 DNA”包含两列：

### 任务 2：采纳模式看板

### 任务 4：DNA 规则与现有经验规则打通

当前 `creative-memory.json` 已有全局/标签层/方向层规则。建议让 DNA 偏好也能生成规则草案：

这样视觉偏好就不是静态统计，而能进入下一轮 Agent 指令。

## 7.3 第三阶段：候选方向人工审核前置

目标：参考项目的“审核候选方向”，让用户在 prompt 和生图之前先审核方向。

```text
  自动通过：保持当前流程，Direction Plan Gate 自动筛选后直接生成 prompt
  人工审核：先生成候选方向，停在候选审核区，由用户确认后再生成 prompt
```

### 任务 2：候选方向卡片

每个候选卡片展示：

```text

描述
视觉 DNA 标签
```

### 任务 3：支持编辑 DNA 后再生成 prompt

用户可以在候选方向上改：

- 方向名。
- 氛围。

然后再送到 prompt 生成阶段。

收益：

- 人可以在方向层纠偏，而不是等图片生成后才发现方向不对。

## 7.4 第四阶段：成长层升级为方向治理工作台

目标：把当前“本地成长方向草案”从列表升级成参考项目那种成长整理流程。

### 任务 1：草案完整度

### 任务 2：Direction Plan Gate 按 DNA 打分

这样可以减少“方向很好，但 prompt 没写出来”的问题。

## 12. 风险与注意事项

### 12.1 不要把 DNA 做成太重的表单

视觉 DNA 是辅助生产，不应该让用户每次都填十几个字段。建议：

- Agent 自动抽取为主。
- 人工编辑为辅。
- 第一版只做 6 个核心维度。

### 12.2 不要让页面同时承担所有任务

创意拓展页负责“方向规划与产图执行”。  
知识库页负责“沉淀、维护、学习、治理”。  
不要把知识库维护功能全部塞回创意拓展页，否则页面会变复杂。

### 12.3 不要直接覆盖原有字段

历史数据很多，建议使用兼容字段：

- 先新增 `visualDna`。
- 保留 `visualHook`、`creativeAxes`、`productionAdvice`。
- 聚合层从旧字段推导 DNA。
- 等数据稳定后再考虑迁移。

### 12.4 注意反馈样本偏差

风格偏好统计要区分：

- 只是生成得多。
- 真的被人工评为好。
- 自动评审认为好。
- 只是某个方向历史样本多。

建议默认以人工好图/成功案例为高权重，以自动评审为中权重，以运行历史为低权重。

## 13. 最终建议

当前项目已经具备比参考项目更强的执行闭环，包括 Direction Plan Gate、Prompt Gate、自动修复、Legil 自动化、资产审核、反馈学习和飞书同步。真正值得补的是“视觉知识表达层”。

下一步不建议重写系统，而是做三件事：

1. 把已有的 `visualHook / creativeAxes / productionAdvice / riskNote` 聚合成统一 `visualDna`。
2. 在知识库中新增“采纳模式 + 风格偏好 + DNA 覆盖率”的维护视图。
3. 在创意拓展中增加候选方向审核，让用户能在生图前控制方向质量。

这样迭代后，当前项目会从“自动创意产图系统”进一步升级成“能学习视觉偏好、能治理方向资产、能稳定批量生产的创意知识中台”。
