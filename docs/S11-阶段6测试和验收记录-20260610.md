## 目标

覆盖源比例复用、逐 job 闭环交付、断点恢复、LOGO 缺失失败、source-reuse 后处理等核心业务路径，保证三尺寸交付流程稳定可用。

## 新增验收测试

新增：

```text
scripts/test-s11-stage6-acceptance.js
```

该脚本使用本地 Express 路由和假 Legil，真实执行：

```text
scan -> Legil 候选生成 -> 标准化 -> 加 LOGO -> final-package 输出
```

不会访问外部平台，但会真实生成图片文件并校验最终交付结果。

## 覆盖场景

| 场景 | 验收内容 |
| --- | --- |
| 单张 `1:1` OK 图 | `800x800` 为 source-reuse，`1280x720` / `1080x1920` 走 Legil |
| 单张 `16:9` OK 图 | `1280x720` 为 source-reuse，`800x800` / `1080x1920` 走 Legil |
| 单张 `9:16` OK 图 | `1080x1920` 为 source-reuse，`800x800` / `1280x720` 走 Legil |
| 单张 `4:3` OK 图 | 三个目标尺寸都走 Legil |
| 多张混合比例 OK 图 | 每张图按自身比例复用对应 target，混合 run 统计为 3 个 source-reuse target、9 个 Legil target |
| 完整交付中途停止 | 第 1 个 job 完成后已有 final-package 文件夹，恢复时跳过第 1 个 job，只继续后续 job |
| LOGO 模板缺失 | 后台任务失败，run.status 变为 failed，错误日志包含 LOGO |
| source-reuse 标准化 | 源 OK 图输出精确目标尺寸、JPG、体积小于 390KB，并加 LOGO |

## 最终交付校验

对每个 finalized job 校验：

```text
1. final-package/<job-folder> 中存在 800x800、1280x720、1080x1920 三张 JPG
2. 每张 JPG 尺寸精确匹配目标尺寸
3. 每张 JPG 文件名为 <job.baseName>_<targetSize>.jpg
4. target.logoApplied = true
5. 通过底部右侧 LOGO 像素检查确认 LOGO 已叠加
6. source-reuse target 不存在 Legil 调用记录
7. 第 1 个 job 的最终文件在第 2 个 job Legil 开始前已经存在
```
