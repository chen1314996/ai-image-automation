最终目标是把当前项目改造成：

```text
根据现有创意体系，自动选择方向、自动拓展方向、自动拓展提示词、自动调用 Legil 生图、自动记录结果，并支持 24 小时循环运行。
```

---

## 2. 总目标和原则

### 2.1 总目标

系统最终要形成这个闭环：

```text
创意知识库
  -> 自动选题
  -> 创意 Agent 拓展方向
  -> 提示词解析和质检
  -> Legil 自动生图
  -> 图片保存和资产索引
  -> 结果反馈回流知识库
  -> 下一轮自动选题
```

### 2.2 开发原则

1. 先跑通最小闭环，再做 24 小时全自动。
2. 先用 JSON 文件落地状态，不急着上数据库。
3. 先复用当前已有能力，不重写 Legil 自动化。
4. 先做单轮自动运行，再做循环调度。
5. 先做可观察、可暂停、可恢复，再提高速度。
6. 先不追求完全智能，先让规则可解释、可控。
7. 任何自动化都必须能停止、能恢复、能查日志。
8. 任何 LLM 输出都必须经过程序验收。
9. 同一时间只允许一个 Legil 网页任务运行。
10. 每张图必须能追溯来源方向、prompt、runId 和生成参数。

## 4. 分阶段总览

建议按 10 个阶段推进。

| 阶段 | 名称 | 目标 | 自动化程度 |
| --- | --- | --- | --- |
| P0 | 资料准备与规则确认 | 你提供创意体系、账号、目录、运行规则 | 无 |
| P1 | 最小创意知识库 | 系统能读取方向、参考图、资产索引 | 无 |
| P2 | 自动选题器 | 系统能推荐下一批要拓展的方向 | 半自动 |
| P3 | Agent 单轮拓展 | 系统能自动选方向并生成提示词 | 半自动 |
| P4 | 提示词质检与去重 | 系统能筛掉明显无效/重复 prompt | 半自动 |
| P5 | Legil 单轮产图接入 | 一键完成“选题 -> Agent -> Legil” | 自动单轮 |
| P6 | 资产索引和结果回流 | 每张图可追溯，方向状态可更新 | 自动单轮 |
| P7 | 前端/飞书控制面板 | 人可以看状态、启动、暂停、恢复 | 半自动运行 |
| P8 | 24 小时循环调度 | 系统能按规则持续运行多轮 | 全自动 |
| P9 | 运维增强和失败恢复 | 更稳地处理卡住、掉线、登录失效 | 全自动稳定版 |
| P10 | 质量提升和知识增长 | 引入反馈、精选图、参考图池、视觉 DNA | 进阶版 |

推荐先交付到 P6，再进入试运行；P8 以后才是真正 24 小时自动化。

## 5. P0：资料准备与规则确认

### 5.1 阶段目标

在写代码之前，先把系统需要的业务输入准备好。

这一阶段不写核心功能，但非常重要。资料不清，后面自动化会跑偏。

### 5.2 你需要提供

#### 1. 创意方向种子表

推荐提供 Excel 或 CSV，至少包含这些列：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| `路径` | 是 | 如 `题材/探索发现/物品展示/急救药品` |
| `方向名` | 是 | 如 `冰封医院药房抽屉` |
| `方向描述` | 是 | 说明这个方向要表达什么 |
| `必须保留` | 建议 | 逗号或换行分隔，如 `简体中文药品标签、冰封医院、医疗资源稀缺` |
| `必须避开` | 建议 | 如 `真实药品品牌、现代干净医院、重复抽屉近景` |
| `优先级` | 建议 | 1-100，越高越优先 |
| `参考图目录/文件` | 可选 | 指向本地方向参考图 |
| `备注` | 可选 | 其他人工说明 |

最小样例：

| 路径 | 方向名 | 方向描述 | 必须保留 | 必须避开 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 题材/探索发现/物品展示/急救药品 | 冰封医院药房抽屉 | 幸存者在废弃医院药房中发现保存完好的止痛药、抗生素和绷带 | 简体中文药品标签、冰封废弃医院、医疗资源稀缺 | 真实品牌、现代医院广告、重复抽屉近景 | 90 |

第一版建议至少给：

```text
20-50 个方向
```

如果一开始只有 5-10 个也可以，但自动选题空间会小。

#### 2. 层级语义说明

为了让 Agent 理解标签层级，建议提供一个简单表：

| 路径 | 层级含义 |
| --- | --- |
| 题材 | 冰封末世生存世界观，所有画面应体现极寒环境、资源稀缺和废墟生存 |
| 题材/探索发现 | 角色在未知废墟、旧文明遗迹或危险环境中发现资源或线索 |
| 题材/探索发现/物品展示 | 关键物资成为画面视觉中心，强调可识别、可获得、可引发点击动机 |

这会生成：

```text
data/creative-knowledge/hierarchy-context.json
```


你需要确认：

你需要提供或确认：

## 7. P2：自动选题器

### 7.1 阶段目标

系统能根据知识库自动推荐下一批最值得拓展的方向。

### 7.2 计划新增代码

```text
src/services/creative-knowledge/selector.js
src/services/creative-knowledge/scoring.js
```

### 7.3 计划新增接口

```text
GET /api/creative-scheduler/suggestions
```

或放在知识库路由中：

```text
GET /api/creative-knowledge/suggestions
```

### 7.4 选题评分

第一版建议使用可解释打分：

```text
score =
  priority
  + coverageGap
  + staleBoost
  + feedbackBoost
  - recentPenalty
  - failurePenalty
  - missingInfoPenalty
```

字段说明：

| 字段 | 计算逻辑 |
| --- | --- |
| `priority` | 人工优先级，1-100 |
| `coverageGap` | 图片越少分越高 |
| `staleBoost` | 越久没跑分越高 |
| `feedbackBoost` | 历史好图越多分越高 |
| `recentPenalty` | 刚跑过则降权 |
| `failurePenalty` | 最近失败多则降权 |
| `missingInfoPenalty` | 缺描述/缺上下文则降权 |

### 7.5 返回示例

```json
{
  "success": true,
  "suggestions": [
    {
      "directionId": "direction_001",
      "path": "题材/探索发现/物品展示/急救药品",
      "name": "冰封医院药房抽屉",
      "score": 92,
      "reason": "高优先级，尚未产图，方向描述完整",
      "recommendedAction": "expand"
    }
  ]
}
```

### 7.6 你需要提供

本阶段需要你确认：

- 方向优先级怎么定。
- 哪些方向第一版不要自动跑。
- 是否有黑名单方向。
- 哪些方向必须先人工审核。

建议在方向表里增加：

| 字段 | 含义 |
| --- | --- |
| `自动运行` | `是/否` |
| `人工审核` | `是/否` |
| `优先级` | 1-100 |

### 7.7 验收标准

访问建议接口，能看到排序后的候选方向。

人工检查前 5 个建议，至少 3 个符合直觉，说明选题器可用。

## 8. P3：Agent 单轮拓展

### 8.1 阶段目标

系统能自动选择一个方向，调用现有 creative Agent，生成新方向和提示词。

这一阶段先不发给 Legil，只生成结果文件。

### 8.2 计划新增代码

```text
src/services/creative-scheduler/
  agent-runner.js
  prompt-builder.js
  run-store.js
```

### 8.3 计划新增接口

```text
POST /api/creative-scheduler/run-once
```

支持 dry run：

```json
{
  "mode": "agent-only",
  "directionId": "direction_001"
}
```

如果不传 `directionId`，系统自动选题。

### 8.4 自动构建 Agent 指令

调度器会把方向信息拼成 Agent 请求：

```text
# 自动创意拓展任务

请基于当前知识库方向继续拓展，不要重复已产出的方向和画面结构。

## 当前方向
路径：题材/探索发现/物品展示/急救药品
方向名：冰封医院药房抽屉
方向描述：幸存者在废弃医院药房中发现保存完好的止痛药、抗生素和绷带。

## 必须保留
- 简体中文药品标签
- 冰封废弃医院环境
- 医疗资源稀缺与救命价值

## 必须避开
- 不要重复同一抽屉近景构图
- 不要出现真实药品品牌
- 不要变成现代干净医院广告

## 历史已生成方向
- 近景抽屉药品
- 俯拍满屉药品

## 本次目标
生成 5 个高差异新方向，每个方向 5 条完整中文生图提示词。
```

### 8.5 运行记录

每轮生成：

```text
data/creative-knowledge/runs/<runId>/
  run.json
  agent-request.txt
  agent-result.json
  prompts.json
```

### 8.6 你需要提供

本阶段需要：

- LLM API Key 可用。
- Agent 模型确认。
- 单次目标数量确认。
- prompt 风格规则确认。

如果你想让 Agent 更贴合业务，需要提供：

- 过去效果好的 5-10 条 prompt。
- 过去效果差的 5-10 条 prompt。
- 禁止元素列表。
- 统一尾句或风格要求。

### 8.7 验收标准

执行：

```text
POST /api/creative-scheduler/run-once
```

请求：

```json
{
  "mode": "agent-only"
}
```

结果：

- 能自动选中一个方向。
- 能调用 Agent。
- 能生成 Excel 或 JSON 结果。
- 能提取出 prompts。
- prompts 数量大于 0。
- 不启动 Legil。

```text

  -> select_direction
  -> run_agent
  -> compile_prompts
  -> run_legil
  -> record_assets
  -> update_knowledge
  -> cooldown
  -> select_direction
```

失败分支：

```text
任意阶段失败
  -> failure_count + 1
  -> 如果连续失败 >= 阈值，进入 paused
  -> 飞书通知
```

### 13.4 限额设计

必须支持：

```json
{
  "maxPromptsPerRun": 25,
  "maxImagesPerRun": 100,
  "maxImagesPerDay": 1000,
  "maxRunsPerDay": 20,
  "cooldownSeconds": 120,
  "nightMode": false,
  "allowedHours": [0, 1, 2, 3, 4, 5, 9, 10, 11, 14, 15, 16, 20, 21, 22]
}
```

### 13.5 Preflight 检查

每轮开始前检查：

- Legil 当前是否有任务。
- Agent 是否有任务。
- LLM 配置是否可用。
- 输出目录是否可写。
- 今日额度是否用完。
- 是否处于暂停状态。
- 连续失败是否达到阈值。

第二版再加：

- 浏览器是否登录。
- 磁盘剩余空间。
- 最近 N 分钟是否有新图片。

### 13.6 你需要提供

- 允许运行时间段。
- 夜间是否降低产量。
