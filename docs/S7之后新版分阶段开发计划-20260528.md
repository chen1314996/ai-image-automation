### 1.2 当前最重要的变化

旧计划中 S7 原本直接进入“飞书同步”。但现在项目已经新增了大量本地闭环能力，且其中一部分还需要真实页面、真实 Winky、真实 Legil 验收。

因此新版路线不建议马上进入 24 小时调度，也不建议马上做飞书写回。更合理的顺序是：

```text

S10 完善量产和后处理联动

S12 做监控、恢复、日报和飞书通知闭环
S13 做跨周趋势和策略优化
S14 才进入 24 小时正式运行验收
```

## 3. S7：当前能力收口与真实验收

### 3.1 目标

把已经开发出来的能力做一次完整收口，不再只依赖服务级脚本或 stub 验收。

S7 的重点不是新增大功能，而是确认下面这些真实链路能跑通：

```text
真实 Winky 图文能力
真实素材视觉识别
真实 Agent prompt 生成
真实 Prompt Gate 检查
真实 Legil 生图保存
真实资产入库
真实页面展示
真实失败提示
```

### 3.2 为什么要先做

当前 S0-S6 和素材分析主链路已有较多代码。继续往后做飞书同步、调度器和 24 小时循环之前，必须先确认这些新能力不是“单元测试通过但真实流程有断点”。

如果跳过 S7，后续调度器会放大问题：

```text
Winky 返回格式不稳定
Legil 页面选择器变化
图片保存路径不一致
资产入库缺字段
前端页面看不懂运行结果
错误提示无法指导人工接管
```

## 4. S8：素材分析沉淀到知识库

### 4.1 目标

把素材分析页得到的优秀素材、风险素材、视觉洞察、方向表现和周报经验沉淀成系统下一轮能使用的长期记忆。

本阶段需要特别区分两类知识：

```text
文字经验、避坑规则、周报总结
  -> 进入素材经验池和 creative-memory
  -> 服务自动选题、Prompt Gate 和后续策略判断

画面直观、可复刻的好方向
  -> 由你点击“加入候选方向”
  -> 生成方向草稿
  -> 后续补参考图并人工确认后，才进入正式方向库
```

方向库本身保持直观，不承载大段素材分析文字。正式方向应继续以标签、画面核心内容、参考图、状态和统计为主。

### 4.2 核心流程

```text
导入每周素材表
  -> Top100 和健康度分析
  -> AI 视觉识别
  -> 生成周报和经验文档
  -> 选择优秀素材或优秀方向
  -> 沉淀到素材经验池 material-learnings.json
  -> 选择失败素材或风险方向
  -> 写入负向经验和 Prompt Gate 避坑规则
  -> 对特别值得复刻的素材或方向，人工点击“加入候选方向”
  -> 自动生成方向草稿，参考图状态标记为待人工上传
  -> 影响下一轮自动选题和 Prompt Gate
```

### 4.3 开发任务

| 任务 | 说明 |
| --- | --- |
| 单素材经验沉淀 | `/api/material-analysis/materials/:materialId/collect-knowledge` 写入素材经验池，不直接写正式方向库 |
| 方向级经验沉淀 | `/api/material-analysis/directions/:directionKey/collect-knowledge` 写入素材经验池，不在方向卡展示大段文字 |
| 本周经验批量沉淀 | `/api/material-analysis/imports/:runId/collect-weekly-learnings` 批量生成正向经验和负向避坑 |
| 素材经验池结构 | 写入 `data/creative-knowledge/material-learnings.json` |
| 负向经验结构 | 写入 `data/creative-knowledge/creative-memory.json`，用于 Prompt Gate |
| 候选方向生成 | 补齐 `/api/material-analysis/*/create-direction-draft`，把好素材或好方向转成方向草稿 |
| 方向库页面边界 | 正式方向库只展示方向标签、画面核心内容、参考图、状态和统计，不展示素材分析长文本 |
| 自动选题权重接入 | direction-selector 读取素材经验、风险记忆和近期表现 |
| Prompt Gate 接入避坑规则 | 将负向经验转成可解释的 prompt 拦截或警告 |

## 5. S9：飞书只读同步

### 5.1 目标

让系统从飞书读取团队已有的方向、标签、参考图线索和 TOP 素材表，减少手动维护 `sucai` 的依赖。

S9 只做只读同步，不做自动写回。

### 5.2 当前基础

项目已经有飞书通知、CLI 桥接、状态查询、卡片按钮和远程控制接口，但这些主要服务于“控制和通知”。

S9 要新增的是“数据同步”能力：

```text
飞书表格 / 多维表格
  -> 字段映射
  -> 本地缓存
  -> directions.json
  -> top-materials.json
  -> reference-images.json
  -> knowledge-operations.json
```

### 5.3 开发任务

| 任务 | 说明 |
| --- | --- |
| 飞书数据源配置 | 配置 app id、secret、表格 token、sheet id、字段映射 |
| 同步配置页 | 在前端配置区展示飞书同步状态和测试按钮 |
| 方向表同步 | 从飞书读取方向层级、描述、标签、状态、优先级 |
| TOP 素材同步 | 从飞书读取项目、周次、素材指标或素材链接 |
| 参考图线索同步 | 从飞书读取图片 URL、附件或本地路径字段 |
| 本地缓存 | 同步成功后保存快照，飞书失败时可继续使用上次缓存 |
| 字段映射校验 | 缺字段、权限不足、token 错误时给出清晰提示 |
| 操作日志 | 写入 `knowledge-operations.json`，记录同步来源、时间、数量、警告 |

### 5.4 同步策略

| 策略 | 说明 |
| --- | --- |
| 只读优先 | 第一版只从飞书读，不自动写回 |
| 人工触发优先 | 先做“点击同步”，不直接定时同步 |
| 本地缓存兜底 | 飞书失败不影响已有知识库使用 |
| 字段映射可配置 | 表头变化时不改代码或少改代码 |
| 写入前预览 | 同步前展示会新增、更新、忽略多少条 |
| 不覆盖人工反馈 | 本地审核和反馈优先级高于飞书原始状态 |

### 5.5 你需要提供

| 项目 | 说明 |
| --- | --- |
| 飞书 App ID | 用于 API 访问 |
| 飞书 App Secret | 用于 token 获取 |
| 表格或多维表 token | 指定读取哪份数据 |
| sheet id 或 table id | 指定读取哪张表 |
| 字段说明 | 方向、标签、参考图、素材指标对应哪些列 |
| 权限确认 | 应用需要能读表格、附件或图片 |

### 5.6 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 数据是否读对 | 飞书里的方向、标签、参考图字段是否正确进入本地 |
| 页面是否一致 | 知识库页展示是否和飞书核心字段一致 |
| 失败是否清楚 | 缺权限、缺字段、token 错误是否能看懂 |
| 同步是否安全 | 没有确认不写回，不覆盖本地人工审核结果 |

### 5.7 通过标准

```text
点击“同步飞书”后，
知识库方向、TOP 素材和参考图索引能更新；
同步结果有数量、警告和失败原因；
飞书不可用时系统仍能使用上次本地缓存。
```

把创意拓展、素材分析提示词池、Legil 量产、资产库、重命名、改尺寸和打包输出串成可追溯的生产链路。

### 6.2 当前基础

当前已经具备：

```text
素材分析生成提示词池
创意拓展页接收提示词池
Legil 批量生成
资产入库
改尺寸多比例续跑
重命名和打包相关服务
```

S10 要补齐的是“入口统一”和“派生产物追溯”。

### 6.3 核心流程

```text
素材分析优秀方向

  -> 创意拓展页选择 prompt
  -> Legil 批量生成
  -> 资产入库
  -> 人工审核好图
  -> 重命名
  -> 改尺寸
  -> 打包输出
  -> 派生产物回写资产关系
```

### 6.4 开发任务

| 任务 | 说明 |
| --- | --- |

| 派生产物关系 | 改尺寸、重命名、打包后的文件记录 `sourceAssetId`、`sourceRunId`、`sourcePromptId` |
| 量产 run 统一记录 | 将 `/api/legil/creative-batch` 或现有批量任务和 creative-auto run 关联 |
| 后处理状态展示 | 资产详情显示是否已重命名、是否已改尺寸、有哪些派生文件 |
| 失败可继续 | 后处理失败后能从未完成步骤继续 |
| 输出目录规范 | 明确原图、重命名图、改尺寸图、打包图的目录和命名规则 |

### 6.5 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 好方向能否进入量产 | 从素材分析或知识库出发，不重复复制 prompt |
| 好图能否进入后处理 | 从资产库选图后能进入重命名和改尺寸 |

| 结果是否可交付 | 最终文件夹能直接给投放或后续流程使用 |

### 6.6 通过标准

```text

完成一小批 Legil 生成，
```

## 7. S11：调度器和小流量试运行

### 7.1 目标

从“手动运行一次”升级为“按规则自动运行多轮”，但先做小流量试运行，不直接 24 小时放量。

### 7.2 前置条件

进入 S11 前必须满足：

```text
S7 真实验收通过
S8 知识沉淀可用
S9 飞书只读同步可用或确认暂缓
S10 小批量量产和资产追溯可用
连续失败能暂停
每日额度能读取和写入
```

### 7.3 调度策略

| 策略 | 默认值 | 说明 |
| --- | --- | --- |
| 运行窗口 | 手动配置 | 例如每天 10:00-12:00、14:00-18:00 |
| 每日额度 | 1000 张 | 硬上限，任何任务不能突破 |
| 单轮规模 | 1-5 prompt 起步 | 稳定后再扩大到 25 prompt |
| 每 prompt 出图数 | 4 张 | 沿用当前 Legil 默认配置 |
| 冷却时间 | 每轮 10-30 分钟 | 避免平台风控和连续错误 |
| 连续失败暂停 | 5 次 | 已有策略继续强化 |
| 夜间策略 | 只暂停不重试 | 避免无人值守时重复出错 |
| 人工审核阈值 | 可配置 | 未审核资产过多时暂停新生成 |

### 7.4 开发任务

| 任务 | 说明 |
| --- | --- |
| scheduler-state 升级 | 记录自动运行状态、额度、窗口、当前轮次、暂停原因 |
| 调度服务 | 按运行窗口触发 run-once，避免并发任务冲突 |
| 控制接口 | 开启、暂停、恢复、停止、跳过当前方向 |
| 前端运行中心 | 显示调度状态、下一轮时间、今日额度、失败次数 |
| 方向轮换 | 避免连续跑同一方向，结合知识库权重 |
| 未审核积压保护 | 未审核图片超过阈值时暂停 |
| 试运行报告 | 每次试运行结束输出轮次、成功、失败、保存数 |

### 7.5 试运行节奏

```text
第 1 轮：手动开启，1 个方向，1 条 prompt，观察完整链路
第 2 轮：自动触发，1 个方向，1-2 条 prompt
第 3 轮：自动触发，2-3 个方向，总计 5 条 prompt
第 4 轮：半天试运行，总计不超过 50 张图
第 5 轮：一天试运行，总计不超过 200 张图
通过后再考虑 1000 张/天上限
```

### 7.6 你需要验收

| 验收项 | 你看什么 |
| --- | --- |
| 是否能自动跑 | 不需要每轮手动点击 run-once |
| 是否停得住 | 点暂停后不再提交新 prompt |
| 是否守额度 | 不超过每日上限 |
| 是否避开重复方向 | 不连续跑同一个方向 |
| 是否能接管 | headed 浏览器和页面状态能让你接手 |
| 是否不会堆积 | 未审核图过多时能暂停 |

### 7.7 通过标准

```text
系统能在小流量下连续自动运行多轮；
每轮都有 run 记录和资产记录；
失败能暂停；
额度不超限；
你能在页面上看懂它正在做什么和为什么暂停。
```

### 8.3 开发任务

| 任务 | 说明 |
| --- | --- |

## 9. S13：跨周趋势和策略优化

### 9.1 目标

让素材分析、知识库、反馈学习和自动选题形成长期优化能力。

S13 解决的问题不是“今天能不能出图”，而是：

```text
哪些方向连续变好

哪些方向该暂停
哪些新方向值得试
哪些失败原因反复出现
下一周应该把额度花在哪里
```

### 9.2 开发任务

| 任务 | 说明 |
| --- | --- |

| 生命周期判断 | 判断冷启动、增长、成熟、单点依赖、疲劳、方向枯竭等状态 |
| 方向权重模型 | 将趋势、反馈、素材经验、负向经验转成选题权重 |
| Prompt Gate 优化 | 用历史坏图原因和素材分析风险规则增强拦截 |
| 参考图策略 | 根据方向表现、参考图线索和素材经验选择更合适的参考图 |
| 复盘页面 | 展示方向成长、衰退、风险、机会 |

### 9.3 指标

| 指标 | 说明 |
| --- | --- |
| 好图率 | good / reviewed |
| 审核覆盖率 | reviewed / saved |

## 13. 防跑偏规则

以下情况出现时，应该暂停继续往后开发，先纠偏：

| 跑偏信号 | 为什么要停 |
| --- | --- |
| 只增加自动运行，不增加审核反馈 | 系统会更快地产生错误资产 |
| 只看生成数量，不看好图率 | 会浪费额度和时间 |
| 图片没有资产记录 | 无法学习和追溯 |
| 反馈只写备注，不进入规则 | 下一轮不会变好 |
| Agent 直接写飞书或覆盖知识库 | 容易污染团队底表和本地经验 |
| 调度器没有暂停机制 | 可能连续失败或无限重试 |
| 失败没有分类 | 人工无法判断是否需要接管 |
| 页面看不懂系统状态 | 无法无人值守 |
| 趋势模型早于真实数据 | 容易凭空优化，影响判断 |

## 14. 推荐下一步

从当前项目情况出发，下一步不建议直接进入旧计划的“飞书同步”，而是先进入：

```text
S7：当前能力收口与真实验收
```

建议 S7 的第一天工作顺序：

```text
1. 清点 data/ 和 sucai/，确定提交和忽略策略
2. 补齐 docs/接口清单.md 中的素材分析和 start-legil 接口
3. 用真实 Winky 跑一次参考图 prompt 生成
4. 用真实 Winky 跑一次素材视觉识别
5. 用真实 Legil 跑一次 agentOnly -> Prompt Gate -> 继续 Legil -> 资产入库
6. 打开知识库、创意拓展、素材分析三个页面做浏览器验收
7. 根据真实验收结果决定进入 S8，还是先修复断点
```

S7 通过之后，再进入：

```text
S8：素材分析沉淀到知识库
```

这样路线会更稳：先确认系统真的能跑，再让它记住经验，再接飞书，再自动调度，最后进入 24 小时无人值守。
