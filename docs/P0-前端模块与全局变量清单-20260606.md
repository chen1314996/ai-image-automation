# P0 前端模块与全局变量清单

> 日期：2026-06-06  
> 目的：记录当前 vanilla JS 页面脚本的全局暴露面，避免 P0 后续继续扩大污染。

---

## 1. 现状判断

当前前端仍是非模块脚本，所有顶层 `function`、`let`、`const`、`var` 都在普通 script 作用域内执行。大量按钮仍通过 inline `onclick` 调用全局函数，因此 P0 不做大规模 ES Module 改造，只先建立新模块命名空间和轮询清理机制。

P0 原则：

```text
新增通用能力挂在命名空间。
新增轮询必须可 start/stop。
旧 onclick 全局函数保留。
新模块不引入新的裸全局状态池。
```

## 2. P0 新增全局

| 全局名 | 来源 | 类型 | 用途 |
| --- | --- | --- | --- |
| `window.ApiClient` | `public/js/api-client.js` | 命名空间 | `fetchJson`、`readJsonResponse`、pending 状态 |
| `window.createStatusPoller` | `public/js/status-poller.js` | 工厂函数 | 创建可启停轮询 |
| `window.loadAutonomyDiagnostics` | `public/js/autonomy-diagnostics.js` | 函数 | 手动刷新 P0 诊断 |
| `window.startAutonomyDiagnosticsPolling` | `public/js/autonomy-diagnostics.js` | 函数 | 启动诊断轮询 |
| `window.stopAutonomyDiagnosticsPolling` | `public/js/autonomy-diagnostics.js` | 函数 | 停止诊断轮询 |
| `window.getLastAutonomyDiagnostics` | `public/js/autonomy-diagnostics.js` | 函数 | 读取最近诊断快照 |
| `window.startRunCenterPolling` | `public/js/run-center.js` | 函数 | 启动运行中心轮询 |
| `window.stopRunCenterPolling` | `public/js/run-center.js` | 函数 | 停止运行中心轮询 |

P0 新增内部状态仅保留在 IIFE 闭包中：

```text
api-client.js: pendingKeys
status-poller.js: timer / inFlight / stopped
autonomy-diagnostics.js: diagnosticsPoller / lastDiagnostics
run-center.js: runCenterPoller
```

## 4. 高风险全局污染源

| 文件 | 原因 | P0 处理 |
| --- | --- | --- |
| `creative-auto.js` | 自动创意页面状态多，函数超过 300 个扫描命中 | 暂不重写；新 P0 诊断独立到 `autonomy-diagnostics.js` |
| `creative-knowledge.js` | 知识库列表、审核、反馈和飞书逻辑混在一个全局脚本 | 暂不重写；只在 HTML 增加治理入口容器 |
| `material-analysis.js` | 素材分析和创意方向包逻辑复杂 | 不卷入 P0 页面改造 |
| `config-panels.js` | 配置项覆盖多页面 | 不新增闭环配置项 |
| `app-state.js` | 历史全局变量集中地 | P0 不再向其中添加新状态 |

## 5. 轮询清单

| 轮询 | 当前状态 | P0 处理 |
| --- | --- | --- |
| 运行中心状态 | 原来用 `window.__runCenterStatusInterval` | 改为 `createStatusPoller`，支持 `startRunCenterPolling/stopRunCenterPolling` |
| P0 诊断状态 | 新增 | `autonomy-diagnostics.js` 使用 `createStatusPoller` |
| 自动创意 run 轮询 | 既有 `creativeAutoStatusInterval` | 暂不重构，避免影响 run-once 主流程 |
| 改尺寸/交付/表格批量轮询 | 既有 | P0 不改 |

---

## 6. 后续收口建议

下一阶段如果要继续减少全局污染，建议顺序如下：

```text
1. 把 ui-core 的通用工具迁入 ApiClient / UI 命名空间。
2. 把 creative-auto.js 拆成 status、target-picker、run-detail、actions 四个 IIFE 模块。
3. 把 creative-knowledge.js 拆成 overview、directions、assets、memory、feishu-sync 五个 IIFE 模块。
4. 移除新功能里的 inline onclick，改成 DOMContentLoaded 内部绑定。
5. 最后再考虑 ES Module；不要在 P0/P1 中强行迁移。
```
