# Web页面成熟产品化优化方案-20260612

## 1. 方案概述

当前 Web 平台已经具备完整的 AI 生图自动化能力，包括提示词生成、Legil 生图、创意拓展、素材分析、方案迭代、知识库沉淀、改尺寸交付和运行监控。下一阶段的核心目标是把这些能力包装成一个成熟、清晰、可交付给他人使用的产品界面。

本方案从产品经理和 UI/UX 视觉设计角度出发，对整体信息架构、页面内容、交互方式、移动端体验和成熟产品文案进行系统优化。

## 2. 产品定位

建议将当前平台定位为：

```text
AI 生图自动化生产工作台
```

一句话说明：

```text
围绕创意方向、素材反馈、方案迭代、批量产图和交付处理，提供从创意生成到图片交付的自动化生产能力。
```

产品气质：

- 专业
- 稳定
- 高效
- 工作台型
- 面向生产流程
- 适合长期反复使用

不建议的方向：

- 不做营销落地页风格。
- 不做花哨大屏。
- 不做强装饰视觉。
- 不做开发调试台式文案。

## 3. 目标用户

### 3.1 核心用户

- 负责广告素材生产的人
- 负责创意方向拓展的人
- 负责批量产图和交付的人
- 负责素材复盘和方案迭代的人

### 3.2 使用场景

- 每天启动批量产图任务。
- 根据参考图自动生成提示词并提交生图。
- 根据投放数据分析 Top 素材和方向表现。
- 导入方案任务表并整理成可执行方向。
- 将生成图片纳入知识库和资产审核。
- 对成品图片做多尺寸交付、标准化、LOGO、命名和打包。
- 在桌面端和移动端查看、配置、启动、暂停、继续任务。

## 4. 设计总原则

### 4.1 工作台优先

用户进入页面后，应优先看到：

- 当前能做什么
- 当前状态是什么
- 下一步应该点哪里
- 是否存在异常

页面不是功能说明书，页面是生产工作台。

### 4.2 高频优先

批量产图最高频是：

```text
参考图自动产图
```

因此批量产图页必须默认服务这个流程。

### 4.3 执行优先，配置后置

高频执行页首屏放：

- 输入
- 输出
- 必要配置
- 主按钮
- 当前任务

低频配置放：

- 折叠区
- 高级配置
- 模式切换
- 更多设置

### 4.4 文案成熟化

给别人看的产品不能出现太多内部口径。

需要移除或替换：

```text
OK 图
S10.3
P0 / P1
老流程 / 新流程
Run
Phase
Agent
final-package
跑起来
学起来
emoji 按钮
```

成熟表达：

```text
源图
待交付图片
系统状态
任务
阶段
执行模块
交付包
提示词质检
改尺寸交付
```

### 4.5 移动端完整可操作

移动端不是只读看板，需要完整支持：

- 页面切换
- 配置路径
- 配置参数
- 启动任务
- 暂停、继续、停止
- 查看进度
- 查看日志
- 查看结果

### 4.6 网页与平面设计级版式标准

后续页面调整按网页设计和商业平面设计的标准验收，不按“功能都在就行”的开发后台标准验收。

核心要求：

- 信息层级清楚：一个页面先让用户看到主任务，再看到必要配置，最后才看到辅助信息。
- 视觉焦点单一：首屏只能有一个最强主按钮，不能多个同权重按钮互相抢注意力。
- 对齐优先：同一页面的主卡、表单、命名规则、任务列表尽量共用同一内容宽度和栅格基线。
- 留白克制：卡片之间要有呼吸感，但不能做成空洞的大间距；密度要服务工作台效率。
- 少解释：能通过结构表达的内容，不用说明文字；能通过按钮状态表达的内容，不用提示条。
- 少装饰：普通卡片标题不默认配图标，关键导航、状态、危险操作和主动作才使用符号。
- 文本不溢出：路径、文件名、示例命名、按钮文案必须有截断、换行或响应式策略。
- 内容不堆叠：避免右侧小卡、摘要卡、说明条、流程条同时出现，造成廉价和拥挤。
- 页面像产品：不出现“临时调试区”“内部阶段”“给自己看的备注”式内容。

### 4.7 视觉传达优先级

每个页面的信息传达按以下顺序组织：

```text
当前页面用途
关键输入 / 输出
必要配置
主操作
任务状态
结果或列表
高级设置 / 日志 / 历史
```

如果某个模块不能帮助用户更快完成当前任务，应默认后置、折叠或移出首屏。页面复杂度宁可少一层，也不要多一个让用户犹豫的卡片。

## 7. 全局状态设计

### 7.1 状态分类

| 状态 | 颜色 | 文案示例 |
|---|---|---|
| 可用 | 绿色 | 已配置、已连接、可运行 |
| 处理中 | 黄色 | 运行中、正在读取、等待响应 |
| 阻塞 | 红色 | 连接失败、配置缺失、任务失败 |
| 未开始 | 灰色 | 未启动、未配置、暂无任务 |

### 7.2 顶部状态条

建议统一为：

```text

生图平台：未连接

```

不要让“未启动”显示成绿色状态。

### 7.3 运行中状态

运行中建议统一展示：

```text
任务名称
当前阶段
进度
已完成数量
失败数量
最近更新时间
```

## 16. 页面方案：改尺寸交付

### 16.1 页面定位

改尺寸交付是面向交付人员的图片交付工作台，不是展示内部处理链路的配置页。页面要让用户第一眼明白三件事：源图在哪里、输出到哪里、现在能不能开始交付。

该页底层仍覆盖标准化、LOGO、命名与打包能力，但前端呈现要以“完成交付”为目标组织信息，避免把每个后台步骤都摊开成卡片。

### 16.2 成熟文案

导航名：

```text
改尺寸
```

页面标题：

```text
改尺寸交付
```

副标题：

```text
将待交付图片自动适配为多种投放尺寸，并完成标准化、LOGO、命名与打包。
```

副标题允许说明能力边界，但不要在页面首屏再重复展示 `源图导入 -> AI 尺寸适配 -> 标准化 -> LOGO -> 命名 -> 打包` 这类流程条。成熟产品应通过输入、输出、按钮和任务状态传达流程，而不是用大段步骤说明占空间。

### 16.3 视觉与排版方向

改尺寸交付页采用“精简通栏工作台”：

```text
改尺寸交付主卡
  源图文件夹
  交付输出文件夹
  LOGO 模板目录
  目标尺寸 / 处理模式
  [扫描源图] [开始改尺寸交付] [继续未完成] [停止]

命名规则
  固定前缀 / 起始编号 / 区域代号 / 渠道
  示例图片命名 + 生成规则说明

任务列表
  桌面端表格
  移动端卡片
```

排版要求：

- `改尺寸交付` 主卡和 `命名规则` 卡都使用通栏宽度，避免左窄右空。
- `LOGO 模板目录` 放在 `交付输出文件夹` 下方，作为交付输入的一部分，而不是单独右侧卡片。
- 不展示独立 `配置摘要` 卡片，用户需要的是可操作配置，不是重复摘要。
- 不展示 1-6 步骤条，避免页面像内部流程说明书。
- 任务列表头部只保留标题，不出现“桌面端按表格查看，移动端自动切换为任务卡片”这类解释型文案。
- 输入框内的历史按钮要小型化并靠右，不能抢占路径内容空间。
- 普通信息卡不放装饰图标，靠标题、间距、边框和按钮层级传达结构。

### 16.6 命名规则

命名规则放在改尺寸交付主卡下方，使用通栏卡片。

```text

```


不再展示示例文件夹命名，不在前端展示备用业务命名。长示例文件名要单行省略，不能撑破卡片。

### 16.7 renamePage 整合

renamePage 不做正式页面入口。

整合方式：

```text

本地标准化 -> 改尺寸交付：后台标准化能力
批量加 LOGO -> 改尺寸交付：LOGO 模板目录
批量打包文件夹 -> 改尺寸交付：后台打包能力
```

前端不单独展示 `标准化配置`、`备用业务命名`、`交付包设置`。如后续确实需要高级手动能力，应放到二级折叠或内部工具入口，默认不进入首屏。

## 23. 验收标准

### 23.1 产品成熟度

- 外部用户能理解每个页面的用途。
- 页面没有明显开发阶段文案。
- 页面没有“给自己看的 OK 图”文案。
- 页面标题和按钮符合成熟产品表达。

### 23.2 使用效率

- 高频任务首屏即可启动。
- 每页只有一个当前主动作。
- 必要配置清楚，重复摘要不抢占首屏。
- 高级配置不干扰主流程。

### 23.3 移动端

- 可完整配置和启动任务。
- 无横向滚动。
- 宽表格卡片化。
- 主操作 sticky。
- 日志抽屉可用。

### 23.4 稳定性

- 不影响现有 API。
- 不影响现有自动化函数。
- 所有页面切换正常。
- SSE 日志正常。
- 桌面端和移动端截图无明显重叠、溢出、按钮文字截断。

### 23.5 视觉与版式质量

- 页面主内容按统一栅格对齐，没有明显左窄右空或局部挤压。
- 卡片数量克制，普通信息不拆成过多小卡。
- 标题、标签、输入、按钮、任务列表之间的间距统一。
- 长路径、长文件名、长示例命名不溢出、不遮挡、不撑破布局。
- 图标数量克制，不因每张卡片都配图标而显得廉价。
- 说明性文案不过度占用首屏，能用结构表达的内容不额外写说明。
- 桌面端和移动端都要截图验收，移动端不出现横向滚动。

## 25. 最终产品观感

改造完成后，平台应给人的第一印象是：

```text
这是一个成熟的 AI 图片生产自动化系统。
```

而不是：

```text
这是一个内部开发中的自动化脚本控制台。
```

用户可以清楚看到：

- 从哪里开始
- 当前任务状态
- 哪些配置已经生效
- 哪些动作是安全的
- 哪些动作是危险的
- 任务完成后结果在哪里

这就是本次 Web 页面成熟产品化优化的核心目标。
