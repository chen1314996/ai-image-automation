> 日期：2026-06-06  
> 范围：基线收口与设计系统准备  
> 目标：在进入 24 小时创意闭环新功能前，把当前真实状态、页面入口、前端模块和后端诊断契约收口。

## 1. P0 结论

当前系统已经具备单轮自动创意、Prompt Gate、Legil creative-batch、资产入库、知识库方向/资产/反馈展示、队列恢复和运行中心聚合状态能力。

P0 不重做整站导航，不改批量产图、改尺寸、素材分析、任务方向池、配置的主流程。此阶段只把三块核心区域收口：

| 页面 | P0 定位 | 本阶段新增 |
| --- | --- | --- |
| 运行中心 | 看状态 | 系统当前阶段、系统健康摘要、P0/P1 诊断提示 |
| 创意拓展 | 跑起来 | 系统当前阶段、闭环执行入口 |
| 知识库 | 学起来 | 闭环治理入口 |

系统当前阶段在页面顶部统一展示为：

```text
L2 单轮自动
```

## 3. 数据统计口径

P0 诊断接口统一返回以下只读字段：

```text
serviceStatus
schedulerState
targetQueue
lastRun
legilResume
knowledgeCounts
policySummary
warnings
```

统计口径：

| 字段 | 口径 |
| --- | --- |
| 当前方向 | `directions.json` 中方向数量 |
| 参考图 | `reference-images.json` 中图片数量 |
| 资产 | `assets.json` 中资产数量 |
| run | `runs/*.json` 数量和最近一条 run |
| 队列 | `creative-target-queues.json` 最近队列 |
| 反馈 | `feedback.json` 数量 |
| 未评审资产 | `reviewStatus` 或 `review.status` 不在 good/normal/bad/rejected 的资产 |
| 今日产量 | `scheduler-state.json.daily.imageCount`，仅当 date 等于今日 |
| P0 异常 | 诊断 `warnings` 中 `severity === "P0"` 的数量 |

## 9. 只读诊断接口

接口：

```text
GET /api/creative-auto/diagnostics
```

返回示例：

```json
{
  "success": true,
  "schemaVersion": 1,
  "serviceStatus": {},
  "schedulerState": {},
  "targetQueue": {},
  "lastRun": {},
  "legilResume": {},
  "knowledgeCounts": {},
  "policySummary": {},
  "warnings": []
}
```

说明：

```text
route 只调用 service。
service 从 knowledge store、scheduler-state、target queue、runs、resume state 聚合。
接口不启动任务、不修改配置、不触发 Legil。
```
