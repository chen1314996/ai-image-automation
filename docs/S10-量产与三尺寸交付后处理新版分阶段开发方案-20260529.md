# S10：量产与三尺寸交付后处理新版分阶段开发方案

> 文档日期：2026-05-29  
> 项目目录：`C:\Users\dd\Desktop\项目`  
> 适用范围：替代旧版 S10「量产和后处理联动完善」的业务方案。  
> 核心变化：把系统拆成两段清晰流水线：  
> 1. 根据已有方向自动拓展创意并用 Legil 生成候选图。  
> 2. 你人工复制 OK 图到新文件夹后，系统用 Legil 为每张 OK 图生成三尺寸候选、人工挑最终图、加 LOGO、重命名并按图打包。

## 1. 已确认的业务规则

| 项目 | 新规则 |
| --- | --- |
| OK 图交接方式 | 你从量产输出中人工挑选 OK 图，**复制**到新的「待交付后处理输入文件夹」。不移动、不破坏原量产目录。 |
| 三尺寸目标 | 每张 OK 图最终必须有 `800x800`、`1280x720`、`1080x1920` 三个尺寸。 |
| 三尺寸生成方式 | 不是本地简单裁切或拉伸，而是优先用 **Legil 图生图**进行画面适配和构图调整。 |
| 候选数量 | 每张 OK 图的每个尺寸生成 `2-4` 张候选，由你挑选 1 张作为最终交付图。第一版建议默认每尺寸 4 张，可配置为 2/3/4。 |
| LOGO | 三个尺寸都需要加 LOGO，并且有三个不同尺寸的 LOGO 模板。 |
| 平台取舍 | 三尺寸适配只保留 **Legil**，去掉即梦相关入口和流程。 |
| 创意拓展入口 | 去掉创意拓展页的「手动表格模式」，按新版自动拓展和提示词池流程精简。 |
| 文件夹命名 | 每张图一个交付文件夹，文件夹名和图片命名主体一致，但文件夹名不带最后的尺寸后缀。 |
| 图片命名 | 最终图片固定带尺寸后缀：`_800x800`、`_1280x720`、`_1080x1920`。 |
| 文件体积 | 三个尺寸最终图都需要小于 `390KB`。 |
| 最终交付 | 每张 OK 原图对应一个文件夹，文件夹里放 3 张最终图。 |

## 2. 新版 S10 总体业务逻辑

新版 S10 拆成两个互不混淆的流水线。

### 2.1 流水线 A：自动创意量产

目标：根据已有方向自动拓展创意，批量生成候选图，并保存到本地。

```text
已有方向 / 素材分析方向 / 提示词池
  -> 自动拓展创意提示词
  -> Prompt Gate 质检
  -> Prompt 翻译或标准化
  -> Legil 批量生成候选图
  -> 保存到本地量产输出文件夹
  -> 可选登记到资产库
  -> 你人工浏览本地输出
  -> 你把 OK 图复制到待交付后处理输入文件夹
```

这一段只负责探索和出候选图，不负责最终交付。不应该自动把所有量产图都送去三尺寸处理。

### 2.2 流水线 B：OK 图三尺寸交付后处理

目标：把你人工挑出的 OK 图变成可交付的三尺寸文件夹。

```text
你复制 OK 图到待交付后处理输入文件夹
  -> 系统扫描 OK 图
  -> 每张 OK 图建立一个 delivery job
  -> 每张图 x 3 个目标尺寸
  -> 每个尺寸用 Legil 生成 2-4 张候选
  -> 你从每个尺寸候选中选 1 张
  -> 本地标准化到精确像素和 390KB 以内
  -> 按尺寸加对应 LOGO 模板
  -> 按命名规则重命名
  -> 每张 OK 图打包成一个文件夹
  -> 生成 manifest，记录原图、候选图、最终图和处理状态
```

这一段是 S10 的交付核心。

## 3. 术语调整

旧系统里「改尺寸」容易误导。新版建议改成三个层次：

| 名称 | 含义 | 是否主流程 |
| --- | --- | --- |
| AI 三尺寸适配 | 用 Legil 图生图生成适合目标比例的新画面。会重新构图、补画面、适配横竖版。 | 是 |
| 本地标准化 | 用本地图片处理把 AI 输出校准成精确像素、格式、体积。 | 是 |
| 本地简单改尺寸 | 只缩放、裁切或压缩，不理解画面。 | 仅作为兜底工具保留 |

以后页面上不建议继续把主流程叫「改尺寸」，建议改为：

```text
三尺寸交付
或
OK 图交付包
或
AI 三尺寸适配
```

## 7. 状态设计

### 7.1 run 状态

| 状态 | 含义 |
| --- | --- |
| `idle` | 未开始 |
| `scanned` | 已扫描输入文件夹 |
| `running` | 正在生成候选或后处理 |
| `waiting_selection` | 候选已生成，等待人工选择最终图 |
| `finalizing` | 正在标准化、加 LOGO、重命名、打包 |
| `completed` | 完成 |
| `stopped` | 人工停止，可继续 |
| `failed` | 失败，可查看错误 |

### 7.2 target 状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 待处理 |
| `generating` | 正在用 Legil 生成候选 |
| `candidates_ready` | 候选已生成 |
| `candidate_selected` | 已选择最终候选 |
| `standardized` | 已标准化为精确尺寸和体积 |
| `logo_applied` | 已加对应尺寸 LOGO |
| `finalized` | 已重命名并进入交付文件夹 |
| `failed` | 当前尺寸失败 |

## 8. API 设计建议

### 8.1 三尺寸交付 API

| Endpoint | Method | 说明 |
| --- | --- | --- |
| `/api/delivery/scan` | POST | 扫描 OK 图输入文件夹，创建或刷新 delivery run。 |
| `/api/delivery/start` | POST | 开始 Legil 三尺寸候选生成。 |
| `/api/delivery/stop` | POST | 停止当前 delivery run。 |
| `/api/delivery/resume` | POST | 从未完成的 job/target 继续。 |
| `/api/delivery/status` | GET | 获取当前运行状态。 |
| `/api/delivery/runs` | GET | 查看历史 delivery runs。 |
| `/api/delivery/runs/:runId` | GET | 查看单次 delivery run 详情。 |
| `/api/delivery/runs/:runId/select-candidate` | POST | 为某个 job 的某个尺寸选择最终候选。 |
| `/api/delivery/runs/:runId/finalize` | POST | 对已选候选执行标准化、加 LOGO、重命名、打包。 |
| `/api/delivery/runs/:runId/retry-target` | POST | 重跑某张图的某个尺寸。 |
| `/api/delivery/runs/:runId/retry-job` | POST | 重跑某张 OK 图缺失或失败的尺寸。 |

### 8.2 旧接口处理建议

| 旧接口/能力 | 新处理 |
| --- | --- |
| `/api/legil/resize-batch` | 不再作为主入口。可作为 delivery 内部调用或后续废弃。 |
| `/api/jimeng/*` | 从页面和主流程移除。服务代码可后续集中删除。 |
| `/api/resize-images/*` | 改名或降级为本地标准化内部工具。 |
| `/api/rename-images/*` | 可继续复用命名规则，但最终应由 delivery manifest 驱动。 |
| `/api/package-images/*` | 可继续复用文件复制能力，但分组应由 delivery job 驱动，而不是只靠文件名后缀猜。 |

## 9. Legil 三尺寸适配提示词建议

通用提示词模板建议：

```text
请基于输入图片进行图生图改造，保留主体、题材、情绪、核心卖点和可读性。
不要简单拉伸或裁切。请根据目标画幅重新构图，适当扩展背景、补足空间、调整主体位置。
保持广告素材风格清晰，主体关系明确，避免文字乱码和主体变形。
目标尺寸：{{targetSize}}
```

`800x800` 模板补充：

```text
适配正方形广告图。主体居中偏稳，核心动作和冲突关系必须在第一眼可见。
```

`1280x720` 模板补充：

```text
适配横版广告图。允许横向扩展背景和动作空间，主体不要过小，画面左右信息保持均衡。
```

`1080x1920` 模板补充：

```text
适配竖版广告图。主体和关键动作应位于中上区域，保留竖屏浏览的视觉冲击，避免重要元素贴边。
```

## 10. 分阶段开发计划

### S10.1：业务收口与页面精简

目标：先把页面和业务入口改对。

开发任务：

| 任务 | 说明 |
| --- | --- |
| 导航精简 | 保留量产、创意拓展、知识库、素材分析、三尺寸交付、配置。 |
| 移除即梦主入口 | 从页面移除即梦改尺寸相关入口，避免误用。 |
| 移除创意拓展手动表格模式 | 创意拓展只保留自动方向和提示词池到 Legil 量产。 |
| 新增三尺寸交付页面骨架 | 先做输入输出、目标尺寸、候选数量、LOGO 模板、命名规则、任务列表。 |
| 文案统一 | 把主流程里的「改尺寸」改为「AI 三尺寸适配」或「三尺寸交付」。 |

验收标准：

```text
页面上能清楚区分：
1. 自动创意量产
2. OK 图三尺寸交付

看不到即梦主流程入口；
看不到创意拓展手动表格量产入口；
三尺寸交付页面能填写输入文件夹、输出文件夹、LOGO 模板和命名规则。
```

### S10.2：扫描 OK 图与 delivery run 状态

目标：先不调用 Legil，只把本地 OK 图文件夹变成可追踪任务。

开发任务：

| 任务 | 说明 |
| --- | --- |
| 新增 delivery store | 写入 `data/delivery-postprocess/`。 |
| 扫描输入文件夹 | 读取 OK 图，建立 run 和 job。 |
| 生成 baseName | 根据命名规则为每张图生成图片命名主体和文件夹名。 |
| 页面任务列表 | 展示每张 OK 图和三个尺寸状态。 |
| 防重复扫描 | 同一输入文件可识别已存在 job，避免重复建组。 |

验收标准：

```text
你复制 5 张 OK 图到输入文件夹；
点击扫描；
页面显示 5 个 job；
每个 job 都有 800x800、1280x720、1080x1920 三个 pending target；
每个 job 已生成不带尺寸后缀的 baseName。
```

### S10.3：Legil 三尺寸候选生成

目标：每张 OK 图的每个尺寸用 Legil 生成 2-4 张候选。

开发任务：

| 任务 | 说明 |
| --- | --- |
| Legil 图生图适配封装 | 复用现有 Legil automation，只保留 Legil。 |
| 目标尺寸映射 | `800x800 -> 1:1`，`1280x720 -> 16:9`，`1080x1920 -> 9:16`。 |
| 候选数量配置 | 每尺寸 2/3/4 张，默认 4 张。 |
| 分尺寸提示词模板 | 通用模板 + 尺寸专用模板。 |
| 状态更新 | 每个 target 独立记录生成中、候选完成、失败。 |
| 失败可继续 | 中断后只重跑缺失或失败 target。 |

验收标准：

```text
选择 1 张 OK 图；
每个尺寸生成 2-4 张候选；
页面能看到候选图；
候选图是 AI 重新适配画面，不是本地简单裁切；
失败后能只补跑失败尺寸。
```

### S10.4：人工选择最终候选

目标：你从每个尺寸候选中选 1 张作为最终交付图。

开发任务：

| 任务 | 说明 |
| --- | --- |
| 候选图库 | 每个 job 下按尺寸展示候选。 |
| 单选最终图 | 每个尺寸只能选 1 张。 |
| 选择状态持久化 | 写入 delivery job 的 `selectedCandidateId`。 |
| 缺选提醒 | 未选满三个尺寸时不允许 finalize。 |
| 快捷预览 | 支持查看大图或打开本地文件。 |

验收标准：

```text
一张 OK 图有三个尺寸候选区；
你能为每个尺寸选一张；
选中状态刷新页面后仍然存在；
未选满三个尺寸时，系统提示不能生成最终交付包。
```

### S10.5：本地标准化到精确尺寸和 390KB

目标：把选中的 AI 候选图处理成精确尺寸、JPG、390KB 以内。

开发任务：

| 任务 | 说明 |
| --- | --- |
| 精确尺寸输出 | 生成 `800x800`、`1280x720`、`1080x1920`。 |
| JPG 输出 | 默认最终格式 JPG。 |
| 体积控制 | 三个尺寸都压缩到 `390KB` 以内。 |
| 质量下限 | 沿用现有最低质量 60，可配置。 |
| 失败标记 | 如果压缩到最低质量仍超过 390KB，标记失败并提示。 |

验收标准：

```text
选中候选后点击标准化；
输出图像素精确匹配三个目标尺寸；
三个文件都小于 390KB；
如果无法压到 390KB，页面能说明是哪张图失败。
```

### S10.6：三尺寸 LOGO 叠加

目标：三个尺寸分别加对应尺寸 LOGO 模板。

开发任务：

| 任务 | 说明 |
| --- | --- |
| LOGO 模板配置 | 分别配置 `800x800`、`1280x720`、`1080x1920` 模板。 |
| LOGO 尺寸校验 | 模板尺寸应与目标图一致，避免错贴。 |
| 叠加方式 | 第一版使用模板原样覆盖。 |
| 加 LOGO 后体积控制 | 加 LOGO 后仍需小于 390KB。 |
| 状态记录 | 每个 target 记录 `logo_applied`。 |

验收标准：

```text
三个尺寸能分别贴对应 LOGO；
错传 LOGO 尺寸时系统拒绝并提示；
加 LOGO 后仍满足 390KB；
原始 AI 候选图不被覆盖。
```

### S10.7：重命名与按图打包

目标：生成最终交付目录。

开发任务：

| 任务 | 说明 |
| --- | --- |
| 文件夹名生成 | 文件夹名等于图片命名主体，不带尺寸后缀。 |
| 图片名生成 | 图片名等于图片命名主体 + 固定尺寸后缀。 |
| 每图一个文件夹 | 每个 job 一个最终文件夹。 |
| 三尺寸完整性检查 | 缺任意尺寸，不允许标记为完成。 |
| batch manifest | 输出整批 `batch-manifest.json`。 |
| 单图 manifest | 每个文件夹输出 `manifest.json`。 |

验收标准：

```text
每张 OK 原图生成一个文件夹；
文件夹里必须有：
_800x800.jpg
_1280x720.jpg
_1080x1920.jpg

文件夹名不带尺寸后缀；
图片名固定带尺寸后缀；
缺尺寸时不打包或标记为未完成。
```

### S10.8：恢复、补跑与最终验收

目标：让交付后处理可安全中断和继续。

开发任务：

| 任务 | 说明 |
| --- | --- |
| run 恢复 | 服务重启后能读取上次 delivery run。 |
| target 补跑 | 只补跑失败或缺失尺寸。 |
| job 补跑 | 一张 OK 图可整体补跑三个尺寸。 |
| finalize 补跑 | 已选候选后，可只补标准化/LOGO/打包。 |
| 验收报告 | 输出本次交付数量、完成数量、失败数量、缺失尺寸。 |

验收标准：

```text
任务中断后继续，不重复跑已完成尺寸；
失败 target 能单独重试；
已完成 job 不被重复覆盖；
最终报告能说明哪些图已完成、哪些图缺尺寸、哪些图超体积或生成失败。
```

## 11. 第一版最小可用范围

为了尽快跑通，第一版建议只做这些：

```text
1. 新增三尺寸交付页面。

5. 页面人工选择每尺寸 1 张。
6. 本地标准化到精确尺寸和 390KB。
7. 三尺寸加对应 LOGO。
8. 重命名。
9. 每张图一个文件夹打包。
10. 支持停止和继续。
```

暂缓内容：

```text

2. 自动判断候选好坏。
3. 多平台适配，尤其即梦。
4. 多渠道不同体积规则。
5. 自动从资产库筛选好图进入交付。
```
