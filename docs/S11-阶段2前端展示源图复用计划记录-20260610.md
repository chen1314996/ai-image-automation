# S11 阶段 2：前端展示源图复用计划记录

> 日期：2026-06-10  
> 对应方案：`docs/S11-源比例复用与逐张闭环三尺寸交付分阶段开发方案-20260610.md`  
> 阶段目标：交付页面清楚展示哪些 target 会复用源图，哪些 target 需要 Legil，避免 source-reuse target 被误看成“待生成”。

---

## 1. 本阶段完成内容

### 1.1 扫描汇总展示 source-reuse 数量

调整文件：

```text
public/js/delivery-page.js
```

`setDeliveryInfoForRun()` 现在会读取阶段 1 新增的 scan 字段：

```text
run.scan.sourceReuseTargetCount
run.scan.legilTargetCount
run.scan.estimatedSavedTargetCount
```

扫描后信息框会展示类似：

```text
源图复用 3 个 target，需 Legil 9 个 target，预计节省 3 个 target
```

同时把原来的“复用/新增”改成“历史复用/新增”，避免和“源图复用”混淆。

### 1.2 target cell 显示源图复用

`renderDeliveryTargetCell()` 新增 source-reuse 分支。

source-reuse target 会显示：

```text
源图复用
1:1 · 1/1 张
跳过 Legil · 源图 800x800
```

候选缩略图标签从普通的：

```text
候选 1
```

改为：

```text
源图
```

### 1.3 target cell 显示跳过 Legil

当 target 满足：

```text
target.generationMode === "source-reuse"
或 target.reuseSource === true
```

页面会明确显示：

```text
跳过 Legil
```

并且状态 pill 使用 `source-reuse` 专属样式，不再显示成 `pending` 或 `candidate_selected`。

### 1.4 保留 Legil 候选数量展示

Legil target 继续显示候选进度：

```text
Legil 候选 0/4 张
```

source-reuse target 的期望候选数固定为 `1`，不会在任务总候选数里按 `4` 张计算。

新增前端 helper：

```text
isDeliverySourceReuseTarget()
getDeliveryTargetExpectedCandidateCount()
getDeliveryTargetStatusLabel()
```

### 1.5 完整交付按钮文案调整

按钮文案从：

```text
开始完整改尺寸并生成交付包
```

调整为：

```text
开始逐张生成三尺寸交付包
```

流程提示从：

```text
完整交付会自动标准化、加 LOGO 并输出 final-package
```

调整为：

```text
完整交付会逐张闭环输出 final-package
```

启动任务时的信息框也改为：

```text
已提交逐张闭环三尺寸交付任务：后端会完成一张输出一张...
```

## 6. 后续阶段注意点

阶段 2 只完成前端计划展示，不改变后端完整交付执行顺序。

下一阶段建议进入：

```text
阶段 3：完整交付改为 job 闭环执行
```

阶段 3 需要让后端真正做到：

```text
当前 OK 图三尺寸齐备后
  -> 立即标准化当前 job
  -> 立即 finalize 当前 job
  -> 输出当前 job 的 final-package 文件夹
  -> 再进入下一张 OK 图
```
