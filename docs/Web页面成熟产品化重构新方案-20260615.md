# Web页面成熟产品化重构新方案-20260615

## 1. 方案定位

本方案用于指导当前 AI 生图自动化平台的 Web 界面继续产品化升级。参考当前已经相对成熟的三个页面：

- 运行中心
- 批量产图
- 改尺寸

后续优化重点不是重新发明一套视觉风格，而是把其它页面接入这三页已经形成的成熟产品语言：深色生产工作台、紧凑导航、清晰状态、通栏主任务卡、单一主操作、可追踪任务进度、可交付给他人使用的界面表达。

旧方案的问题不在方向错误，而在表达过于“列表化”和“文档化”：覆盖很多点，但没有形成足够明确的设计抓手。新的方案更强调：

- 从真实使用任务出发，而不是从功能模块堆叠出发。
- 从首屏判断效率出发，而不是从页面内容完整度出发。
- 从统一设计系统出发，而不是逐页局部修补。
- 从成熟产品交付标准出发，而不是开发调试台标准。

目标状态：

```text
用户第一次打开平台，就能判断：
这是什么产品、当前能不能运行、我要从哪里开始、任务完成后结果在哪里、异常时应该怎么处理。
```

一句话产品定位：

```text
AI 图片生产自动化工作台
```

更完整的产品表达：

```text
围绕创意方向、素材反馈、方案整理、批量生图、资产审核和多尺寸交付，提供从创意生成到图片交付的自动化生产能力。
```

### 1.1 本方案的评审视角

本方案按四类专业视角共同约束：

- 10 年以上互联网产品经理视角：先定义用户任务、业务链路、页面优先级和可交付标准，避免把页面做成内部功能清单。
- UI/UX 设计视角：统一用户路径、状态反馈、主次操作、空状态、移动端任务流和异常处理。
- Web 界面设计视角：统一导航、栅格、组件、响应式、交互状态和可复用样式 token。
- 平面设计视角：控制版式重心、视觉节奏、对齐关系、信息密度、文字层级和页面整体完成度。

四个视角合在一起，最终只服务一个判断：这个平台能否被一个非开发人员稳定、清晰、放心地使用。

## 2. 设计总方向

### 2.1 产品气质

建议统一为：

```text
暗色专业生产工作台 + 轻量资产管理系统
```

不是营销落地页，不是数据大屏，不是开发控制台，也不是只给自己看的脚本面板。

产品气质关键词：

- 稳定
- 清晰
- 高效
- 可控
- 可交付
- 工作台型
- 适合长期重复使用

页面要让人感觉这是一个“生产系统”，不是一个“把按钮都摆出来的工具合集”。

### 2.2 视觉基调

沿用当前成熟页面的深色体系，但需要进一步收口：

```text
背景：深黑灰
主面板：深灰绿 / 深蓝灰
边框：低饱和灰蓝
主操作：低饱和青绿
信息强调：清晰蓝
成功：绿色
警告：琥珀色
危险：柔红色
禁用：灰色
```

避免：

- 多套渐变混用
- 卡片过多发光
- 每个模块都配图标
- 页面被单一青绿色淹没
- 顶部品牌区过高
- 首屏像说明书

### 2.3 平面设计原则

从平面设计角度，每页必须满足四个版式要求：

1. 视觉重心明确  
   首屏只能有一个最强动作。其它按钮必须降级为次按钮、文字按钮、折叠项或菜单。

2. 栅格稳定  
   主内容宽度、卡片边界、表单字段、按钮组、状态条尽量落在同一套栅格线上，避免左窄右空、局部拥挤。

3. 信息密度服务工作效率  
   这是生产工作台，不需要大面积留白和营销式 hero，但也不能把所有指标挤成开发面板。关键是“可扫读”。

4. 长文本必须被设计  
   Windows 路径、文件名、提示词、任务 ID、模型名都可能很长。必须统一使用截断、省略、换行、tooltip、抽屉详情，而不是让文字撑破卡片。

## 3. 总体体验模型

所有页面统一按下面的信息顺序组织：

```text
页面用途
当前可用状态
关键输入 / 输出
必要参数
主操作
当前任务 / 结果
高级配置 / 历史 / 日志
```

不要把“流程说明”放在首屏占空间。成熟产品应通过表单、状态、按钮、任务列表表达流程。

## 4. 全局页面骨架

### 4.1 桌面端结构

推荐所有页面使用同一套骨架：

```text
顶部产品栏
  品牌名 / 当前页面说明 / 分组导航

全局状态条
  浏览器状态 / Winky 状态 / 生图平台状态 / 最近异常

页面标题区
  页面名 / 一句话用途 / 页面级辅助操作

主任务区
  当前页面最重要的输入、输出、参数和主按钮

状态与结果区
  当前任务、进度、队列、列表、资产、分析结果

辅助区
  高级配置、历史任务、日志、同步记录
```

运行中心、批量产图、改尺寸已经基本符合这个方向，其它页面应向这套骨架靠拢。

### 4.2 移动端结构

移动端不是桌面端缩小版。移动端要采用单列任务流：

```text
顶部栏：当前页面 + 页面切换 + 状态入口
主内容：输入输出 -> 参数 -> 主操作 -> 结果
底部 sticky：当前主操作 / 运行控制
日志：抽屉
表格：卡片化
```

移动端必须完整支持：

- 页面切换
- 路径配置
- 参数配置
- 启动任务
- 暂停、继续、停止任务
- 查看进度
- 查看日志
- 查看结果

## 5. 从成熟页面抽取的设计规则

### 5.1 运行中心的可复用规则

运行中心做对了这些事情：

- 顶部说明克制，不抢主内容。
- 状态条直接告诉用户系统是否可用。
- 用指标卡展示全局状态、阶段、执行模块、更新时间。
- 当前任务和生图队列拆成两个高价值面板。
- 操作按钮集中，不散落在每张卡里。

应抽取为通用组件：

```text
ProductHeader
GlobalStatusStrip
MetricGrid
TaskStatusCard
QueueStatusCard
TaskControlBar
```

### 5.2 批量产图的可复用规则

批量产图做对了这些事情：

- 默认模式明确：参考图自动产图。
- 文件夹路径、任务状态、主操作在同一工作面内。
- 表格提示词产图降级为次级模式。
- Legil 参数不抢首屏主流程。
- 页面像一个“能马上开工”的生产入口。

应抽取为通用组件：

```text
ModeTabs
PrimaryTaskSurface
FolderField
MiniTaskStatus
ParameterSummary
PrimaryActionRow
AdvancedConfigDetails
```

### 5.3 改尺寸页面的可复用规则

改尺寸页面做对了这些事情：

- 源图、输出、LOGO、尺寸、模式构成清晰的交付主链路。
- 命名规则放在主任务下方，不拆成无意义的零散卡片。
- 高级处理能力不喧宾夺主。
- 长路径和历史按钮处理较成熟。
- 移动端有底部主操作意识。

应抽取为通用组件：

```text
DeliverySetupCard
NamingRulePanel
SizeSelector
ProcessModeSelector
TaskTableDesktop
TaskCardsMobile
StickyMobileActionBar
```

## 6. 全局组件规范

### 6.1 卡片层级

卡片分三层，不要无限增加卡片类型。

一级卡片：主任务卡  
用于页面最关键的输入、输出和主操作。每页最多 1 张。

二级卡片：结果 / 状态卡  
用于当前任务、任务队列、资产列表、分析结果。每页 2 到 4 张。

三级卡片：局部信息块  
用于小指标、标签、单条记录、缩略图。可以重复，但必须保持统一尺寸和密度。

不建议：

- 卡片套卡片
- 每个小功能都拆一张大卡
- 同一页面出现 6 张以上同权重大卡
- 标题卡、说明卡、摘要卡同时存在

### 6.2 按钮层级

每页当前状态下只允许一个主按钮。

主按钮示例：

```text
开始自动产图
开始创意拓展
导入素材数据
开始整理任务
开始改尺寸交付
保存配置
```

次按钮示例：

```text
扫描
刷新
预览
浏览
复制
导出
打开平台
查看日志
```

危险按钮示例：

```text
停止任务
清除任务
删除记录
覆盖输出
```

按钮不使用 emoji。图标如果要用，优先用于危险、状态、导航和工具按钮，不为普通卡片标题强行加图标。

### 6.3 状态设计

全局状态和任务状态必须统一语义：

| 状态 | 颜色 | 文案示例 |
|---|---|---|
| 可用 | 绿色 | 已配置 / 已连接 / 可运行 |
| 运行中 | 蓝色 | 运行中 / 正在扫描 / 正在生成 |
| 等待 | 琥珀色 | 等待响应 / 等待审核 / 队列中 |
| 异常 | 红色 | 连接失败 / 任务失败 / 需要处理 |
| 未开始 | 灰色 | 未启动 / 暂无任务 / 未导入 |

避免大面积出现：

```text
--
读取中
暂无
unknown
undefined
```

空状态应该告诉用户下一步：

```text
还没有素材数据。请先导入素材表，系统会生成 Top 素材、方向表现和创意机会。
```

### 6.4 表格与列表

桌面端：

- 数据密集内容用表格。
- 表格必须有 sticky 表头。
- 宽表格允许横向滚动，但页面整体不能横向滚动。
- 关键操作列固定在右侧或放入行内菜单。

移动端：

- 宽表格必须卡片化。
- 每张卡片展示 3 到 5 个关键字段。
- 详情通过抽屉或展开区域查看。

### 6.5 日志

日志是辅助信息，不是主界面。

统一策略：

- 桌面端默认收起或半收起。
- 任务运行中可显示轻量日志摘要。
- 完整日志通过抽屉、弹层或底部展开查看。
- 移动端日志必须默认抽屉化。

## 7. 页面级重构方案

## 7.1 自动化策略

### 页面定位

自动化策略不是“权限矩阵配置页”，而是“系统自动执行边界和异常保护中心”。

页面标题：

```text
自动化策略
```

副标题：

```text
控制系统可自动执行的操作范围、运行阈值和异常保护策略。
```

### 首屏结构

```text
策略总览卡
  当前自动化等级
  可自动执行范围
  当前保护状态
  最近一次策略变更

主操作
  [保存策略]

策略配置区
  自动化等级
  执行权限
  异常保护
  运行阈值
```

### 交互建议

自动化等级使用分段控件：

```text
手动确认 / 辅助自动 / 全自动
```

权限项使用开关，不要用过重表格铺满首屏。

阈值项使用紧凑输入组：

```text
连续失败次数
单任务超时时间
队列最大长度
低置信度暂停阈值
```

异常保护用“规则卡片”展示：

```text
连接失败：暂停当前任务，提示检查登录状态
输出异常：保留中间结果，等待人工确认
图片保存失败：重试 2 次后进入待处理
```

### 视觉调整重点

- 首屏强调“当前策略是否安全”，不要让用户先看到配置细节。
- 保存策略是唯一主按钮。
- 事件记录放到底部，不占首屏。
- 内部词如 Policy Guard 可作为帮助说明，不做主标题。

## 7.2 创意拓展

### 页面定位

创意拓展是生产链路的策源地，用于从方向库、参考图和任务要求生成可执行提示词，并送入生图。

页面标题：

```text
创意拓展
```

副标题：

```text
基于方向库和参考资料生成创意提示词，并提交生图任务。
```

### 首屏结构

```text
创意任务卡
  方向来源
  参考资料
  生成数量
  提示词质检
  输出位置

右侧状态摘要
  当前任务
  已选方向
  待生成提示词
  待提交生图

主操作
  [开始创意拓展]
```

### 页面分区

1. 方向选择  
   方向库状态、推荐方向、已选方向、搜索筛选。

2. 提示词质检  
   生成后展示质检通过率、问题提示词、修正入口。

3. 生图执行  
   展示队列、当前提示词、保存进度、失败重试。

4. 结果审核  
   生成图片、采纳、驳回、沉淀到知识库。

### 视觉调整重点

- 去掉口语化按钮，例如“跑起来”。
- Prompt Gate 显示为“提示词质检”，Prompt Gate 可作为括号说明或 tooltip。
- 历史 run 改为“历史任务”。
- Run ID 改为“任务 ID”。
- 不要让 Legil 参数默认占据主视觉，放入“生图参数”折叠区。
- 运行进度在桌面端可右侧 sticky，在移动端放入底部运行条。

### 推荐布局

桌面端：

```text
左侧 60%：方向、参考资料、提示词生成配置
右侧 40%：当前任务、质检结果、生图队列
底部：历史任务与结果审核
```

移动端：

```text
方向来源
参考资料
生成设置
开始创意拓展
任务进度
结果审核
```

## 7.3 素材分析

### 页面定位

素材分析是数据反馈入口，用于导入投放素材数据，识别高消耗素材、表现趋势和后续创意机会。

页面标题：

```text
素材分析
```

副标题：

```text
导入投放素材数据，识别高消耗素材、表现趋势和创意机会。
```

### 未导入状态

未导入数据时，不展示大量空表格和空指标。首屏只展示：

```text
导入素材数据卡
  素材表路径 / 文件选择
  数据月份 / 渠道
  分析目标

[导入素材数据]

历史导入
```

### 导入后状态

导入后页面展示：

```text
数据概览
  素材数
  消耗
  ROI 健康度
  高潜素材数

分析摘要
  方向表现
  Top 素材
  风险素材
  创意机会

后续动作
  送入方案迭代
  送入创意拓展
  沉淀到知识库
```

### 视觉调整重点

- Top 素材尽量展示缩略图，纯表格会削弱“图片生产平台”的产品感。
- 数据图表保持克制，重点是决策结论，不做大屏风。
- 未导入前隐藏分析结果区或显示锁定空状态。
- 移动端 Top 素材、方向表现、创意机会全部卡片化。

### 推荐文案替换

```text
TOP100 素材逐张拓展 -> Top 素材创意拓展
本地沉淀 -> 数据沉淀
D0 ROI 健康度优先目标 -> ROI 健康度
生成拓展提示词池 -> 生成创意提示词
```

## 7.4 方案迭代

### 页面定位

方案迭代是人工任务表到自动化生产任务的转换器。

页面标题建议：

```text
方案迭代
```

页面内主标题可以更具体：

```text
任务表整理
```

副标题：

```text
导入方案任务表，整理方向、参考图和执行要求，形成可送入创意拓展的生产任务。
```

### 首屏结构

```text
任务表导入卡
  文件路径 / 上传
  表格识别状态
  字段匹配状态

任务整理状态
  总行数
  已识别方向
  缺少参考图
  可执行任务

主操作
  [导入任务表] 或 [开始整理任务]
```

### 页面分区

1. 导入任务表  
   支持文件选择、最近导入、字段识别。

2. 任务整理  
   行级状态、方向提取、参考图匹配、风险提示。

3. 方向池  
   多选、筛选、批量送入创意拓展。

4. 执行记录  
   已送入任务、失败原因、重新整理。

### 视觉调整重点

- “方案迭代”不是月度专属，不再出现“月度方案迭代”作为主页面名。
- 表格导入前隐藏复杂方向池。
- 禁用按钮必须写清楚解锁条件。
- 方向池桌面端可以三栏：分组、方向列表、详情；移动端必须卡片化。
- 从素材分析进入时，可以显示来源提示，但不要做成大面积说明卡。

## 7.5 知识库

### 页面定位

知识库不是文档集合，而是创意资产、方向体系、审核反馈和经验规则的沉淀中心。

页面标题：

```text
知识库
```

副标题：

```text
管理方向体系、生成资产、审核反馈和创意经验沉淀。
```

### 推荐页内导航

```text
总览
资产审核
方向库
经验规则
飞书同步
运行记录
```

默认建议打开“资产审核”或“总览”，不要让飞书协同占据首屏主体。

### 总览结构

```text
知识库总览
  方向数
  资产数
  待审核
  本周沉淀

待处理事项
  待审核资产
  待归类方向
  待同步记录

最近沉淀
  新方向
  新规则
  新资产
```

### 资产审核结构

桌面端：

```text
左侧筛选栏
  状态 / 来源 / 方向 / 日期

中间资产网格
  图片缩略图 / 方向 / 状态 / 关键标签

右侧详情抽屉
  大图 / 提示词 / 审核动作 / 反馈记录
```

移动端：

```text
筛选按钮
资产卡片列表
点击进入详情抽屉
底部审核动作
```

### 视觉调整重点

- 知识库必须多展示图片资产，避免成为纯文本后台。
- 审核动作要清晰：采纳、待修改、驳回、沉淀规则。
- Visual DNA 可改为“视觉经验沉淀”。
- “学起来”等口语化文案移除。
- 飞书同步是协同能力，不应默认压过资产审核。

## 7.6 全局配置

### 页面定位

配置页是系统设置，不是开发参数页。

页面标题建议：

```text
配置
```

页面内主标题：

```text
全局配置
```

副标题：

```text
管理提示词模型、通知策略、运行监控和默认生图参数。
```

### 首屏结构

```text
配置健康卡
  Winky：已配置 / 未配置
  生图平台：可连接 / 未连接
  浏览器：可用 / 未启动
  通知：已开启 / 未开启

主操作
  [保存配置]
```

### 配置分组

1. 模型配置  
   Lumos Winky API、模型、Provider、视觉能力说明。

2. 生图默认参数  
   默认模型、比例、数量、参考图策略。注意：具体任务页仍可覆盖。

3. 通知策略  
   任务完成、任务失败、需要人工处理。

4. 运行监控  
   Watchdog、异常检测、自动恢复。

5. 高级连接  
   API Base URL、超时、重试、调试开关。默认折叠。

### 视觉调整重点

- 强化配置是否可用，而不是先暴露字段。
- 所有密钥输入必须有保存状态、是否已配置的可信提示。
- 高级连接默认折叠。
- 不新增 Volcengine / Ark / Doubao LLM 配置入口；LLM 能力统一表达为 Lumos Winky。

## 10. 实施阶段

### 阶段 1：设计系统收口

目标：把已经成熟的运行中心、批量产图、改尺寸页面经验抽象为通用样式。

任务：

1. 整理全局 token：颜色、圆角、边框、字号、间距。
2. 抽取通用组件 class：状态条、主任务卡、路径输入、指标卡、任务卡、折叠配置、日志抽屉。
3. 统一按钮层级。
4. 统一空状态、加载状态、错误状态。
5. 统一移动端 sticky 主操作。

验收：

- 三个成熟页面视觉不倒退。
- 其它页面可以直接复用相同组件。
- CSS 不再靠大量页面级覆盖维持一致性。

### 阶段 2：自动化策略与配置页先收口

原因：这两个页面相对不依赖图片资产，适合先建立“系统类页面”的标准。

任务：

1. 自动化策略改为策略总览 + 权限配置 + 异常保护 + 阈值配置。
2. 配置页改为健康状态 + 模型配置 + 默认参数 + 通知 + 监控 + 高级连接。
3. 删除内部术语主标题。
4. 高级配置默认折叠。

验收：

- 用户能第一眼判断系统是否配置可用。
- 页面只有一个主按钮。
- 移动端能保存配置、调整策略。

### 阶段 3：创意拓展、素材分析、方案迭代重构

原因：这三页是生产前半段链路，应一起形成“从方向到任务”的连续体验。

任务：

1. 创意拓展建立方向选择、提示词质检、生图执行、结果审核结构。
2. 素材分析建立未导入 / 已导入两种状态。
3. 方案迭代建立任务表导入、字段识别、方向池、送入创意拓展结构。
4. 页面之间建立轻量来源提示，比如“来自素材分析的 12 个创意机会”。

验收：

- 用户能理解生产链路：素材反馈 -> 方案整理 -> 创意拓展 -> 批量产图。
- 未导入状态不显示大面积空数据。
- 移动端表格全部卡片化。

### 阶段 4：知识库与方向库资产化收口

原因：创意拓展页已经明确了“方向库选择 -> 待拓展方向队列 -> 生图参数 -> 运行进度”的生产入口形态，知识库不能只做后台资料堆放，而要成为创意拓展可直接调用的资产来源。阶段 4 的重点是把方向、素材、审核结果和经验规则沉淀成可筛选、可选择、可送入任务的产品资产。

任务：

1. 重构知识库信息架构为：资产总览、资产审核、方向库、经验规则、同步记录、运行记录。
2. 方向库改为可生产化使用的选择系统，支持按来源、状态、标签、表现、更新时间筛选，并保留“选择当前筛选全部内容 / 清空选择 / 反选”等批量操作。
3. 方向名称、已选内容、来源提示全部使用中文业务表达，不再暴露英文状态值、内部字段名和开发命名。
4. 方向库与创意拓展建立轻量联动提示，例如“来自知识库的 24 个可拓展方向”“已选 8 个方向，可送入创意拓展”。
5. 资产审核默认突出图片资产、方向标签、审核状态、来源任务和可沉淀动作，不把飞书同步、运行日志放在默认首屏主区域。
6. 资产列表图片化，桌面端使用缩略图网格或图文列表，移动端使用资产卡片；不再用纯表格承载图片生产资产。
7. 详情使用右侧抽屉或移动端底部抽屉，审核动作固定在详情操作区底部，避免按钮散落在每个小模块里。
8. 高级信息、同步记录、运行记录默认折叠，折叠按钮统一为右侧小按钮，并保证点击后从当前位置向下展开，不发生页面跳动。
9. 空状态只保留下一步动作，不展示大面积空指标、空表格和无意义占位数据。

验收：

- 知识库看起来像可交付的创意资产管理系统，而不是内部数据面板。
- 用户能完成查看、筛选、批量选择、审核、沉淀、送入创意拓展的连续动作。
- 方向库内容能直接被创意拓展页复用，已选方向和来源提示表达清楚。
- 飞书同步、运行记录、调试信息不抢默认首屏。
- 所有折叠区域按钮样式、对齐、文案、展开方向与创意拓展页保持一致。

### 阶段 5：移动端与折叠交互专项验收

原因：创意拓展页暴露出的问题不是单个页面的视觉细节，而是移动端、折叠面板、按钮层级和首屏信息密度需要统一验收。阶段 5 不只检查“能不能显示”，而要检查用户是否能在小屏上稳定完成生产任务。

任务：

1. 所有页面按 390x900 验收首屏，首屏只保留状态、关键路径、当前任务、一个主按钮和必要队列。
2. 所有移动端宽表格卡片化，任务、方向、资产、历史记录都必须以 3 到 5 个关键字段组织成卡片。
3. 所有路径输入在移动端可编辑、可复制、可浏览，长路径必须截断、换行或进入详情，不得撑破布局。
4. 所有页面只保留一个当前主按钮，移动端使用底部 sticky 主操作承载启动、保存、继续、停止等核心动作。
5. 所有折叠按钮统一位置、尺寸、文案和交互反馈，使用“展开 / 收起”，不再出现“展开展示”等不一致表达。
6. 所有折叠面板点击后必须从当前位置向下展开，展开和收起时不闪动、不自动把页面拉到上方、不改变用户当前阅读位置。
7. 日志、历史任务、高级配置、同步记录默认收起或抽屉化，能打开、关闭、返回原位置。
8. 状态检查在移动端使用轻量标签或状态点表达，不堆叠多个大框；“通过”等冗余文字可省略，用圆点、底色和状态文案判断。
9. 危险操作必须二次确认，并且确认弹窗或抽屉按钮不能遮挡当前主任务。

验收：

- 390x900 下无横向滚动。
- 主按钮不被遮挡，底部 sticky 操作不覆盖关键输入和列表内容。
- 文字不溢出按钮、标签、卡片和路径输入。
- 页面切换不挤占首屏，不出现大面积说明文字或空数据。
- 折叠面板展开 / 收起不闪动、不跳屏，按钮位置在点击前后保持稳定。
- 创意拓展、知识库、素材分析、方案迭代的移动端任务链路能连续完成。

## 11. 页面首屏验收标准

每页首屏必须回答 5 个问题：

```text
1. 这个页面是做什么的？
2. 当前系统是否可运行？
3. 用户需要配置什么？
4. 下一步主操作是什么？
5. 任务或结果在哪里看？
```

如果某个模块不能帮助用户回答以上问题，就不应该出现在首屏。

## 12. 视觉验收标准

桌面端验收视口：

```text
1440 x 1000
```

移动端验收视口：

```text
390 x 900
```

每页检查：

- 主内容是否在首屏足够靠上。
- 是否只有一个最高权重主按钮。
- 状态颜色是否可信。
- 是否存在内部开发文案。
- 是否存在横向滚动。
- 长路径和长文件名是否撑破布局。
- 卡片是否过多、过碎、过挤。
- 表格在移动端是否卡片化。
- 日志是否干扰主操作。
- 空状态是否告诉用户下一步。

## 13. 最终交付形态

重构完成后，平台应该像：

```text
一个成熟的 AI 图片生产自动化工作台。
```

不应该像：

```text
一个内部自动化脚本集合的浏览器控制面板。
```

最终用户能清楚看到：

- 从哪里开始生产。
- 当前系统是否准备好。
- 哪些任务正在运行。
- 哪些结果已经生成。
- 哪些资产需要审核。
- 哪些异常需要处理。
- 配置是否已经生效。
- 交付文件会输出到哪里。

本方案的核心判断标准不是“功能是否都摆出来”，而是：

```text
用户是否能稳定、高效、放心地把它当成一个产品来使用。
```
