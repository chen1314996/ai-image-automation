# 创意拓展 Agent 调整优化方案

> 参考 `C:\Users\dd\Downloads\agent-design(1).md` 后，结合当前项目的 Legil 自动化、创意知识库、自动创意 run-once 和前端工作台，整理本项目的 Agent 优化方向。本文默认 Lovart 与我们项目中的 Legil 承担同类角色：网页生图执行平台。

## 1. 核心结论

参考文档最值得迁移的不是某一段 prompt，而是它对 Agent 职责边界的定义：

```text
Agent 只负责理解创意体系、生成结构化新方向和可出图描述。
生图平台由系统流水线执行。
方向入库、知识库更新、反馈沉淀都由程序和人工审核共同完成。
```

放到当前项目里，推荐把系统调整为：

```text
创意知识库/方向种子表/TOP 素材/参考图
  -> 创意拓展 Agent：生成候选方向、维度标签、Legil prompt
  -> Prompt Gate：格式校验、去重、风险过滤、数量截断
  -> Legil 队列：串行生图、保存图片、记录资产
  -> 审核反馈：采纳、修改、删除、精选、失败原因
  -> Creative Memory：提炼规则，下次注入 Agent
```

当前项目已经具备很多基础能力：`agents/creative-expansion-agent/`、`creative-agent-service.js`、`src/services/creative-auto/`、`src/services/creative-knowledge/`、`src/services/legil/`、Prompt 质检和反馈学习都已存在。下一步不是重做系统，而是把 Agent 的“思考输入、输出契约、反馈闭环”收紧，让它从“能生成 prompt 的工具”升级成“围绕创意体系稳定拓展的智能层”。

## 2. Agent 角色重新定义

建议把我们项目里的创意拓展 Agent 定义为：

```text
面向冰封末世/无尽冬日买量素材生产的视觉广告创意拓展 Agent。
它基于已有创意方向树、TOP 素材信号、参考图描述、历史反馈规则，
生成可审核、可入库、可直接送 Legil 生图的新方向和中文长提示词。
```

### 2.1 Agent 应该做什么

- 理解方向树层级：一级/二级/三级/细分标签分别代表什么粒度。
- 沿固定维度发散：氛围、视角、时间、叙事、规模、材质、广告钩子。
- 生成候选新方向：每个方向必须有清晰主体、场景机制、叙事焦点和视觉中心。
- 生成 Legil prompt：中文完整长提示词，适配 Nano Banana 2、2K、每 prompt 4 张。
- 参考同级样本：保持命名粒度、描述长度和画面具体程度一致。
- 避免重复：看到已存在方向、已产出 prompt、已失败方向，主动避开。
- 接受知识库规则：将历史采纳/修改/删除的经验注入下一次生成。

### 2.2 Agent 不应该做什么

- 不直接评价图片好坏，图片质量由人工审核或后续视觉质检模块判断。
- 不直接写飞书或改方向种子表，只输出候选，由系统和设计师确认后入库。
- 不直接操作 Legil 浏览器，Legil 是执行层，由队列和 Playwright 自动化负责。
- 不修改人工已有方向，除非进入“演绎模式”，也只能保留原标签名重新解释。
- 不越级发散，要求拓展 L4 就只产出 L4，要求 prompt 就只产出可执行 prompt。
- 不输出抽象概念型方向，例如“极寒生存感”“末日高级感”“希望氛围感”。

## 3. 当前项目与参考文档的映射

| 参考文档概念 | 我们项目里的对应模块 | 调整建议 |
| --- | --- | --- |
| 创意拓展 Agent | `agents/creative-expansion-agent/`、`creative-agent-service.js` | 保留现有 Agent 包，但把输出从 Markdown 表格进一步结构化为方向候选 + prompt 合约 |
| Lovart 流水线 | `src/services/legil/`、`/api/legil/creative-batch` | 明确 Legil 是生图执行层，Agent 不碰浏览器 |
| 方向树全貌 | `sucai/创意方向种子表.xlsx`、`src/services/creative-knowledge/` | 每次 Agent 运行前注入完整方向树摘要和同级样本 |
| 同级样本 | 方向种子表中同父节点的方向 | 用程序自动提取，作为粒度校准上下文 |
| 拓展维度 | 现有 prompt 规则 + 买量机制 | 增加“广告钩子”“材质/质感”“主体关系”维度 |
| 知识库规则 | `creative-memory.json`、feedback learning | 从反馈中生成通用/方向级/节点级规则，再注入 Agent |
| 反馈采集 | `feedback.json`、asset review | 扩展字段，记录方向是否采纳、prompt 是否跑偏、Legil 是否跳过 |
| 异常处理 | `creative-auto`、Legil 连续失败暂停 | 给 Agent 输出、Prompt Gate、Legil 执行分别设置失败状态 |

## 4. 输入上下文优化

参考文档把上下文分成固定知识、动态知识、焦点知识和积累知识。我们项目建议也按这个结构组织，而不是把所有内容塞进一段 user prompt。

### 4.1 固定知识：项目设定

每次 Agent 运行都注入：

```text
世界观：冰封末世、资源稀缺、废墟生存、旧文明遗迹、幸存者行动
画风：高质量 3D 卡通商业广告海报，不是写实摄影，不是二次元赛璐璐
默认禁用：强赛博、高科技 UI、枪支、军事强相关物品、悬浮设备、机甲、激光界面、真实品牌、大面积英文
默认 prompt 尾句：冰雪氛围，画面直观、主题明确，高质量3D卡通渲染，商业级游戏宣传海报风格，电影镜头感。
```

这些内容已经散落在 `PROJECT_SETTINGS.md` 和 `instructions.md` 中，建议后续把代码运行时的默认值也统一从配置读取，避免文档和程序漂移。

### 4.2 动态知识：方向树全貌

Agent 运行前，程序应从方向种子表或知识库生成一份压缩方向树：

```text
题材
├─ 探索发现
│  ├─ 避难所：避难所形象 / 高处避难所 / 移动避难所 / 趣味化避难所
│  ├─ 物品展示：急救药品 / 生存物资 / 美食 / 燃料
│  └─ 第一人称：驾驶载具 / 探索废墟 / 打开宝箱
├─ 载具
│  ├─ 废弃载具
│  └─ 载具灾难
└─ 围墙
```

目的不是让模型背完整表，而是让它知道：

- 哪些方向已经存在。
- 当前节点在体系里的位置。
- 同一层的命名和描述粒度。
- 哪些方向覆盖密、哪些方向还有空白。

### 4.3 焦点知识：当前节点与同级样本

当用户或自动选题器选择某个方向时，Agent 输入应单独提供：

```json
{
  "selectedNode": "题材 / 探索发现 / 物品展示 / 急救药品",
  "targetLevel": "L4",
  "siblings": [
    {
      "label": "生存物资",
      "description": "重点展示末世生存所需的食物、燃料、工具和保暖用品。",
      "mood": "紧张危机",
      "perspective": "俯瞰"
    }
  ],
  "existingDirections": [
    "冰封医院药房抽屉",
    "雪地急救包争夺",
    "避难所临时诊疗角"
  ]
}
```

同级样本是最关键的“粒度校准器”。没有它，Agent 很容易把 L4 写成 L3，或者把方向写成 prompt。

### 4.4 积累知识：反馈规则

建议 `creative-memory.json` 中规则分三层注入：

```text
通用规则：
- 避免“未来科技、量子、虚拟空间”等抽象科幻词。
- 每条 prompt 必须包含具体镜头、主体关系和画面动作。

方向级规则：
- 探索发现类方向更适合远景、俯瞰、发现瞬间、人物比例参照。
- 物品展示类方向要让物资成为强视觉中心，不要只做背景氛围。

节点级规则：
- 急救药品方向要突出稀缺、救命价值、破损包装、冰霜保存状态。
- 避难所方向不要只做温暖路线，需补充荒凉、紧张、撤离类变体。
```

这可以直接承接当前 `src/services/creative-knowledge/feedback-learning.js` 的能力，但需要让 Agent 调用层明确读取并注入当前节点相关规则。

## 5. 拓展维度调整

参考文档已有五个维度：氛围、视角、时间、叙事、规模。我们项目建议扩成八个维度。

| 维度 | 用途 | 示例值 |
| --- | --- | --- |
| 氛围 | 控制情绪基调 | 温暖希望 / 荒凉孤独 / 紧张危机 / 神秘未知 / 幽默轻松 / 史诗壮阔 |
| 视角 | 控制镜头语言 | 俯瞰 / 仰视 / 平视 / 第一人称 / 远景 / 微距 / 低机位 |
| 时间天气 | 制造差异和环境压力 | 暴风雪 / 雪后初晴 / 夜晚 / 黎明 / 正午 / 白雾寒潮 |
| 叙事动作 | 让画面有正在发生的事 | 初次发现 / 争夺资源 / 正在搭建 / 被迫撤离 / 护送救援 / 修复重启 |
| 规模 | 控制主体体量 | 单体小件 / 小队行动 / 中等建筑 / 巨型地标 / 微观细节 |
| 材质质感 | 强化 Legil 可视化细节 | 锈蚀金属 / 裂冰 / 厚雪 / 旧布料 / 破损包装 / 火光雾气 |
| 主体关系 | 提升广告图可读性 | 人与物资 / 小队与灾害 / 敌我争夺 / 角色与建筑 / 角色与载具 |
| 广告钩子 | 连接买量表现 | 稀缺奖励 / 危险冲突 / 反差惊喜 / 救命价值 / 选择压力 / 升级收益 |

程序层可以为每个方向计算覆盖情况：

```json
{
  "mood": { "温暖希望": true, "紧张危机": true, "荒凉孤独": false },
  "perspective": { "俯瞰": true, "第一人称": false, "微距": false },
  "narrative": { "初次发现": true, "争夺资源": false, "被迫撤离": false },
  "hook": { "稀缺奖励": true, "危险冲突": false, "救命价值": true }
}
```

Agent 生成时优先填补 `false` 的维度组合，避免“换个地点继续写同一种图”。

## 6. 输出契约调整

当前 Agent 默认输出 `新方向拓展表`，这对人工阅读友好，但程序长期运行更需要结构化结果。建议支持“双格式输出”：

1. Markdown 表格：给前端和人工审核看。
2. JSON：给程序解析、入库、Prompt Gate 和 Legil 队列用。

### 6.1 候选方向 JSON

建议每个方向输出：

```json
{
  "type": "new",
  "sourcePath": "题材/探索发现/物品展示/急救药品",
  "targetLevel": "L4",
  "label": "雪夜急救箱护送",
  "description": "画面重点表现幸存者小队在暴风雪夜护送一只带红十字标识的急救箱穿过废弃街区。可包含破损担架、手电光、冰封救护车、远处避难所灯光，突出药品救命价值和路途危险。",
  "dimensions": {
    "mood": "紧张危机",
    "perspective": "远景",
    "time": "夜晚",
    "narrative": "护送救援",
    "scale": "小队行动",
    "material": "裂冰、旧布料、霜雪金属",
    "hook": "救命价值"
  },
  "duplicateRisk": "低",
  "reason": "现有急救药品方向多集中于发现和展示，缺少护送救援叙事。",

    {
      "title": "提示词1",
      "prompt": "主题：雪夜急救箱护送..."
    }

```

### 6.2 Markdown 表格仍保留

前端和 Excel 导出继续使用固定列：

```text

新方向名称
方向描述
来源于哪条详细迭代策略
提示词1
提示词2
提示词3
提示词4
提示词5
```

但建议新增隐藏/附加字段：

```text
目标层级
氛围
视角
时间天气
叙事动作
规模
材质质感
主体关系
广告钩子
去重依据

```

这样既保留人工工作流，也能支撑自动选题和知识库分析。

## 7. Prompt Gate 优化

Agent 输出后，不应直接送 Legil。中间加一个 Prompt Gate，承担程序验收。

### 7.1 必检项

- JSON 或表格是否可解析。
- 是否有 `新方向拓展表`。
- 每行是否有方向名称、方向描述和 1-5 条 prompt。
- prompt 是否为中文完整长提示词。
- prompt 是否包含主题、画风、情绪氛围、画面内容、整体基调。
- 是否出现禁用词：真实品牌、强赛博、机甲、激光 UI、大面积英文、二次元赛璐璐。
- 是否过短、过抽象、只有关键词堆砌。
- 是否与历史 prompt 高度相似。
- 单条 prompt 是否包含多个互斥画面方案。

### 7.2 风险分级

建议 Prompt Gate 输出：

```json
{
  "status": "pass",
  "acceptedPromptCount": 23,
  "rejectedPromptCount": 2,
  "issues": [
    {
      "level": "warning",
      "direction": "冰封药房抽屉",
      "promptTitle": "提示词3",
      "message": "与历史 prompt 存在较高相似度，建议换叙事动作。"
    }
  ]
}
```

规则建议：

- `error`：不得进入 Legil。
- `warning`：可人工确认后进入，自动模式下默认丢弃或截断。
- `info`：只记录，不阻断。

## 8. Legil 执行层调整

参考文档强调 Agent 不直接操作 Lovart。我们项目也应明确：

```text
Agent 输出文字。
Prompt Gate 验收文字。
Legil 队列执行生图。
资产索引记录结果。
```

### 8.1 Legil 任务对象

建议从 Agent 候选方向构造统一任务：

```json
{
  "runId": "creative_auto_20260602_001",
  "directionId": "direction_001",
  "sourcePath": "题材/探索发现/物品展示/急救药品",
  "newDirectionName": "雪夜急救箱护送",
  "promptTitle": "提示词1",
  "prompt": "主题：...",
  "settings": {
    "model": "nano-banana-2",
    "aspectRatio": "1:1",
    "resolution": "2K",
    "outputQuantity": 4
  },
  "referenceImages": [],
  "outputFolder": "D:\\工作\\自动化工作流1\\创意拓展\\输出"
}
```

### 8.2 队列和锁

Legil 是共享浏览器资源，必须串行：

```text
同一时间只允许一个 Legil 任务运行。
Agent 可以提前准备下一批 prompt，但不能并发点击 Legil。
```

当前项目已有 Legil 运行状态和 creative-auto run-once，短期可继续复用。中期建议抽象成统一浏览器任务队列：

```text
enqueue(task)
pause()
resume()
cancel(taskId)
status()
currentTask
pendingTasks
history
```

这样后续即梦、尺寸后处理、参考图补图也能共享任务调度。

## 9. 反馈与自我进化机制

参考文档里的“反馈 -> 规则转化 -> 下次注入”非常适合我们当前的创意知识库。

### 9.1 反馈采集字段

每个方向候选需要记录：

```json
{
  "expandId": "exp_20260602_001",
  "node": "题材/探索发现/物品展示/急救药品",
  "label": "雪夜急救箱护送",
  "type": "new",
  "action": "accepted",
  "original": "Agent 原始方向描述",
  "modified": "人工修改后的描述",
  "deleteReason": "",
  "previewGenerated": true,
  "legilSkipped": false,
  "legilError": "",
  "selectedAsReference": false,
  "rating": null,
  "tags": ["主体明确", "救命价值", "夜景"]
}
```

每张图需要记录：

```text
runId
directionId
newDirectionName
promptHash
filePath
generationSettings
success/failure
人工评分
是否精选
拒绝原因
是否加入参考图池
```

### 9.2 规则提炼

定期或手动触发学习：

```text
读取最近 N 条 feedback 和 assets
  -> 统计被采纳方向的共同特征
  -> 统计被删除方向的共同词和机制
  -> 统计人工修改中反复新增的维度
  -> 输出候选规则
  -> 人工确认后进入 creative-memory.json
```

规则类型建议：

| 类型 | 示例 |
| --- | --- |
| 正向规则 | 物品展示方向中，包含手部动作和包装破损细节的 prompt 采纳率更高 |
| 负向规则 | 避免“量子、虚拟、能量场”等抽象科幻词 |
| 节点规则 | 急救药品方向要突出救命价值，不要只做静态摆拍 |
| 维度建议 | 多次人工修改加入“材质质感”，建议提高材质维度权重 |

### 9.3 规则注入

下次 Agent 运行时，只注入相关规则，而不是注入完整历史：

```text
通用规则：最多 10 条
当前 L2 规则：最多 8 条
当前节点规则：最多 8 条
近期失败避坑：最多 5 条
```

避免上下文过长，也避免模型被无关经验带偏。

## 10. 前端工作台调整

建议把当前创意 Agent 和 creative-auto 前端整合成更清晰的三段式工作台。

### 10.1 方向拓展面板

功能：

- 选择方向树节点。
- 查看同级已有方向。
- 查看维度覆盖情况。
- 设置拓展层级和数量。
- 选择模式：只新增 / 新增 + 演绎 / 只生成 prompt。
- 运行 Agent。
- 展示候选方向卡片。

候选方向卡片应包含：

```text
方向名
方向描述
维度标签
去重依据
5 条 prompt 折叠预览
操作：采纳 / 修改 / 删除 / 发送 Legil / 加入知识库
```

### 10.2 Prompt Gate 面板

功能：

- 展示解析数量。
- 展示 error/warning/info。
- 批量删除不合格 prompt。
- 一键修复或重新生成问题 prompt。
- 显示预计出图数量和今日额度消耗。

### 10.3 Legil 运行面板

功能：

- 当前任务。
- 队列长度。
- 已生成/预计生成。
- 连续失败次数。
- 暂停/继续/停止。
- 最近输出缩略图。
- 单张图反馈：精选、删除、重复、跑偏、加入参考图。

## 11. 自动模式分级

不要一开始就让系统完全无人值守。建议分三级：

| 模式 | 行为 | 适用阶段 |
| --- | --- | --- |
| 观察模式 | Agent 只生成方向和 prompt，不发 Legil | 调整 Agent 规则和输出质量 |
| 半自动模式 | Agent 自动生成，人工确认后发 Legil | 验证 Prompt Gate 和 Legil 稳定性 |
| 全自动模式 | 自动选题、自动生成、自动发 Legil、自动记录资产 | 单轮稳定后再放开 |

自动模式下建议默认：

```text
每轮 1 个原始方向
5 个新方向
每方向 5 条 prompt
Prompt Gate 通过后最多发送 25 条 prompt
每 prompt 生成 4 张
连续失败 5 次暂停
每日总量不超过 1000 张
```

如果当前处于调试期，可以把每 prompt 出图数量临时降到 1，先观察方向质量。

## 12. 分阶段落地计划

### 阶段 1：收紧 Agent 输入输出

目标：让 Agent 稳定按“方向候选 + prompt 合约”输出。

要做：

- 更新 `instructions.md`：加入参考文档中的角色边界、层级规则、维度覆盖、质量自检。
- 更新 `PROJECT_SETTINGS.md`：补充维度体系、Legil 与 Lovart 的映射说明。
- 更新 `agent.yaml`：增加 JSON 输出契约说明。
- 在 `creative-agent-service.js` 的请求构造中注入方向树摘要、同级样本、相关 memory 规则。
- 在解析层支持 Markdown 表格 + JSON 双格式。

验收：

```text
同一个方向连续跑 3 次，输出结构稳定，可解析率 100%，无越级拓展。
```

### 阶段 2：Prompt Gate 强化

目标：Agent 输出不能直接污染 Legil 队列。

要做：

- 扩展 `creative-agent-quality.js` 或新增 `src/services/creative-auto/prompt-gate.js` 规则。
- 增加禁用词、相似度、空泛描述、多方案混写检测。
- 输出 pass/warning/error 结构。
- 自动模式只发送 pass prompt。

验收：

```text
低质量 prompt 能被拦截；通过的 prompt 能被 Legil 直接执行。
```

### 阶段 3：方向树与同级样本注入

目标：Agent 能看到自己在创意体系里的位置。

要做：

- 从方向种子表或 creative-knowledge directions 生成压缩方向树。
- 根据 selectedNode 自动提取 siblings。
- 计算维度覆盖情况。
- 将已有方向名、历史 prompt hash、被拒绝方向加入排除上下文。

验收：

```text
新方向与同级已有方向至少在 2 个维度上有明显差异，重复率显著下降。
```

### 阶段 4：反馈闭环

目标：人工审核能变成下次 Agent 的规则。

要做：

- 补齐方向候选反馈字段。
- 将图片反馈、方向反馈和 prompt 反馈关联。
- 扩展 feedback learning：生成通用/方向级/节点级候选规则。
- 增加人工确认规则后写入 creative-memory 的流程。

验收：

```text
同一节点的人工修改偏好能在下一轮 Agent 输出中体现出来。
```

### 阶段 5：Legil 队列与资产回流

目标：生图执行层可追踪、可暂停、可恢复。

要做：

- 统一 Legil 任务对象。
- 确认 creative-auto run-once 发送的是 Prompt Gate 通过后的 prompt。
- 每张图写入资产索引，绑定方向、prompt、runId、生成参数。
- 前端展示最近产出和反馈入口。

验收：

```text
从一个方向出发，完成 Agent -> Prompt Gate -> Legil -> asset record -> feedback 的闭环。
```

## 13. 推荐优先级

最高优先级：

1. Agent 输出契约结构化。
2. 方向树/同级样本/维度覆盖注入。
3. Prompt Gate 阻断低质量 prompt。
4. 反馈规则注入 creative-memory。

中优先级：

1. 前端方向候选审核卡片。
2. Legil 队列统一抽象。
3. 资产索引与缩略图反馈。
4. 自动选题评分。

后续增强：

1. 视觉 DNA。
2. 图片感知哈希去重。
3. OCR 检查画面文字。
4. 多模型对照生成。
5. 24 小时全自动循环。

## 14. 一版最终目标

优化完成后，一次“创意拓展 Agent”运行应变成：

```text
用户或自动选题器选择一个方向节点
  -> 系统读取方向树、同级样本、历史反馈和维度覆盖
  -> Agent 生成候选新方向和 Legil prompt
  -> Prompt Gate 校验、去重、截断
  -> 前端展示候选方向，或自动模式直接发送 pass prompt
  -> Legil 串行生成图片
  -> 图片和 prompt 写入资产索引
  -> 人工反馈沉淀为 memory 规则
  -> 下一轮 Agent 变得更贴近项目偏好
```

这套调整的关键价值是：

```text
方向不乱扩，prompt 不乱跑，Legil 不乱点，结果能回流，系统能越跑越懂项目。
```
