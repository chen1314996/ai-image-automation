# Legil 运行一次自动创意 Prompt 合约

## 使用场景

当任务涉及以下任一语义时，必须使用本技能：

- 运行一次自动创意
- creative-auto / run-once
- 自动拓展 prompt 后发送 Legil 生图
- 根据创意知识库自动选方向
- 输出需要被程序解析成 `prompts` 数组

本技能的重点是让 Agent 输出能被程序稳定解析，并且能直接进入 Legil 生成图片。

## 当前固定参数

| 参数 | 当前值 |
| --- | --- |
| 模型 | Nano Banana 2 |
| 内部值 | `nano-banana-2` |
| 比例 | `1:1` |
| 分辨率 | `2K` |
| 每条 prompt 出图 | `4` 张 |
| 浏览器模式 | `headed` |
| 每日图片上限 | `1000` 张 |
| 连续失败暂停 | `5` 次 |

这些参数不是让你在 prompt 里机械复述，而是影响创作方式：

- 构图要默认适配方图，视觉中心稳定。
- 每条 prompt 会生成 4 张图，所以每条 prompt 应是一个清晰可执行的画面方案，不要把 4 个互斥画面塞进同一条 prompt。
- 2K 输出允许写清楚材质、空间和光线，但不要依赖过小文字或过碎细节。

## Run-once 输出格式

后台自动创意优先只需要 `新方向拓展表`。

表头必须严格使用：

```text
参考方向
新方向名称
方向描述
来源于哪条详细迭代策略
提示词1
提示词2
提示词3
提示词4
提示词5
```

要求：

- 不要把表格放进代码块。
- 不要改列表头名称。
- 每一行是 1 个新方向。
- 每行 prompt 数量必须按调用层数量执行；run-once 默认每行 4 条 prompt。
- 默认生成 3 行新方向，也就是 12 条 prompt。
- 如果调用层要求更少，按调用层数量执行。

## Prompt 结构

每条 prompt 用中文完整描述，并优先包含：

```text
主题：
画风：
情绪氛围：
画面内容：
整体基调：
```

每条 prompt 还需要自然覆盖：

- 主体是谁，主体关系是什么。
- 正在发生什么场景机制。
- 画面中心和广告点击点是什么。
- 方图构图如何稳定主体。
- 镜头景别、视角、前中后景如何组织。
- 冷暖光、雪雾、冰霜、材质细节如何服务主视觉。
- 为什么这张图在投放缩略图里能被快速看懂。

默认尾句：

```text
冰雪氛围，画面直观、主题明确，高质量3D卡通渲染，商业级游戏宣传海报风格，电影镜头感。
```

## 质量要求

合格 prompt：

- 读完能马上想象出一张具体广告图。
- 主体、动作、场景、冲突或奖励点明确。
- 适合生成方形广告图，不是宽屏电影分镜。
- 画面信息前置，缩略图下也能读懂。
- 同方向下多条 prompt 之间有明显不同的动作机制、镜头和空间。
- 物品展示类方向也要包含发现、争夺、护送、抢救、交换、撤离、守护或倒计时选择等动态关系，不要只有物品静置摆拍。

不合格 prompt：

- 只有氛围词和风格词，没有主体事件。
- 只是同一句话换同义词。
- 画面过度复杂，导致主体和广告点不清。
- 依赖大量小字、密集 UI、细小符号才能成立。
- 默认加入赛博、激光、机甲、悬浮设备、未来屏幕。

## 与 TOP 素材的关系

TOP 素材用于判断什么方向更可能有效，但不要复刻已有素材。

使用方式：

- 高 CTR 说明点击抓手可能强，可以提取其主体关系、冲突、奖励反馈或文字机制。
- 高花费说明有过投放验证，可以参考其大方向。
- 高 D7 ROI 说明后端质量可能更好，可以参考其题材和用户预期。
- 低 CPI 说明成本表现有参考价值，但仍要检查画面是否容易同质化。

输出时不要堆砌指标，也不要把素材名直接写进 prompt。要把指标背后的创意机制转译成新画面。

## 自检清单

输出前检查：

1. 表名或表头是否能被程序识别为 `新方向拓展表`。
2. 是否每行 prompt 数量符合调用层要求，run-once 默认 4 条。
3. 是否每条 prompt 都是完整中文画面描述。
4. 是否默认适配 Nano Banana 2、1:1、2K、每 prompt 4 张。
5. 是否避免同方向内多条 prompt 近似重复。
6. 是否保留冰封末世、现实废土、资源稀缺、3D 商业海报质感。
7. 是否没有主动加入不该有的高科技/赛博元素。
